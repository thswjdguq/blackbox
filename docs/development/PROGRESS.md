# 개발 진행 기록

## 2026-09-15 / 1단계 구현, 통합 검증 대기

### 적용한 흐름
프로젝트 홈 → 제출물 등록(이름·기한·담당자·제출 경로) → 필수/선택 요구사항 작성 → 요구사항에서 업무 생성 또는 기존 업무 연결 → 업무 보드에서 담당자·기한·완료 기준·상태 관리.

- 새 화면: `/projects/{projectId}/deliverables`. 사이드 메뉴와 프로젝트 홈에서 진입한다.
- 제출물·요구사항 생성/수정/삭제와 저장 오류 표시를 추가했다.
- 업무에 제출물·요구사항·완료 기준을 추가했다. 제출물 변경 시 이전 요구사항은 해제한다.
- 기존 업무는 삭제하지 않고 미연결로 표시한다. 보드에서 제출물별/미연결 필터를 제공한다.
- 제출물의 업무 링크는 보드의 해당 업무 수정 창으로 이어진다.
- 업무 완료 수와 최종 검토·제출 완료를 구분한다. 검토·제출 상태는 이번 단계에서 추가하지 않았다.
- 팀장/팀원만 쓰기 가능하며 관찰자는 새 제출물 화면을 읽기 전용으로 사용한다.
- 타 프로젝트 연결, 다른 제출물의 요구사항 연결, 참여하지 않은 담당자 지정을 서버에서 거절한다.
- 연결된 업무가 있는 제출물/요구사항 삭제는 409 응답으로 거절한다.
- `V19__deliverables_requirements_tasks.sql`을 추가했다. 기존 마이그레이션과 기존 업무 데이터는 유지한다.

### API
기본 경로는 `/api/projects/{projectId}/deliverables`다.

| 요청 | 동작 |
| --- | --- |
| GET / | 제출물과 요구사항 목록 |
| POST / | 제출물 생성 |
| PUT /{id} | 제출물 수정 |
| DELETE /{id} | 미연결 제출물 삭제 |
| POST /{id}/requirements | 요구사항 생성 |
| PUT /{id}/requirements/{requirementId} | 요구사항 수정 |
| DELETE /{id}/requirements/{requirementId} | 미연결 요구사항 삭제 |

기존 업무 생성/수정 API에 `deliverableId`, `requirementId`, `completionCriteria`를 추가했다. 수정에서 값 생략은 기존 관계 유지, `clearDeliverable: true`는 두 관계 해제, `clearRequirement: true`는 요구사항만 해제다. 연결 ID와 해당 해제 플래그를 동시에 보내면 400으로 거절한다.

### 검증
- 프론트엔드 `npm run type-check`: 통과.
- 프론트엔드 `npm run build`: 통과, 새 제출물 경로 생성 확인. 이후 보드 오류 복구 보완에 대해 타입 검사를 다시 수행했다.
- 백엔드 `compileJava`: 통과. Java 23으로 실행하고 기존 Java 17 대상 설정을 유지했다.
- 백엔드 선택 테스트: `DeliverableServiceTest`, `TaskDeliverableTest`.
- 검증 대상: 관찰자/비회원 권한, 담당자 자격, 프로젝트/요구사항 경계, 연결 해제·이동, 삭제 차단, 완료 기준 및 기존 관계 보존.
- 단위 테스트는 저장소를 모의 구현한다. 실제 DB 저장과 API 인증 전체를 검증한 것으로 간주하지 않는다.
- 로컬 PostgreSQL·백엔드 실행 서버가 없고 Docker 엔진도 실행되지 않아 V19 실제 적용, 서버 기동, 브라우저 저장·재조회는 미검증이다. 전체 Spring 컨텍스트 테스트도 실행하지 않았다.
- 기존 Next 빌드는 복수 lockfile 경고와 Browserslist 갱신 안내를 출력한다. 빌드 실패는 아니다.

### 통합 확인 순서
1. 기존 로컬 PostgreSQL 설정으로 DB를 실행하고 백엔드를 시작한다. Flyway V19 적용 성공을 확인한다.
2. 프론트를 실행하고 팀원 계정으로 프로젝트의 ‘제출물·요구사항’에 들어간다.
3. ‘조사 보고서’와 제출 기한을 등록하고 ‘출처 3개 이상 포함’ 필수 요구사항을 추가한다.
4. 해당 요구사항에서 업무를 만들고 담당자·마감·완료 기준을 입력한다.
5. 새로고침 후 값이 유지되는지 확인하고 업무 링크로 보드에 진입한다.
6. 다른 제출물로 업무를 옮기면 기존 요구사항이 해제되는지, 연결 해제 후 미연결 필터에 나타나는지 확인한다.
7. 연결된 제출물/요구사항 삭제가 거절되고 입력 내용과 오류 메시지가 유지되는지 확인한다.
8. 관찰자는 목록 조회만 가능하고 쓰기 API는 403인지 확인한다. 기존 업무 목록과 회의에서 업무 생성도 확인한다.
