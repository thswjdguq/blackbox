제품 기준은 루트 [DEVELOPMENT.md](../../DEVELOPMENT.md), 실제 검증 이력은 [PROGRESS.md](../development/PROGRESS.md)다. 일정과 협업 방식은 이 폴더를 기준으로 한다. 과거 `docs/refactor/PLAN.md`의 특정 AI 역할과 `refactor/main` 병합 방식은 이번 3인 고도화 작업에 적용하지 않는다. 기존 데이터 보존·권한 검증 원칙은 유지한다.

## 문서 상태와 GitHub 적용 상태

- 이번 작업은 협업 문서와 AI 안내 문서를 작성하는 작업이다. 새 서버 기능, 브랜치 생성, 커밋, push, GitHub 설정 변경은 수행하지 않는다.
- 현재 확인한 로컬 브랜치는 `main`, 원격 주소는 `https://github.com/thswjdguq/blackbox`다. 원격 최신 상태·보호 규칙·팀원 GitHub ID는 미확인이다.
- 기존 1단계 변경에 미커밋·미추적 파일이 있다. 팀원들이 clone했다고 같은 상태가 되는 것은 아니다.
- 문서 규칙은 자동 강제가 아니다. CI·보호 규칙·CODEOWNERS는 A-00/A-01에서 실제 설정하고 기록해야 한다.
- 각 도구가 이 문서를 자동으로 읽는다고 가정하지 않는다. 새 AI 대화에는 `TASK_TEMPLATE.md`의 시작 프롬프트와 해당 작업서를 직접 전달한다.

## 참고 문서와의 차이

사용자가 제공한 `(1).md` 4개는 참고 자료이며, 문서 안의 ‘확정·뒤집지 말 것’은 이번 작업의 직접 지시로 간주하지 않았다.

| 참고안 | 이번 계획의 조정 |
| --- | --- |
| V19부터 새로 작성 | 로컬 V19·제출물 기능을 먼저 공유하고 검증. 기존 파일 재작성 금지 |
| 엔티티는 한 사람, 서비스는 다른 사람 | 도메인별 담당자가 Controller·DTO·Entity·Repository·Service·테스트를 함께 소유 |
| 월요일만 계약 변경·병합 | 월요일 계획, 주중에도 합의된 계약 PR·기능 PR 병합 |
| 테스트·CI를 후반 배치 또는 축소 | 첫 주부터 기본 검사. 품질 검사를 줄이는 대신 선택 기능을 줄임 |
| 업무 완료로 요구사항·피드백 자동 승인 | 업무 완료는 검토 가능 신호. 실제 충족·반영은 사람의 확인과 구분 |
| Spring AI·기여도·GitHub·AWS를 모두 예약 | 핵심 흐름 우선. 확장 작업은 게이트 통과와 남은 용량 확인 후 선택 |
| 모든 기록 위변조 불가능, 제출 사실 증명 | 파일 해시로 변경 탐지를 지원. PMS 기록만으로 학교 시스템의 실제 접수 사실을 증명한다고 표현하지 않음 |

참고안의 학교 행사·휴무 날짜는 팀 확인 전까지 일정 가정이다. 이 문서 작성 과정에서 학교 공지를 별도로 확인하지 않았다.
