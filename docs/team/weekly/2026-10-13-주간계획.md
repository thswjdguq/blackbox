### 새로 확인된 문제

- **마이그레이션 번호**: main의 V25는 `agent_proposals`이고, 시연 브랜치는 V25~V28이 업무·회의 기능, V29가 `agent_proposals`다. main 전체를 시연 브랜치에 합치면 파일 충돌은 없지만 V25가 둘이 되어 서버가 뜨지 않는다. 통합안은 main의 V25를 두고 시연 쪽 넷을 V26~V29로 옮기는 것이다(시연 쪽 V29는 main V25와 같은 내용이라 뺀다).
- **AI 공급자가 둘이다**: main은 Spring AI의 OpenAI 공급자(#127), 시연 브랜치는 `OpenAiService`를 쓰는 별도 구현이다. 통합할 때 하나로 정한다.
- **AWS**: 학교 계정의 IAM 사용자로 EC2를 만들면 `ec2:RunInstances` 권한 오류가 난다. 기본값으로만 만들어도 같아 관리자 확인이 필요하다. Elastic IP는 인스턴스를 만든 뒤 관리자가 붙여 주고, t3.small로 시작한다.
- **AI 사용량**: 학교가 Bedrock 대신 OpenAI 호환 LLM API를 줬다. 키마다 사용 한도가 있어 넘으면 엑스포 도중 AI가 막힌다. 요청 내용은 게이트웨이 로그에 남고 개인정보를 넣지 말라는 조건이 있다.
- **에이전트 실행 한도**: 시연 브랜치는 프로젝트 하나가 한 시간에 20번, 서버 전체가 동시에 2개까지 실행한다. 관람객 여럿이 같은 프로젝트에서 AI를 쓰면 금방 막힌다.
- **관람객의 첫 화면**: QR로 들어와 새로 가입한 관람객에게는 프로젝트가 없다. 무엇을 보여 줄지 정해야 한다.

## 2. 이번 주에 정할 것

정하는 순서대로 적었다.

1. **시연 브랜치를 main에 맞추는 방식**: 마이그레이션 번호와 AI 공급자, 겹치는 AI 도우미 화면 중 남길 것. 이것이 정해져야 시연 브랜치가 main을 그대로 받을 수 있다. 정해지기 전까지는 커밋 단위로 옮긴다
2. **관람객 흐름**: 관람객이 직접 가입하는지, 보드에 적은 시연 계정으로 들어오는지. 직접 가입이면 관람객의 이메일이 서버에 남고, 시연 계정이면 여러 사람이 같은 프로젝트를 만져 자료가 섞인다. 관찰자 계정(읽기와 AI 질문만)으로 들어오게 하는 방안도 있다
3. **AI 사용량**: 에이전트 실행 한도를 얼마로 올릴지, 게이트웨이 사용 한도를 누가 어떻게 지켜볼지, 한도에 닿으면 AI를 끄고 나머지로 시연할지
4. **회원가입의 역할 선택지**: 서버로 가지 않는 선택지라 없앨지 저장할지
5. **시연 서버에 올릴 커밋**: 위 수정이 시연 브랜치에 들어온 뒤의 커밋으로 정하고, 그 뒤로 바꾸면 이미지를 다시 만들어 보낸다
