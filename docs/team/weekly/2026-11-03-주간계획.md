### 새로 확인된 것

- **캘린더 API에 프로젝트 멤버 확인이 없다(main, 코드로 확인)**:
  - 로그인만 하면 다른 프로젝트의 ID로 연동 상태를 조회해 팀원 이름과 이메일을 볼 수 있다. 가용 시간 조회와 시간 추천도 다른 프로젝트 팀원의 일정을 읽는다
  - 시간 추천과 일정 등록은 참석자로 아무 사용자 ID나 받는다. 다른 사용자의 일정을 읽거나 그 사람의 구글 캘린더에 일정을 넣을 수 있다
  - 연동 콜백이 `state`에 사용자 ID를 그대로 쓴다. 다른 사용자 계정에 내 구글 캘린더를 연결할 수 있다
  - 공개 서버에서는 개인정보가 새는 경로다
- **회의 오류 문구가 깨져 있다(main)**: `MeetingService`의 회의 일시 변경 오류 두 곳이 소스에 `?`로 저장되어 화면에도 그대로 나온다
- **이메일 발송 수단**: 학교가 안내한 AWS 사용 가능 서비스에 메일 발송 서비스가 없다. 외부 SMTP 같은 다른 수단을 정해야 한다
- **라이브러리 지원 종료와 취약점**:
  - Spring Boot 3.5는 6월 말에 공개 지원(OSS)이 끝났고 3.5.16이 마지막 버전이다. Node 20(Dockerfile, CI)도 4월 말에 지원이 끝났다
  - 화면의 Next.js 16.2.1은 `npm audit`에서 심각(critical)으로 나온다. 이미지 최적화 API의 원격 코드 실행 등이고, 16.4.1부터 고쳐졌다. 운영에 쓰는 의존성의 취약점 9건은 모두 메이저 버전을 바꾸지 않고 고칠 수 있다
  - `eslint-config-next`가 14라 Next 16과 맞지 않는다
- **Java 25 시험 결과(임시 작업 폴더, 커밋 안 함)**:
  - Spring Boot 3.5.16은 그대로 두고 Java 25, Gradle 9.8.2, Lombok 1.18.48로 바꿔 전체 빌드와 테스트를 돌렸다
  - 테스트 373개가 통과했고 실패는 0이다(실제 AI를 부르는 2개는 건너뜀). 코드는 고치지 않았고 `build.gradle` 두 줄과 Gradle wrapper만 바꿨다
  - Docker 이미지 빌드는 아직 하지 않았다. 필요한 `gradle:9.8.2-jdk25-alpine`, `eclipse-temurin:25-jre-alpine` 이미지는 있다
  - 교수님의 스프링 부트 수업도 Java 25를 쓴다
- **Spring Boot 4 시험 결과(임시 작업 폴더, 커밋 안 함)**: Boot 4.1.2, Spring AI 2.0.2, Java 21로 바꿔 컴파일만 했다
  - 서버 코드는 세 곳만 고치면 컴파일된다: 보안 자동 설정의 패키지, `fromHttpUrl` → `fromUriString`, Flyway 스타터 추가
  - 테스트 코드는 21개 파일에서 오류가 난다. 오류 목록이 javac 상한(100건)에서 잘려 더 있을 수 있다. 대부분 `@MockBean` → `@MockitoBean`과 테스트 자동 설정 패키지 이동이라 기계적으로 고칠 수 있다
