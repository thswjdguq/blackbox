# B-22 미해결 피드백 조회·최종 확정 경계 검증

- 담당: 손정협(B). 검토: 송승준(A), 손정효(C).
- 일정: 4주차 2026-10-12~18. 상태: READY_FOR_CONTRACT_REVIEW (구현 완료 아님).
- 기준: main `25ccca5`. 선행: K-10/K-11/K-12/K-20 AGREED, A-11/V21·V22, B-20/B-21, A-20 확정 API.
- 허용: B 소유 피드백 조회·테스트, B 작업서·인수인계. 금지: A 회차·확정 서비스와 migration, C frontend, 실제 데이터 삭제.

## 범위

1. countUnresolvedComments는 제출물 전체 회차에서 해결 정보가 없는 코멘트만 센다. OPEN/REFLECTION_PENDING은 포함, RESOLVED는 제외한다. 업무 DONE만으로 감소하지 않는다.
2. A 승인·확정 검사가 실제 B 조회를 호출하는지 확인한다. B 기능 적용 후 기본 0 구현이 남아 있지 않아야 한다.
3. CONFIRMED/SUBMITTED 뒤 작성·해결·다시 열기·새 업무 연결은 409다. 쓰기 거절 후 코멘트·업무·활동 기록이 추가되지 않아야 한다.
4. 승인/확정과 코멘트 작성·다시 열기가 동시에 요청되면 동일 제출물 잠금으로 직렬화되어 미해결이 있는 확정을 허용하지 않아야 한다.

## 실제 DB·HTTP 검사

검사 전용 PostgreSQL과 네 계정(팀장·팀원·관찰자·비회원)을 사용한다. 운영 데이터나 볼륨을 초기화하지 않는다.

| 준비/요청 | 기대 |
| --- | --- |
| 회차·피드백 없는 제출물 | 미해결 0 |
| 과거 OPEN 1 + 최신 업무 DONE 미해결 1 + 해결 1 | 미해결 2 |
| 연결 업무 DONE → TODO | 표시 상태 변경, 미해결 수 유지 |
| 미해결 해결 → 다시 열기 | 수 -1 → +1, 해결 이력 보존 |
| 타 프로젝트·타 제출물 ID | 경계 거절, 제목 등 정보 노출 없음 |
| 관찰자 조회/쓰기, 비회원, 미인증 | 조회 200 / 쓰기 403, 비회원 403, 미인증 401 |
| 미해결 > 0 승인·확정 | 409 |
| 필수 충족·최신 파일 승인·미해결 0 | K-20의 확정 조건 충족 |
| 승인 vs 작성, 확정 vs 다시 열기 | 잠금 획득 순서에 맞는 일관된 결과, 미해결 확정 없음 |
| 확정/제출 후 직접 쓰기 API | 409, DB·활동 기록 변동 없음 |
| v1 승인 → 다른 내용 v2 → v1과 동일 내용 v3 (새 회차 없음) | K-10 v0.2 초안 기준 currentBasis true → false → true |
| 승인 뒤 새 회차를 연 뒤 같은 파일 내용을 다시 업로드 | 과거 승인의 currentBasis false 유지 |
| 과거 비승인 회차 피드백 다시 열기 → 해결, 파일 내용 동일 | K-10 v0.2 초안 기준 count 증가 → 감소, 최신 승인 근거 유지 |

## 합의가 필요한 경계

- K-10 v0.2는 내용 동일 상태의 과거 피드백 재개·해결 후 새 승인 없이 확정하도록 제안했고 B가 동의했다. C 확인과 공통 CONTRACTS의 예외 설명 반영 후 K-20에서 같은 규칙으로 검사한다.
- 파일 업로드와 확정이 경쟁할 때 최신 파일 판정을 보호하는 방법은 A가 결정한다. B는 검증 시나리오를 제공한다.
- 확정/제출 뒤 기존 업무 전환 재시도의 읽기 응답 허용 여부는 K-12와 K-20을 맞춘다.

## 완료 기준

단위 테스트, 실제 PostgreSQL count·동시 요청·롤백, 인증 필터를 거친 HTTP 응답을 구분해 기록한다. C와 초안→피드백→업무→수정→재검토→확정 흐름을 확인하고, 실행 SHA·결과·미검증·의존 PR을 B 인수인계에 남긴다. 현재 검사는 모두 미수행이다.
