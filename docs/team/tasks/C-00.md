# C-00 · 사용자 흐름 점검과 화면 작업 준비

- 상태: READY (화면 조사·설계)
- 담당: 손정효 / 검토: 손정협, 서버 계약은 송승준
- 예상: 6시간 이내
- 기준 SHA: A-00 공유 후 기록. 그전에는 현재 화면 구조를 읽고 설계한다.

## 목표

‘제출물→업무’ 기존 화면을 살리고 ‘검토→제출’로 이어질 진입 경로를 정한다.

## 허용 범위

- frontend 페이지·컴포넌트·타입 및 기존 서버 DTO 읽기.
- `docs/team/handoffs/C-00-YYYYMMDD.md`, `docs/team/tasks/C-10.md` 신규 작성.
- 화면별 동작 표·화면 초안 작성. 실제 프론트 수정 파일은 C-10에 한정해 후속 구현.
- 서버/DB/공통 인증 코드 변경 금지.

## 산출물

1. 프로젝트 홈→제출물→요구사항→업무 보드 경로와 막히는 지점 목록.
2. 제출물 상세의 요구사항/업무·검토·최종 제출 영역 구성. 미구현 기능은 사용 가능처럼 표시하지 않는다.
3. 각 화면의 로딩·0건·권한 없음·저장 실패·재시도·저장 성공 상태 표.
4. 멤버 관리 기존 API 연결 계획. 코드 존재와 실제 동작 확인 여부를 구별한다.
5. K-10/K-13에서 필요한 응답 필드 요청. backend가 준비되기 전 개발 전용 mock을 쓰는 방법과 실제 연동 전환 기준.

## 완료 조건

- C-10에 변경할 실제 frontend 경로와 검증 시나리오를 적는다.
- 화면 예제 필드가 현재 계약인지 미래 계약인지 표시한다.
- 서버를 기다리는 동안 가능한 화면과 실제 API가 필요한 화면을 나눈다.
