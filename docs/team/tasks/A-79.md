# A-79 · AI 문서 초안 쓰기와 채택

- 담당: 송승준 / 검토: 손정협(파일 참여 집계), 손정효(카드 화면)
- 기능: S2 (AI 에이전트)
- 상태: IN_REVIEW
- 기준: A-78(#239) 위에 쌓은 브랜치. A-78이 병합된 후 main으로 대상을 바꾼다
- 근거: 계약 K-59(#238) 2·3·4장, 12주차 계획(#231) 정할 것 5

## 목표

K-59의 두 번째·세 번째 단계를 구현한다. 사람이 채택한 목차대로 장별 초안 카드를 만들고, 초안 카드를 채택하면 .docx로 파일 금고에 올려 그 파일로 검토 회차를 연다.

## 구현

- **.docx 생성**(`agent/draft/DocxWriter`): 새 라이브러리 없이 Office Open XML 여섯 파일을 직접 쓴다. 문서 제목, 장 제목(제목 1 스타일), 문단, 글머리 기호 목록, 장 끝의 근거 한 줄(회색 작은 글씨)이 들어가고 "[작성 필요: …]"는 굵게 표시한다. 글꼴은 지정하지 않고 용지는 A4다. XML에 넣을 수 없는 제어 문자와 짝 없는 서로게이트는 빼고 `&`·`<`·`>`는 이스케이프한다. 같은 내용이면 서버의 시간대와 상관없이 같은 바이트가 나온다(압축 항목의 시각을 지역 시각으로 고정)
- **실행 종류 `DRAFT_DOCUMENT`**("문서 초안 쓰기"): 팀장·팀원. 입력은 목차 카드 id다. 같은 프로젝트의 채택된 목차가 아니면 404, 채택 전·거절된 목차는 409 `OUTLINE_NOT_ACCEPTED`, 목차의 제출물이 확정·제출됐으면 409다. 채택한 목차의 장과 다룰 요구사항, 메모를 자료로 주고, 조회 도구는 목차 실행과 같다. 근거로 쓸 수 있는 id를 모델을 부르기 전에 읽어 두고, 모델이 쓴 근거 중 그 밖의 것을 빼서 "근거를 확인할 수 없어 n건은 뺐습니다"로 알린다
- **카드 종류 `DOCUMENT_DRAFT`**: 문서 제목, 장 1-6개(장 제목 100자, 본문 1200자, 근거 업무·회의·요구사항 id). 근거는 같은 프로젝트의 업무·회의와 그 제출물의 요구사항만 남고 검증할 때마다 다시 거른다. 형식이 틀린 id 하나로 카드 전체를 거절하지 않고, 겹친 id는 한 번만 남기되 "확인할 수 없는 근거"로 세지 않는다. `missingCount`("[작성 필요: …]"의 개수)도 검증할 때마다 센다. 콜론 앞 공백과 전각 콜론(：)도 같은 표시로 본다. 제출물과 목차 id는 고쳐도 바뀌지 않는다
- **채택**: 제출물을 먼저 잠가 확정·제출된 제출물이면 파일을 올리기 전에 409다. 그다음 화면 업로드와 같은 `FileVaultService.upload`로 `{제출물 제목} 초안.docx`를 올리고(채택한 사람이 올린 사람, 활동 기록 `FILE_CREATE`·`FILE_EDIT`, 같은 이름이면 다음 버전), 그 파일로 `ReviewRoundService.open`을 부른다(검토 요청 알림 그대로). 결과는 `FILE`, `REVIEW_ROUND`이고 응답의 `results.fileId`, `results.reviewRoundId`로 나간다. 근거 줄은 "근거: 업무 「제목」, 회의 「제목」(날짜)"이고 회의 날짜는 한국 시간이다. 파일 이름에 쓸 수 없는 문자는 `_`로 바꾸고 255자에 들게 자른다
- **파일 금고**: 업로드와 같은 트랜잭션이 되돌아가면 디스크에 쓴 파일을 지운다. 초안 채택뿐 아니라 업무 파일 업로드처럼 업로드 다음 일이 실패하는 모든 경로에 적용된다. 커밋 여부를 알 수 없을 때는 지우지 않는다
- **에이전트 실행기**: 실행 종류가 응답을 다 읽은 후 글 끝에 문장을 덧붙일 수 있게 했다(`AgentSkill.notes`). 카드는 남기고 카드 안의 일부만 뺀 사실을 알리는 데 쓴다
- **지시문**: `agent/skills/DRAFT_DOCUMENT.md`, `agent/kinds/DOCUMENT_DRAFT.md`. 기록에 없는 결과·수치·날짜·사람·인용은 쓰지 않고 "[작성 필요: 무엇]"으로 두게 한다. 본문에는 링크를 넣지 않는다
- **계약 K-30 0.12**: 실행 종류 표, 카드 종류, `results`의 `fileId`·`reviewRoundId`, 종류별 `content`에 위 내용을 더했다. 상태는 "검토 대기"다

## 검사

- .docx 4건(`DocxWriterTest`): 여섯 XML의 형식, 문단별 스타일과 글, 굵은 표시, 글머리 기호, 글꼴 미지정, 같은 입력의 같은 바이트(항목 시각 고정, 확장 필드 없음), 짝 없는 서로게이트 제거, 문단 나누기 규칙
- 편집기에서 열기: 시험 파일을 MS Word와 한컴오피스 한글에서 열어 확인했다. 구글 문서는 확인하지 않았다
- 실행 1건(`AgentRunnerTest`, 모델만 mock): 채택한 목차와 요구사항을 자료로 주고, 제출물·목차 id를 서버가 채우고, 다른 프로젝트의 요구사항과 형식이 틀린 id 두 건을 빼서 글 끝에 알리고(겹친 id는 세지 않음), `missingCount`를 센다
- 카드 HTTP 5건(`DocumentDraftCardHttpTest`, 실제 PostgreSQL·인증·파일): 고쳐도 제출물·목차 유지와 근거 거르기·`missingCount` 재계산, 채택 시 파일 이름·올린 사람·버전·활동 기록·검토 회차와 .docx 안의 본문·근거 줄, 채택한 사람의 회차 결정 403과 다른 팀원의 결정 200(K-59 8장 4), 두 번째 채택은 같은 이름의 버전 2와 `FILE_EDIT`, 확정된 제출물은 파일 없이 409, 실행 시작의 404·409 `OUTLINE_NOT_ACCEPTED`·400
- 이름과 표시 2건(`DocumentDraftKindTest`): 파일 이름의 경로 문자·줄바꿈 정리와 255자 자르기, "[작성 필요]"의 공백·전각 콜론 변형 세기
- 파일 금고 1건(`FileVaultRollbackTest`): 되돌린 업로드의 파일이 디스크에 남지 않는다. 지우기를 끈 상태에서는 이 테스트가 실패하는 것을 확인했다
- 실제 모델 1건(`DocumentDraftLiveTest`, 키가 있을 때만 실행): 요구사항 12개(필수 10개), 업무 4개, 회의 2개(끼워 넣은 지시와 전화번호 포함)인 테스트용 프로젝트로 목차와 초안을 만든다. Bedrock(`bedrock-haiku`, OpenAI 호환 API)으로 D1-D11을 모두 통과했다
  - 목차: 필수 요구사항 10개를 모두 장에 걸었다(출력 3,063 토큰)
  - 초안: 목차의 6개 장을 그대로 따르고, 기록에 있는 사실(기존 도구의 문제, 기술 스택, 핵심 기능)만 썼다. 기록에 없는 내용은 "[작성 필요]" 12군데로 남겼고, 성능·사용성 평가 장은 본문 전체가 "[작성 필요]"다. 끼워 넣은 지시와 전화번호는 초안에 나오지 않았다
  - 출력은 5,062 토큰으로 상한(8,192) 안이었지만, 본문은 6개 장 합쳐 676자였다. 근거 id·설명 글·모델의 내부 추론이 출력의 대부분이라, 기록이 많아 장마다 본문이 길어지면 상한에 가까워질 수 있다. 한 번의 결과라 관찰로 남긴다
  - Gemini(`gemini-3.5-flash-lite`)로는 답이 중간에서 끊겨 실패했다. 원인은 모델 연결이 여러 결과로 나뉜 응답의 첫 결과만 읽는 결함이고 A-80(#241)에서 수정했다. 수정 후 Gemini 재실행은 Gemini의 503(요청 혼잡)으로 아직 확인하지 못했다
  - 모델의 답 원문은 이 테스트에서만 출력한다(`DRAFTRAW`). 운영 로그에는 남기지 않는다
- 에이전트 실행기: 형식이 틀려 다시 요청할 때 문제 목록(칸 이름·규칙·기록 id)을 로그에 남긴다. 다시 요청한 호출까지 실패하면 무엇이 틀렸는지 남지 않았다

## 정할 것

- 초안 채택으로 올린 파일이 채택한 사람의 파일 참여로 집계된다(K-59 9장의 B 확인 사항). 지금은 K-30의 원칙(사람이 채택한 카드는 그 사람이 화면에서 한 것과 같다)대로 화면 업로드와 같은 활동 기록을 남긴다
- 같은 이름의 파일이 있으면 초안은 그 다음 버전이 되고, 화면에서 다시 올릴 때처럼 변경 기록(`REUPLOAD`)이 남는다. 초안을 다시 채택할 때마다 변경 기록이 쌓이는 것이 괜찮은지 B가 확인한다
- 모델로 보내는 기록의 동의(K-30 9장의 미결, A-78과 같음)
