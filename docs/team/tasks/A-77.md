## 목표

지금은 Mailpit으로 메일을 확인할 때 실행 인자로 SMTP 설정을 덮어써야 하고, 사람마다 컨테이너 이름과 포트가 다르다. 테스트 전용 수신함과 프로필을 정해 두어 같은 설정으로 확인 메일과 알림 메일을 확인하고, 확인 메일이 확인 API까지 가는 흐름을 자동 테스트로 남긴다.

## 구현

- **수신함**: `docker-compose.test-db.yml`에 `mail-test`(컨테이너 `blackbox_mail_test`)를 추가했다. 이미지는 `axllent/mailpit:v1.27.4`를 다이제스트로 고정했다(B가 #223 확인에 쓴 것과 같다). SMTP `127.0.0.1:28125`, 화면·API `127.0.0.1:28025`로 이 PC에서만 열고, 받은 메일을 밖으로 전달하지 않는다. 정보 API가 GitHub에 최신 버전을 묻지 않도록 버전 확인을 껐다
- **`test-mail` 프로필**(`application-test-mail.yml`): SMTP를 수신함으로 돌리고 인증·STARTTLS를 끄며 발송을 켠다. 발신 주소를 `blackbox@example.test`로 고정해 `.env`의 Gmail 계정과 앱 비밀번호를 쓰지 않는다. 수신 허용 목록은 그대로 적용된다
- **기동 차단**: SMTP 어댑터가 생성될 때, 인증이나 STARTTLS 필수가 꺼져 있는데 SMTP 주소가 loopback(`127.0.0.1`, `localhost`, `::1`)이 아니면 기동을 멈춘다. 프로필을 잘못 조합해도 외부 SMTP에 평문·무인증으로 보내지 않는다. 운영의 Gmail 설정(587, 인증, STARTTLS 필수)은 바뀌지 않는다
- **자동 테스트**: `EmailVerificationMailpitTest`가 test-mail 프로필로 확인 메일을 실제 SMTP로 보내고, 수신함 API에서 메일을 읽어 링크의 토큰으로 확인 API를 호출한다. SMTP와 인증 서비스 모두 mock이 아니다. `BB_MAIL_TEST_API`가 있을 때만 돈다
- **CI**: backend job에 같은 이미지의 Mailpit service와 `BB_MAIL_TEST_API`를 추가해 이 테스트가 PR마다 돈다
- **문서**: `docs/docker.md`에 수신함 기동과 `test-mail` 프로필 실행 방법을 적었다

## 검사

- `EmailVerificationMailpitTest` 1건: 발신 주소가 합성 주소, 수신자가 계정 주소 한 명, 본문 링크의 토큰으로 확인 204와 `email_verified_at` 기록. 끝나면 사용자와 받은 메일을 지운다
- `SmtpEmailNotificationTransportTest` 1건 추가: loopback 주소에서만 인증·STARTTLS를 끌 수 있고, 바깥 주소(`127.0.0.2`, `localhost.example.test` 포함)에서는 둘 중 하나만 꺼도 거절
- `SPRING_MAIL_HOST`를 바깥 주소로 바꿔 test-mail 프로필 테스트를 실행하면 기동 단계에서 위 오류로 실패하는 것을 확인했다
