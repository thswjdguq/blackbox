# A-83 · 괄호가 빠진 모델 응답 읽기

- 담당: 송승준 / 검토: 손정협, 손정효
- 기능: S2 (AI 에이전트)
- 상태: IN_REVIEW
- 기준: A-79(#240) 위에 쌓은 브랜치. #240이 병합된 후 대상을 main으로 바꾼다

## 문제

A-80(#241) 수정 후 Gemini(`gemini-3.5-flash-lite`)로 실제 모델 검사(`DocumentDraftLiveTest`)를 다시 돌렸다(11/28). 목차(D1-D4)는 처음으로 Gemini에서도 통과했고, 초안 응답도 끊기지 않고 끝까지 왔다. 그러나 초안 응답의 JSON이 카드 객체를 닫는 `}`를 빼고 목록의 `]`를 먼저 써 문법이 틀렸다. 형식을 고쳐 달라는 재요청에도 모델이 같은 응답을 냈고, 실행은 "답이 JSON 객체 하나가 아니다"로 실패했다. 내용은 온전했다.

## 수정

- `ModelJson`(에이전트 실행기): 모델 답에서 JSON 객체를 읽는다. 그대로 읽히지 않으면 괄호의 짝만 맞춰 한 번 더 읽는다. 닫는 괄호가 지금 열린 것과 다르면 빠진 닫는 괄호를 앞에 넣고, 열린 적 없는 닫는 괄호는 빼고, 끝까지 열린 괄호는 닫는다. 따옴표 안의 글은 건드리지 않는다
- 짝을 맞춘 결과도 카드 종류의 검증을 그대로 지나므로 모양이 틀린 내용은 저장되지 않는다. 그래도 읽히지 않으면 지금처럼 형식 재요청으로 넘어간다
- 실행기 하나에서 고쳐 모든 실행 종류에 적용된다

## 검사

- `ModelJsonTest` 5건: 11/28 Gemini 응답과 같은 모양(카드 객체의 `}` 없이 `]`), 따옴표 안의 괄호와 이스케이프된 따옴표, 끝에서 빠진 괄호와 짝 없는 닫는 괄호, 올바른 JSON은 그대로이고 객체 밖의 글은 버림, 고칠 수 없는 답은 지금처럼 실패
- `AgentRunnerTest` 1건: `}` 하나가 빠진 계획 만들기 답이 다시 묻지 않고 카드 2장으로 저장된다
- 실제 모델 검사(11/28, Gemini, 이 브랜치): `DocumentDraftLiveTest`의 D1-D11을 모두 통과했다. 목차와 초안 모두 형식 재요청 없이 끝났고, 초안은 장 6개·본문 456자·"[작성 필요]" 10군데였다. 이번 응답에서 괄호 짝 맞춤이 실제로 쓰였는지는 로그가 없어 알 수 없으므로, 그 동작은 단위 테스트로 확인한 것으로 둔다. Bedrock 결과(#240)와 합쳐 K-59 수용 테스트 7은 두 공급자에서 통과했다
