## 초기 설계·검증 이력

- 담당 B / 검토 A / 기준 main `611d9c4b` / 2026-11-23.
- 선행: #214·#217·#218·#219 및 #221 K-41 0.5가 A·C 승인 후 main에 반영됐다. 실제 인증/설정 조회·SMTP 결합 전이므로 이 작업은 Draft를 유지한다.
- 사용자 요구: 현재 주소 인증과 수신 동의를 마친 사람에게만 업무 메일 발송. 허용 목록으로 인증을 우회하지 않는다.
- 허용: B 신규 EmailDeliveryAuthorization 내부 읽기 경계, EmailDeliveryWorker, B EmailOutboxQueue의 인증/동의 확인, 대응 검사·작업/인수인계. 기존 조회/대기 저장소·composer·transport를 소비한다.
- 금지: A 인증/SMTP/SQL·번호·C 화면·라이브러리·환경 파일·운영 서버 변경. 실제 주소의 메일 발송·비밀값 읽기 없음.
- 범위: 꺼짐/빈 허용 목록/인증 조회 또는 transport 부재 시 대기 획득 없음. 한 번에 한 건씩, 최대25건. 현재 인증·수신 설정·요청 자격·주소·대기 생성 전 인증/동의 시각을 확인한다. SMTP 전 남은 lease30초 이하이면 보내지 않는다.
- 결과: ACCEPTED→SENT, 일시 실패/결과 불명→재시도, 인증/영구 실패→FAILED, 조건 소멸→SKIPPED. 저장소의 획득 fencing·최대3회·지연을 사용하고 SMTP 중 행 잠금을 유지하지 않는다.
- A Ready 전 리뷰 반영: 일시·결과 불명·인증 실패는 결과 저장 뒤 현재 회차를 중단한다. 인증 실패는 결과 저장 실패 여부와 관계없이 재기동 전까지 새 획득을 멈춘다. 대기 id와 예외 종류만 기록하며 원본 예외/주소/본문은 기록하지 않는다. 관련145/145 통과, 실제 인증/설정 조회는 여전히 선행이다.
- 검증: 네트워크 없는 단위 검사에서 미인증/동의 철회/재인증·현재 주소 변경/오래된 요청/lease/결과 분류/재진입을 확인한다. 실제 인증 API·PostgreSQL·SMTP 수신은 별도 결합 검증 전까지 완료로 표시하지 않는다.
