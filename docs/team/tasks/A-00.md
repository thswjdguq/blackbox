# A-00 · 공통 출발점과 실행 환경 정리

- 상태: READY (조사·기준선 준비만, 원격 반영은 별도 실행 요청 시)
- 담당: 송승준 / 검토: 손정협
- 예상: 6시간 이내. 초과 시 CI 실제 적용은 A-01로 분리.
- 기준: 작업 시작 시 main의 SHA·원격 차이·로컬 변경 목록을 기록한다. 이 문서 작성 시점의 미커밋 상태를 기준 커밋으로 오해하지 않는다.

## 목표

이미 작성된 1단계 기능을 세 사람이 같은 코드에서 이어갈 수 있게 만든다. 제출물 기능을 다시 작성하지 않는다.

## 허용 범위

- 전체 소스·Git 상태·설정 예시 읽기. 비밀값 출력 금지.
- `docs/team/handoffs/A-00-YYYYMMDD.md`, `docs/team/ENVIRONMENT.md` 신규 작성.
- 기존 미커밋 코드를 기준선 PR에 넣을 후보로 분류. 코드 수정은 해당 소유자와 별도 Task로 분리.
- 별도 테스트 DB에서 기존 migration 적용 및 현재 검사 실행. 기존 DB/볼륨 초기화 금지.

## 순서

1. 기존 코드 변경·문서·빌드 생성물·PPT 산출물을 분류한다. `backend/bin` 상태를 임의 복구/삭제하지 않는다.
2. 기존 V19 및 제출물 API/화면/테스트가 기준선 후보에 모두 포함되는지 확인한다.
3. 사용 JDK·Node·Docker/DB 및 실제 실행 명령을 ENVIRONMENT.md에 기록한다.
4. 현재 관련 테스트·프론트 타입/빌드를 실행하고 DB 통합 가능 여부를 구분한다.
5. 기준선 PR 설명·명시적 파일 목록·검사 근거를 준비한다. 원격 반영 요청을 받아 병합하면 최종 SHA를 기록한다.

## 완료 조건

- B/C에게 전달할 기준선 후보와 재현 절차가 명확하다.
- 실제 병합 전에는 ‘공유 완료’라고 표시하지 않는다.
- 공통 출발 SHA 확정 후 셋이 같은 SHA를 받았는지 확인한다.
- A-01에 필요한 CI 검사와 남은 환경 문제를 인계한다.

의존성: 없음. B-00/C-00의 조사·설계는 동시에 가능하다.
