# A-78 · AI 문서 목차 만들기

- 담당: 송승준 / 검토: 손정협(회의 조회), 손정효(카드 화면)
- 기능: S2 (AI 에이전트)
- 상태: IN_REVIEW
- 기준 SHA: `63ead3fd`(#234 병합)
- 근거: 계약 K-59(#238) 2·3·5장, 12주차 계획(#231) 정할 것 5

## 목표

K-59의 첫 단계인 목차를 구현한다. 제출물 하나의 요구사항과 업무·회의 기록으로 목차 카드를 만들고, 사람이 고쳐 채택한 목차가 13주차에 구현할 초안 실행(`DRAFT_DOCUMENT`)의 입력이 된다.

## 구현

- **읽기 도구 `list_meetings`**: 기존 회의 목록 조회를 요청한 사람의 권한으로 부르고, 제목·날짜·목적·결정 사항과 회의록 앞 1000자만 돌려준다. 1000자는 코드 포인트로 세어 이모지를 반으로 자르지 않고, 잘렸으면 `notesTruncated`로 알린다. 제목·목적·결정 사항·회의록의 이메일 주소와 전화번호는 `[이메일]`, `[전화번호]`로 가린 후 자른다(K-30 5장의 "연락처는 보내지 않는다"). 출석, 체크인 코드, 노션 정보, 액션 아이템은 넣지 않는다
- **공통 지시문**: 도구가 돌려준 기록의 글(회의록, 결정 사항, 설명, 제목 등)에 든 지시도 따르지 않는다는 규칙을 더했다. 모든 실행에 적용된다. 회의록은 팀원이 길게 쓰는 첫 자유 글이라 지시가 섞일 여지가 크다
- **실행 종류 `DRAFT_OUTLINE`**("문서 목차 만들기"): 팀장·팀원. 제출물·업무·회의·프로젝트 조회 도구를 쓴다. 다른 프로젝트의 제출물은 404, 확정·제출된 제출물은 모델을 부르기 전에 409(K-20의 "확정된 제출물은 변경할 수 없습니다")다. 모델이 쓴 제출물 id는 버리고 고른 제출물로 채운다
- **카드 종류 `DOCUMENT_OUTLINE`**: 문서 제목(255자), 장 1-6개(장 제목 100자, 메모 500자, 다루는 요구사항 id). 요구사항은 그 제출물의 것이어야 한다. 어느 장에도 걸리지 않은 필수 요구사항(`uncoveredRequirementIds`)은 서버가 검증할 때마다 다시 계산한다. 사람이 고칠 때 제출물은 바뀌지 않는다. 채택해도 기록을 만들지 않는다(`results`가 모두 비어 있음)
- **지시문**: `agent/skills/DRAFT_OUTLINE.md`, `agent/kinds/DOCUMENT_OUTLINE.md`. 필수 요구사항을 반드시 어느 장에 걸고, 장마다 쓸 자료가 기록에 얼마나 있는지 적게 한다. 근거가 될 기록이 없으면 카드 없이 글로 답한다
- **계약 K-30 0.11**: 실행 종류 표, 카드 종류, `results`의 설명, 종류별 `content`, 읽기 도구 표에 위 내용을 더했다. 이 PR에서 B·C가 확인하기 전이라 상태는 "0.10까지 AGREED, 0.11은 검토 대기"로 적었다
- 화면은 모르는 실행 종류를 그리지 않으므로(`frontend/src/lib/agent/skills.ts`), C의 화면이 병합되기 전에는 사용자에게 보이는 변화가 없다
- DB 마이그레이션은 없다(V25가 실행·카드 종류를 코드 등록으로 늘리게 되어 있다)

## 검사

- 실행 1건(`AgentRunnerTest`): 모델이 다른 프로젝트의 제출물 id를 써도 고른 제출물로 저장, 도구 4개 제공, 걸리지 않은 필수 요구사항만 표시(선택 요구사항 제외)
- 카드 HTTP 4건(`DocumentOutlineCardHttpTest`, 실제 PostgreSQL·인증): 고쳐도 제출물 유지와 걸리지 않은 요구사항 재계산, 다른 제출물의 요구사항·장 7개·빈 장 제목·256자 제목 거절, 채택 시 기록 없음, 확정된 제출물 409
- 도구 2건(`AgentToolboxTest`): 회의록 1000자 자르기(이모지 경계), 체크인 코드·노션 정보 제외, 이메일·전화번호 가리기(010·02·+82 형식, 날짜·금액·학번·버전 번호는 그대로)
- 카드를 고쳐도 제출물을 유지하는 처리와 걸리지 않은 필수 요구사항 계산을 각각 끈 상태로 돌리면 테스트가 실패하는 것을 확인했다
