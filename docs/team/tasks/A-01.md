## 목표

모든 PR이 사람 손을 거치기 전에 같은 기준으로 검사되게 하고, DB를 새 환경에서 재현하는 절차와
기존 데이터를 그대로 둔 채 새 마이그레이션을 얹는 절차를 실제로 한 번 통과시킨다.

## 허용 파일

- 신규 `.github/workflows/ci.yml`
- 신규 `docker-compose.test-db.yml`
- 신규 `scripts/verify-db.sh`
- 신규 `backend/src/test/resources/application-test.yml`
- 본 작업서와 A 개인 인수인계

`.github/workflows/**`·`docker-compose*`·실행 스크립트·`BlackboxApplicationTests`는 OWNERSHIP 기준 A 소유다.
백엔드/프론트 운영 코드, 마이그레이션 SQL, 타 담당 파일은 이 Task에서 수정하지 않는다.

## 범위

1. **CI 3개 job** — `backend`(Java 17 + PostgreSQL 16 service, `./gradlew build`), `migrations`(아래 검증 스크립트),
   `frontend`(Node 20, `npm ci` → `type-check` → `build`). PR과 main 푸시에서 실행한다.
2. **검사 전용 DB** — 개발·데모 DB와 컨테이너·볼륨·포트를 분리한 `docker-compose.test-db.yml`(55432).
   일반 검증에서 `down -v`를 쓰지 않는다(WORKFLOW §6).
3. **검증 스크립트** — 깨끗한 DB 전체 마이그레이션(V1~V19) + JPA `ddl-auto=validate`,
   기존 V18 데이터 위에 V19 적용 후 데이터 보존, V19 제약의 실제 동작까지 확인한다.
4. **테스트 프로파일** — `BlackboxApplicationTests`가 쓰는 `application-test.yml`. 더미 값만 담고 환경변수로 덮어쓴다.

## 금지 범위

운영 코드 동작 변경, 마이그레이션 SQL 신규/수정, 실패 테스트 삭제, 비밀값 커밋, GitHub 설정을 '완료'로 기록하는 것.
브랜치 보호·필수 검사 설정은 이 PR 병합 후 실제 설정 화면에서 수행하고 결과를 인수인계에 적는다.
