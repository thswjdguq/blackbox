# C-31 · 빈 상태·오류 안내 정리

- 상태: IN_PROGRESS (1차: 실패를 삼키거나 추측 문구를 쓰던 곳 정리)
- 담당: 손정효 / 검토: 손정협
- 주차: 5주차 계획을 앞당김 (C-30은 K-20 계약 대기)
- 브랜치: `2026-10-01/기능-C31-빈상태오류안내`

## 점검 방법

`frontend/src` 전체에서 `catch {}`, `.catch(() => {})`, 고정 실패 문구를 찾아 사용자가 실패를 모르거나 잘못 이해하는 곳을 골랐다. 알림 벨처럼 실패해도 되는 보조 기능은 그대로 둔다.

## 1차 수정

| 화면 | 문제 | 수정 |
| --- | --- | --- |
| 대시보드 | 프로젝트 목록 조회가 어떤 이유로든 실패하면 로그인 화면으로 보냈다. 서버 오류가 로그아웃처럼 보였다 | 401은 기존 api 인터셉터가 처리하므로, 그 밖의 실패는 안내 + 다시 시도 |
| 파일 금고 업로드 | 관찰자 거절(403)·용량 초과도 "파일 크기나 권한을 확인해주세요"로만 보였다 | 서버 사유 표시 |
| AI 일정 조율 회의 생성 | 모든 실패를 "리더 권한이 필요합니다"로 안내 (권한 문제가 아닐 때도) | 서버 사유 표시 |
| 분석 화면 | 리포트·재계산 실패가 고정 문구 | 서버 사유 표시 |
| 회의 만들기 | 팀원 목록을 못 불러와도 아무 표시 없이 참석자 선택지가 비었다 | 안내 표시 |
| 회의 상세 | 체크인 코드 재생성, 액션 아이템 추가 실패가 고정 문구 | 서버 사유 표시 |

## 확인

- `type-check` 소스 오류 0, 개발 서버에서 대상 6개 화면 컴파일·로드
- 미수행: 각 실패 상황을 브라우저에서 재현
