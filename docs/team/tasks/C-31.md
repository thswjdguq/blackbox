## 2차: 역할별 빈 상태와 버튼 (2026-10-12)

빈 프로젝트를 팀장·팀원·관찰자로, 프로젝트가 없는 새 계정으로 열어 화면 34곳의 0건 상태 문구를 모았다. 문구가 할 일을 시키는데 그 역할은 할 수 없거나, 서버가 거절하는 버튼이 보이는 곳을 고쳤다.

| 화면 | 문제 | 고친 것 |
| --- | --- | --- |
| 회의 목록 | 팀원·관찰자에게도 "새 회의". 서버는 팀장만 받아 팀원은 세 단계를 다 채운 뒤 403 | "새 회의"는 팀장에게만. 팀원 "회의는 팀장이 만듭니다…", 관찰자 "팀장이 회의를 만들면 여기서 회의록을 볼 수 있습니다" |
| 회의 상세 | 관찰자에게 회의록 편집·저장·AI 요약·Notion·캘린더·액션 아이템·체크인. 저장은 서버가 200으로 받음 | 관찰자는 읽기 전용(회의록 칸 읽기 전용, 쓰기 버튼 없음, 체크인 대신 안내) |
| 파일 금고 | 관찰자에게 업로드 칸(서버 403) | 관찰자는 업로드 칸 대신 "볼 수만 있습니다", 빈 목록 문구도 관찰자용 |
| 제출물 상세 | 관찰자·확정된 제출물에도 "적으세요", "추가하거나 연결하세요" | 쓸 수 없으면 "등록된 요구사항이 없습니다", "연결된 업무가 없습니다" |
| 프로젝트 홈 | 관찰자에게 기여도 "재계산하세요", "재계산 필요"(관찰자 403) | 관찰자는 "팀장·팀원이 계산하면 여기에 표시됩니다", "계산 전" |

- 역할은 `useMyRole`(멤버 목록)로 읽는다. 아직 모를 때는 쓰기 버튼을 감춘다(회의 만들기)
- 서버 쪽 문제는 #115에 B에게 남겼다: 비멤버도 체크인 코드로 참석자가 됨, 관찰자의 회의록 수정 200, 회의 만들기가 팀장 전용(CONTRACTS 1장은 팀장·팀원 쓰기)
- 회의 만들기를 팀원도 하도록 서버가 바뀌면 회의 목록의 조건을 되돌린다

브라우저 확인 16/16 (Edge headless, 실제 서버 main `78c4413`, 팀장·팀원·관찰자). 바뀐 화면의 예전 확인도 다시 통과했다: 파일 금고 내려받기 8/8, 회의 만들기·체크인(#97) 8/8, 다음 할 일 25/25, 관찰자 점수·경보 17/17.
