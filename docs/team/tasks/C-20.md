## 화면

- 상단: 제출물 상태, 제출물 전체 미해결 피드백 수(`unresolvedCommentCount`), "검토 요청"/"새 검토 회차 열기"
- 회차는 응답 순서(최신이 먼저)대로 그리고, 최신 회차는 `latest`로 정한다
- 회차 열기 창: 파일 금고(`GET /projects/{id}/files`)를 이름별로 묶어 최신 버전 기본 선택, 버전 선택, 파일 없는 중간 검토(`fileId: null`)
  - 이전 회차와 다른 이름이면 "같은 이름으로 올려야 새 버전으로 이어집니다"
  - 지금 확정 근거인 승인(`currentBasis`)이 있으면 "새 회차를 열면 지금 승인은 확정 근거에서 빠집니다"
  - 최신 회차가 결정 전이면 "진행 중인 N회차는 결정 없이 남습니다" (회차 취소가 없으므로)
- 회차 카드: 파일·버전·`shortHash`·올린 사람, 결정(`decision.result`)·결정자·시각
  - 결정 버튼은 최신 회차·결정 전·팀장/팀원에게만. 파일 올린 사람에게는 승인·수정 요청 모두 없음 (서버 403)
  - 미해결이 있으면 승인 비활성 + 이유. 파일 없는 회차도 승인 가능하지만 "확정 근거가 되지 않습니다"
  - 결정 전 지난 회차는 "결정 없음"
  - 확정 근거가 아닌 승인은 흐리게 + 사유: 이후 새 회차가 열림 / 파일 없는 회차 / 같은 이름의 최신 버전과 내용이 다름 (K-10 7장)
- 피드백: OPEN 미해결 / REFLECTION_PENDING 반영 확인 대기 / RESOLVED 해결됨(해결자·시각·사유가 있으면 사유)
  - 해결 사유는 선택. 비우면 본문 `{}`를 보낸다 (K-11 2장)
  - 연결 업무가 끝나지 않았어도 해결할 수 있다 (K-11 3장)
  - 새 피드백은 최신 회차에만. 승인 안 된 지난 회차는 해결·다시 열기만. 승인된 회차·확정된 제출물은 읽기 전용
  - 업무로 만들기: 제목은 피드백 첫 줄, 최대 255자 (K-12)
- 수정본 안내: 최신 회차가 수정 요청이면 미해결 수와 "같은 이름으로 파일 금고에 올리고 새 회차를 여세요"
