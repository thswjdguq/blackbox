## 화면

- 상세 화면 "검토" 탭 활성화
- 상단: 제출물 상태 뱃지, 제출물 전체 미해결 피드백 수, "검토 요청"/"새 검토 회차 열기"
- 회차 열기 창: 파일 금고(`GET /projects/{id}/files`)를 이름별로 묶어 최신 버전 기본 선택, 버전 선택, 파일 없는 중간 검토
  - 이전 회차와 다른 이름이면 "같은 이름으로 올려야 새 버전으로 이어집니다"
  - 지금 확정 근거인 승인이 있으면 "새 회차를 열면 지금 승인은 확정 근거에서 빠집니다"
- 회차 카드 (최신이 위): 파일·버전·짧은 해시·올린 사람, 결정 뱃지, 연 사람·결정자·시각
  - 결정 버튼은 최신 회차·결정 전·팀장/팀원에게만
  - 파일 올린 사람에게는 버튼 대신 "직접 올린 파일은 다른 팀원이 검토합니다"
  - 미해결이 있으면 승인 비활성 + 이유
  - 파일 없는 회차: "승인은 최종 확정 근거가 되지 않습니다"
  - 확정 근거가 아닌 승인은 흐리게 + 이유
- 피드백: OPEN 미해결 / REFLECTION_PENDING 반영 확인 대기 / RESOLVED 해결됨(해결자·시각·사유, "해결은 반영 판정이 아닙니다")
  - 해결(사유 입력, 기본 "반영했습니다."), 다시 열기, 업무로 만들기(제목은 피드백 첫 줄, 완료 기준 선택)
  - 연결 업무가 끝나기 전에는 해결 비활성 + 이유 (K-11 3장 제안)
  - 새 피드백은 최신 회차에만. 승인된 회차·확정된 제출물은 읽기 전용
  - 관찰자는 목록만
- 수정본 안내: 최신 회차가 수정 요청이면 미해결 수와 "같은 이름으로 파일 금고에 올리고 새 회차를 여세요"
- 서버에 검토 API가 없으면 "검토 기능은 서버 준비 중입니다" (가짜 데이터 없음)

## K-10 가정 (계약 초안이 나오면 확인)

`lib/api/review.ts`의 세 함수와 `types/review.ts`의 회차 타입만 고치면 된다.

| 가정 | 내용 |
| --- | --- |
| 회차 목록 | `GET .../deliverables/{id}/reviews` → `{ deliverableStatus, unresolvedCount, rounds[] }` |
| 회차 열기 | `POST .../reviews` `{ fileId? }` → 회차 |
| 결정 | `PUT .../reviews/{reviewId}/decision` `{ decision: "APPROVED" \| "CHANGES_REQUESTED" }` → 회차 |
| 회차 필드 | `roundNo`, `file{fileId, fileName, version, fileHash, uploaderId, uploaderName} \| null`, `decision`, `decidedBy`, `decidedAt`, `openedBy`, `openedAt`, `isCurrentBasis` |

`unresolvedCount`·`isCurrentBasis`·파일 요약은 #58 리뷰에서 요청한 필드다.
