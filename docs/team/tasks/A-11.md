## 목표

K-10의 검토 회차를 서버에 구현한다. 회차 목록·열기·결정 API, 피드백과 업무 전환이 쓸 회차 확인·제출물 잠금 인터페이스, 미해결 피드백 수 인터페이스, DB 변경(V21)까지다.

## 할 일

1. V21: `review_rounds` 테이블과 제약, `file_vault`의 `(id, project_id)` 유일 제약
2. 회차 엔티티와 저장소, 제출물 행 잠금
3. 회차 목록·열기·결정 API. 제출물 상태와 확정 근거는 저장하지 않고 계산한다
4. `ReviewRoundReader`(회차 확인·잠금), `UnresolvedCommentCounter`와 0을 돌려주는 기본 구현
5. 회차가 있는 제출물 삭제 409
6. 같은 이름 재업로드에서 변조 경보를 만들지 않는다(결정안 `docs/team/handoffs/A-10-20260930.md` 4장)
7. K-10 9장 수용 조건을 실제 DB와 HTTP로 확인한다

## 금지 범위

피드백(K-11)·업무 전환(K-12)의 코드와 V22는 이 Task에서 만들지 않는다. 화면 코드(`frontend/**`)와 경보·점수 코드(B 소유)는 바꾸지 않는다. 기존 V1~V20은 수정하지 않는다. 확정·제출 기록(K-20)은 범위 밖이다.
