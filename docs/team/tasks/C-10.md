## 구현 범위

- 제출물 목록 페이지 (`/projects/[projectId]/deliverables`)
  - 추가·삭제 (팀장·팀원), 관찰자는 읽기 전용
  - 409 (연결 업무 있음) 오류 안내
  - 로딩·0건·오류·재시도 상태
- 제출물 상세 페이지 (`/projects/[projectId]/deliverables/[deliverableId]`)
  - 서버에 `GET /deliverables/{id}` 단건 조회가 없으므로 목록(`GET /deliverables`)에서 id 로 찾는다
  - 요구사항 목록·추가·삭제
  - K-14 충족 확인 체크박스 (낙관적 업데이트, 실패 시 해당 요구사항만 원복 + 안내, 관찰자 비활성)
  - 연결 업무 목록 (deliverableId 기준 필터)
  - K-13 진척 현황: 실제 `GET .../progress` 호출
  - 탭 구조: 요구사항·업무(구현) / 검토·최종 제출(준비 중)
- Sidebar: 제출물 메뉴 아이콘 ClipboardList, 레이블 "제출물"

## K-13 진척 표시 (B-10 서버 기준)

서버(`DeliverableProgressDtos`)는 `met`·`percent` 를 항상 숫자로 반환한다.

| 조건 | 화면 |
|------|------|
| `tasks.total === 0` | "연결 업무 없음" (0% 로 표시하지 않음) |
| `requiredRequirements.total === 0` | "필수 요구사항 없음" |
| 그 외 | `met/total (percent%)` |
| API 실패 | 가짜 0% 대신 오류 표시. 이후 재조회가 성공하면 오류 해제 |

요구사항 추가·삭제·충족 확인 변경 후 진척을 다시 조회한다.

## K-14 충족 확인

A-04 로 `/requirements/{id}/assessment` API 구현 완료.
- PUT → 충족 확인, DELETE → 확인 해제, 둘 다 갱신된 요구사항 반환
- 문구 수정 시 체크 초기화는 서버가 담당 (K-14 §2)
- 화면 알림 (K-14 §6-1) 은 후속 개선 항목
