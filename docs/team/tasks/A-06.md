## 발견 경위

- 손정효가 4주차 보고에서 "`start-local.ps1`로 띄우면 화면의 API 호출이 실패한다"고 보고했다. 코드로 확인했다.
- A-01 이후 Windows에서 `scripts/verify-db.sh`가 검사용 DB를 띄우지 못하는 경우가 있었다.

## 사실

1. `frontend/src/lib/api.ts`는 `baseURL: "/api"`로 요청하고, `frontend/next.config.mjs`는 `NEXT_DEV_BACKEND`가 있을 때만 `/api/*`를 백엔드로 넘긴다. `start-local.ps1`의 화면 명령(`$frontendCmd`)은 이 값을 넘기지 않는다. `frontend/.env.local`에 따로 적어 두지 않았다면 개발 서버에 `/api` 경로가 없어 화면의 모든 API 호출이 실패한다.
2. Docker 설정(`frontend/Dockerfile`, `docker-compose*.yml`)은 `NEXT_PUBLIC_API_URL`을 넘기지만 화면 코드는 이 값을 읽지 않는다. README 환경 변수 표와 `frontend/.env.example`은 이 값만 안내하고, 로컬 개발에 필요한 `NEXT_DEV_BACKEND`는 어디에도 적혀 있지 않다.
3. 검사용 DB 포트 55432는 Windows(Hyper-V·WinNAT)가 예약하는 구간(예: 55386~55485)에 들어가 "ports are not available"로 실패할 수 있다. 개발 DB 컨테이너(`blackbox_db`)와는 관계없다. 49152 미만 포트는 이 예약 구간에 들어가지 않는다.

## 할 일

1. `start-local.ps1`의 화면 명령에 `$env:NEXT_DEV_BACKEND='http://localhost:8080';`를 넣는다.
2. README 환경 변수 표에 `NEXT_DEV_BACKEND`(로컬 개발 전용, `/api` 프록시 대상)를 추가하고, `NEXT_PUBLIC_API_URL` 행은 "현재 화면 코드가 읽지 않음"으로 고친다. Docker 설정은 배포 경로라 이 Task에서 바꾸지 않는다.
3. 검사용 DB 포트를 25432로 바꾼다: `docker-compose.test-db.yml`, `scripts/verify-db.sh` 기본값, `backend/src/test/resources/application-test.yml`(설명·기본 URL), A-01 작업서·인수인계의 포트 표기.
4. `frontend/.env.example`은 C 소유라 고치지 않고, 같은 내용을 PR 후속 작업으로 손정효에게 넘긴다.

## 금지 범위

화면 코드(`frontend/**`)와 CI 워크플로(검사용 DB 포트를 쓰지 않음)는 바꾸지 않는다. 개발 DB(`docker-compose.yml`, 5432)는 건드리지 않는다. 일반 검증에서 `docker compose down -v`를 쓰지 않는다.
