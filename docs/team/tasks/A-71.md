## 목표

B의 발송 실행기(worker)가 부를 `EmailNotificationTransport`를 구현한다. A-63의 `spring.mail` 설정(smtp.gmail.com:587, 인증·STARTTLS 필수, 연결·읽기·쓰기 각 5초)으로 수신자 한 명에게 한 통을 보내고, 결과를 다섯 가지로 나눠 돌려준다.

## 구현

- `SmtpEmailNotificationTransport`: `JavaMailSender`로 보낸다
  - 받는 사람은 To 한 명뿐이다. 주소가 둘 이상이거나 그룹 주소(`목록:a@x,b@y;`)이거나 형식이 틀리면 보내지 않는다
  - 본문은 plain text UTF-8, 제목의 줄바꿈은 공백으로 바꾼다. 보내는 사람 이름은 `Team Blackbox`, 주소는 `MAIL_USERNAME`이다
  - Message-ID는 `<deliveryId@발송 계정 도메인>`이다. 재시도해도 같은 값이다. Spring의 `JavaMailSenderImpl`이 미리 지정한 Message-ID를 보존하는 것을 테스트로 확인했다
  - `MAIL_ENABLED=false`에서 불리면 SMTP에 접속하지 않고 예외를 던진다. 실행기가 부르지 않아야 하는 상황이기 때문이다
  - 로그에는 발송 id·결과·SMTP 응답 코드·예외 종류만 남긴다. 예외 메시지에는 주소와 서버 응답 원문이 들어 있을 수 있어 남기지 않는다
- `build.gradle`: 스타터가 실행 시에만 넣던 Angus Mail을 컴파일 의존성으로도 둔다. SMTP 응답 코드를 읽는 데 필요하다. 버전은 Spring Boot가 관리한다

## 결과 분류

`JavaMailSenderImpl`이 실패를 감싸는 방식(연결 단계, 발송 단계, 종료 단계)을 기준으로 나눈다. 실행기는 이 결과를 `EmailDeliveryRepository`의 완료 처리에 그대로 옮긴다(`ACCEPTED`는 `SENT`, 나머지는 같은 이름의 `Failure`).

| 상황 | 결과 | 실행기 처리(#217) |
| --- | --- | --- |
| 서버가 메일을 받음. 받은 뒤 연결 종료만 실패한 경우 포함 | `ACCEPTED` | SENT |
| 로그인 거절, 발송 계정(`MAIL_USERNAME`) 없음 | `AUTHENTICATION_FAILURE` | FAILED |
| 서버의 5xx 응답(수신자 없음, 하루 발송 한도 초과 등), 주소 형식 오류 | `PERMANENT_FAILURE` | FAILED |
| 연결 단계 실패(접속 시간 초과, STARTTLS 불가 등). 아직 아무것도 보내지 않음 | `TEMPORARY_FAILURE` | RETRY |
| 서버의 4xx 응답(나중에 다시 시도) | `TEMPORARY_FAILURE` | RETRY |
| 보내는 중 응답 없이 끊김(읽기 시간 초과 등). 서버가 받았을 수 있음 | `UNKNOWN_OUTCOME` | RETRY |

## 검사

- 단위 8건(`SmtpEmailNotificationTransportTest`): Spring의 실제 `JavaMailSenderImpl`을 쓰고 SMTP 연결만 가짜로 바꿨다. 실패는 Angus가 실제로 던지는 예외(`SMTPSendFailedException`, `SMTPAddressFailedException`, `AuthenticationFailedException`)로 재현했다. 네트워크에는 닿지 않는다
- 실제 발송 1건(`SmtpEmailNotificationTransportLiveTest`): 환경 변수 `MAIL_LIVE_TO`가 있을 때만 돈다. CI에서는 건너뛴다. DB 없이 메일 설정만 띄운다. 발송 계정 없이 돌려 SMTP 접속 전에 `AUTHENTICATION_FAILURE`가 나오는 것까지 확인했다
- 백엔드 전체 557건 통과(건너뜀 5건은 실제 모델·메일 테스트), 새 검사용 DB 사용

## 실제 Gmail 발송 결과

로컬 PC에서 서비스 전용 Gmail 계정과 앱 비밀번호로 실제 발송 테스트를 실행했다. 받는 주소는 담당자 본인의 테스트 주소다.

| 항목 | 결과 |
| --- | --- |
| 테스트 | 1건 통과 |
| Gmail SMTP 응답 | 수락(`ACCEPTED`), 로그 `메일 발송 수락 delivery=<발송 id>` 한 줄 |
| 수신 | 받은편지함에서 `[Team Blackbox] 메일 발송 시험` 메일을 확인했다 |

서버(EC2)에서의 발송은 B의 발송 실행기가 병합된 후 확인한다.

## 실제 Gmail 발송 확인 방법

담당자가 로컬에서 실행한다. 저장소 최상위 `.env`의 `MAIL_USERNAME`·`MAIL_PASSWORD`를 이 명령에만 넘기고, 받는 주소는 수신에 동의한 테스트 계정만 쓴다. 빌드에는 Java 25가 필요하다.

```bash
cd backend && env JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 $(grep -E '^MAIL_(USERNAME|PASSWORD)=' ../.env | xargs) MAIL_LIVE_TO=<받을 주소> ./gradlew test --tests '*SmtpEmailNotificationTransportLiveTest' --rerun
```
