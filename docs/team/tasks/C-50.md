## 1. 왜

국내 협업툴 Flow(플로우)의 화면 구성을 참고해 Blackbox 화면을 다듬는다. **화면 배치와 이동 방식은 참고하고, 흐름(제출물 → 요구사항 → 업무 → 검토 → 확정 → 제출 기록)은 지금 Blackbox 것을 유지한다.**

Flow는 회사 팀의 범용 협업툴이고, Blackbox는 대학생 팀 과제 PMS다. Flow 리뷰에서도 타임라인(피드) 위주라 업무의 전체 맥락과 이력을 파악하기 어렵다는 한계가 지적된다. 과제는 "무엇을 언제까지 어떤 조건으로 내야 하는가"가 중심이라, Blackbox는 제출물을 축으로 둔다. 이 차이가 우리 강점이므로 Flow를 그대로 따라가지 않는다.

## 4. 지금 Blackbox 흐름에서 불편한 점

브라우저로 화면을 돌며 확인한 것이다(C-00·C-31·C-40 점검 포함).

1. **프로젝트를 옮겨 다니기 어렵다.** 프로젝트 전환은 대시보드로 나가거나 업무 보드 머리의 드롭다운으로만 된다. 사이드바에는 지금 프로젝트 이름도 없다
2. **"내가 오늘 할 일"이 없다.** 대시보드는 프로젝트 카드와 체크인한 회의뿐이다. 여러 과목·팀플을 동시에 하는 학생은 프로젝트마다 보드를 열어야 내 업무를 안다
3. **메뉴가 기능 이름 순서다.** 사이드바에 1단계 기능(Hash Vault, 기여도)과 핵심 흐름(제출물, 업무 보드)이 같은 무게로 섞여 있고, "Hash Vault"는 검토 탭·계약 문서에서 쓰는 "파일 금고"와 이름이 다르다
4. **업무를 열면 맥락이 가려진다.** 업무 수정이 화면 가운데 모달이라 보드·제출물이 가려진다. 제출물 상세에서 연결 업무를 고치면 요구사항 목록이 안 보인다
5. **업무를 보드로만 본다.** 마감순·담당자순으로 훑어볼 목록이 없다
6. **마감 표시가 화면마다 다르다.** 날짜, D-n, "기한 N일 지남"이 섞여 있다
7. **일정을 한눈에 볼 수 없다.** 제출물 기한과 업무 마감을 함께 보는 화면이 없다

## 5. 개선안

| # | 개선 | Flow 참고점 | Blackbox 적용 | 서버 | 시기 |
| --- | --- | --- | --- | --- | --- |
| 1 | 사이드바 프로젝트 전환 | 왼쪽 프로젝트 목록 | 사이드바 맨 위에 지금 프로젝트 이름과 전환 목록(내 프로젝트만). 업무 보드 머리의 드롭다운과 같은 동작 | 기존 `GET /projects` | 1차 |
| 2 | 메뉴 묶기·이름 맞추기 | 메뉴를 용도별로 묶음 | "진행"(프로젝트 홈·제출물·업무 보드) / "함께"(회의록·일정 조율) / "기록"(파일 금고·기여도) / 설정. "Hash Vault" → "파일 금고" | 없음 | 1차 |
| 3 | 대시보드 "내 업무" | 모아보기 | 대시보드 위쪽에 모든 프로젝트에서 나에게 배정된 미완료 업무를 "기한 지남 / 오늘 / 이번 주 / 나중"으로. 업무마다 프로젝트·제출물 이름과 보드 링크(`board?task=`) | 1차는 프로젝트마다 `GET /tasks`를 불러 합침(학생 프로젝트 수가 적음). 느리면 B에 `/me/tasks` 요청 | 1차 |
| 4 | 마감 표시 통일 | 업무 마감일 강조 | 모든 화면을 같은 함수로: 오늘 마감, D-n, "N일 지남"(빨강). #77의 `dueLabel`을 공통으로 옮김 | 없음 | 1차 |
| 5 | 업무 상세를 옆 패널로 | 게시물 상세를 옆에서 열기 | 넓은 화면에서는 업무 수정을 오른쪽 패널로 열어 보드·제출물이 보이게. 작은 화면은 전체 화면 | 없음 | 2차 |
| 6 | 업무 목록 보기 | 업무 목록·필터 | 업무 보드에 "보드 / 목록" 전환. 목록은 제목·상태·담당자·마감·제출물·요구사항 열, 정렬·필터는 보드와 공유 | 없음 | 2차 |
| 7 | 제출물 일정 보기 | 간트차트·캘린더 | 제출물 기한과 연결 업무 마감을 한 줄씩 보는 읽기 전용 타임라인. 업무에 시작일이 없어 막대 대신 점(마감)으로. 끌어서 일정 바꾸기는 하지 않음 | 없음(시작일을 넣으려면 B 계약) | 2차 |
| 8 | 알림 종류 넓히기 | 나를 지정한 글 알림 | 지금 알림은 기여도 경보뿐이다. "업무가 나에게 배정됨", "검토 요청됨", "피드백이 달림", "수정 요청 받음"을 알림 벨에 | A·B 알림 API 필요 | 3차 |
| 9 | 프로젝트 홈 최근 활동 | 피드 | 피드 대신 "최근 활동" 짧은 목록(업무 완료, 회차 열림, 승인 등). 서버 활동 기록(`ActivityLogService`)을 읽는 API가 있어야 함 | A·B 조회 API 필요 | 3차 |

- 1차: 서버 변경 없이 화면만. 중간 데모(10/18) 뒤 바로 시작해도 핵심 흐름(C-20·C-30) 일정을 밀지 않는 크기다
- 2차: 6주차(모바일·중간발표) 범위와 함께
- 3차: 서버 계약이 생기면. 생기지 않으면 하지 않는다
- 시간이 모자라면 개발 계획 6장 순서대로 3차 → 2차 순으로 뺀다. 핵심 흐름과 C-30이 먼저다

## 6. 서버에 바라는 것 (A·B, 계약 PR로 따로)

이 문서는 화면 제안이고 서버 파일은 바꾸지 않는다. 아래는 필요해지면 해당 담당에게 계약으로 요청한다.

- B: 여러 프로젝트에서 나에게 배정된 업무 목록(`/me/tasks` 등). 3번이 프로젝트마다 불러 합치는 방식으로 느릴 때만
- A·B: 알림 종류 추가(8번). 배정·검토 요청·피드백·수정 요청
- A·B: 프로젝트 활동 기록 조회(9번)
- B: 업무 "보류" 상태와 시작일은 이번에는 요청하지 않는다(3장)
