## 목표

실제 모델(Bedrock)로 테스트용 프로젝트에서 요구사항 찾기·계획 만들기·업무 나누기·상태 요약·질문 답변이 지시문을 준수하는지 확인한다. 특히 요구사항 찾기가 제출물 기한과 검토 대기 카드를 다시 제안하지 않는지, 점수 도구가 출력하지 않기로 한 `period`를 근거로 쓰지 않는지 본다.

## 실행 환경

- 모델: Bedrock `bedrock-haiku`(OpenAI 호환 API, `SPRING_AI_MODEL_CHAT=openai`)
- 자료: 테스트가 만드는 합성 프로젝트(실제 팀 기록 없음). 실행 후 테스트가 지운다
- DB: 검사용 DB(25432)의 임시 DB. 실행 후 삭제
- 키는 `.env`에서 읽어 환경 변수로만 넘기고 출력하지 않았다

## 발견과 수정

- `AgentQuestionSetLiveTest`가 모델을 부르기 전에 실패했다. 테스트 자료 도우미 `AgentTestData.task`가 완료(`DONE`) 업무를 승인 기록 없이 넣어, V35의 `task_done_requires_approval` 트리거에 거절되었다. 이 테스트는 API 키가 있을 때만 실행되어 CI에서 드러나지 않았다. 끝난 업무는 새 `AgentTestData.doneTask`로만 만들고 승인자를 명시해 받도록 고쳤다. 승인자는 실제 서비스 규칙(`TaskWorkflowService.independentReviewer`)과 같게 업무를 만든 사람·담당자와 달라야 하며, `task`로 끝난 업무를 만들면 거절한다. 처음에는 만든 사람을 승인자로 넣었는데, 서비스는 만든 사람·담당자·요청자의 승인을 거절하므로 서비스로는 만들 수 없는 자료였다(#209 B 리뷰). 이 검사는 키 없이 도는 `AgentTestDataTest`로 둔다
- `RequirementGapsLiveTest`에 G10(제출 기한을 요구사항으로 만들지 않음)을 추가했다. #185에서 고친 문제의 회귀를 실제 모델로 확인하는 항목이다

## 수행하지 않은 것

- `AgentModelLiveTest`(Gemini 전용, `SPRING_AI_GOOGLE_GENAI_API_KEY` 필요)는 실행하지 않았다. 운영은 Bedrock을 쓴다
- 실제 모델의 답은 실행마다 달라질 수 있어, 이번 통과가 다음 실행의 통과를 보장하지 않는다
