## 변경

1. 요청자의 쓰기 권한 오류는 기존 403을 유지한다. 관찰자 후보는 400 “관찰자는 업무 담당자로 지정할 수 없습니다”, 프로젝트 비회원 후보는 400 “프로젝트의 팀장·팀원만 담당자로 지정할 수 있습니다”. 없는 사용자 ID는 기존 404를 유지한다. 후보를 모두 검사한 뒤 기존 배정을 삭제한다.
2. 업무 목록은 단일 연관을 EntityGraph로 가져오고 담당자·사용자를 한 번에 읽는다. 여러 담당자 때문에 업무가 중복되거나 미배정 업무가 빠지지 않도록 응답을 업무별로 묶는다. 필터·정렬·프로젝트 권한은 유지한다.
3. 생성 시 완료 기준을 수정과 같은 trim 규칙으로 저장한다. null은 null, 공백만 있는 문자열은 빈 문자열이다. 기존 레코드는 수정하지 않는다.

## 계약 영향

URL·DTO 필드는 동일하다. 후보 자격 오류의 403→400은 C에게 확인을 요청한다. 사용자 권한 오류와 구별하는 B-13 계획을 구현한 것으로, 공개 오류 변화는 PR 본문에 기록한다. K-10/K-11/K-12와 독립 작업이며 승인/확정 경계를 구현했다고 표현하지 않는다.

## 완료 검사

- 실제 ProjectAccessChecker와 mock 저장소로 요청자 관찰자/비회원 거절, 후보 자격 오류, 중복 배정, 후보 실패 시 기존 배정 삭제 미호출을 확인한다.
- 업무 목록의 복수 담당자·미배정·상태 필터·관찰자 조회·빈 목록을 확인한다.
- PostgreSQL에서 쿼리 수와 지연 로딩, 인증 HTTP의 400/403 및 C 화면의 detail 안내는 별도 실행 증거가 필요하다.
