## 촬영 전 역할과 데이터

| 역할 | 예시 이름 | 맡은 일 | 촬영 중 조작 |
| --- | --- | --- | --- |
| A · 팀장 | 민지 | 일정·최종 보고서 통합 | 업무 배정, B 결과 확인, 최종본 확정 |
| B · 팀원 | 현우 | 현장 조사 | 결과 등록, 의견 답변, 수정, 완료 확인 요청 |
| C · 팀원 | 유나 | 자료 분석·최종 파일 검토 | 최종본에 피드백, 수정본 검토 승인 |
| D · 팀원 | 지호 | 발표 슬라이드 | 자신의 업무를 가진 상태로 목록에 표시 |

관찰자는 선택 장면이다. 읽기 전용 권한 설명이 필요할 때만 별도 세션으로 보여준다. 4인 중 관찰자를 넣어 팀원 수를 줄이지 않는다.

- 프로젝트: ‘지역 상권 분석 · 촬영용 합성’. 최종 제출물: ‘상권 분석 보고서’.
- B 업무 ‘현장 조사 정리’: 완료 기준 ‘조사 대상 3곳 비교와 출처 포함’. 담당자는 B만 지정해 A가 확인할 수 있게 한다.
- A/C/D 업무는 사전 준비한 상태로 두고 B의 결과를 핵심 이야기로 보여준다. 최종 확정에 필요한 연결 업무·필수 조건은 촬영 전에 충족 가능 상태로 점검한다.
- 파일 준비: 현장조사.txt v1/v2, 상권분석_보고서.txt v1/v2. 버전을 보여주려면 같은 파일명을 유지하고 **내용을 변경**해 올린다. 확장자·용량은 실제 업로드 제한 안에서 준비한다.
- 비밀값 없이 합성 자료만 사용한다. .env·토큰·비밀번호 입력창·개인 이메일은 화면 녹화에서 제외한다.
- A/B/C는 별도 브라우저 프로필/세션으로 준비한다. 같은 세션의 탭 여러 개는 계정을 분리하지 않는다. 시작 전 현재 계정 이름을 확인한다.
- 기존 프로젝트를 초기화하거나 기록을 지우지 않는다. 반복 촬영은 별도 합성 프로젝트 또는 아직 실행하지 않은 업무/회차를 준비한다. 확정·제출은 마지막에 실행한다.
- verify-expo-flow.cjs는 데모 계정 파일을 덮어쓰므로 촬영 준비 목적으로 실행하지 않는다.

S03에서 제안을 적용하면 중복 최종 제출물이 생길 수 있다. **AI 장면은 별도 ‘AI 계획 시연’ 합성 프로젝트**로 촬영한 뒤 핵심 4인 프로젝트로 돌아오거나, 적용할 항목을 사전에 정한다. AI 생성 업무에는 담당자·기한·완료 기준을 사람이 확인한다.

S07/S09는 멀티 계정 전환과 폴링을 포함하므로 편집 영상에서는 기다리는 부분을 줄일 수 있다. 현장 시연은 8~10분을 확보한다. 모든 장면을 한 번에 처음부터 생성하려 하지 말고 다음 장면에 필요한 상태를 사전에 준비한다.

특정 팀원에게만 의견을 구하는 기능은 추가 장면으로 보여줄 수 있다. ‘팀원에게 의견 요청’에서 수신자를 선택하고, 해당 팀원이 **그 요청의 ‘답변·수정 내용 남기기’**로 답하면 응답 완료가 된다. 일반 댓글을 새로 등록하는 것만으로 지정 요청이 응답 완료되지는 않는다.

## 화면별 개략 배치

```text
팀 업무                         업무 상세
┌────────┬─────────────────┐  ┌────────────────────────┐
│ 알림   │ 목록 / 칸반     │  │ 현장 조사 정리 · B 담당  │
│ 최종물 │ 내 업무 / 전체  │  │ 기준: 비교표와 출처      │
│ 팀업무 │ 제목 담당 마감  │→ │ 업무 결과 올리기 · v2    │
│ 피드백 │ 조사 B  내일    │  │ 대화·피드백 → 답변       │
└────────┴─────────────────┘  │ 등록한 결과 확인 요청    │
                              └────────────────────────┘

알림 → 피드백 원문 → 수정 파일·답변 → 작성자에게 알림
                                  ↓
최종 제출물 → 검토 회차·피드백 → 다른 팀원 승인
                                  ↓
                  팀장 확정 → 학교 직접 제출 → 제출 기록
```

개략도는 메뉴·기능의 관계를 보여주는 설명용이다. 실제 픽셀 배치나 모든 버튼을 복제한 화면이 아니다.

## 바로 읽는 40초 소개 대본

“Team Blackbox는 대학생이 팀 과제를 진행하며 결과와 기여 기록을 함께 남기는 PMS입니다. Flow의 목록·담당자 보기와 알림 흐름을 참고해, 팀원은 내 업무부터 확인하도록 구성했습니다. 결과 파일과 피드백은 업무 안에서 연결되고, 수정한 내용이 올라오면 원 작성자도 알림을 받습니다. 다른 팀원의 확인으로 업무를 마친 다음, 최종 파일은 다시 검토하고 팀장이 버전을 확정합니다. 학교 제출은 직접 진행하고 제출 사실을 기록합니다. 이 과정에서 남는 파일 버전과 활동 기록을 팀 기여도를 설명하는 근거로 활용할 수 있습니다.”
