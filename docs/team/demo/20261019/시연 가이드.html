Flow 벤치마킹과 Team Blackbox 적용

공유·발표용 / 2026-10-19 / shinguexpo cdae9636

발표에서 전달할 핵심

Flow의 업무 목록·담당자 중심 보기와 알림에서 원문으로 돌아가는 사용 방식을 참고했습니다. Team Blackbox에서는 이를 대학생 팀 과제에 맞춰, 내 업무에서 결과 파일과 피드백을 처리하고 최종 제출물의 검토·확정·제출 기록까지 이어지도록 구성했습니다. 팀원이 평소처럼 업무를 진행하면 담당·파일 버전·답변·확인 기록이 함께 쌓입니다.

Flow의 기능이 부족하다고 주장하는 비교가 아니다. 참고한 패턴과 우리 제품의 적용 목적을 설명한다. Flow에도 AI 기능이 있으므로 “Flow에는 AI가 없고 우리만 있다”는 설명은 하지 않는다.

3. 업무·최종 제출물 피드백 연결

업무: 팀원 B가 결과 파일 등록 → A가 업무에 피드백 → B가 알림에서 원문 확인 → B가 수정 버전 등록·답변 → A가 새 파일/답변 알림 확인 → B가 결과 확인 요청 → 담당자·요청자가 아닌 팀원이 확인.

일반 댓글은 본인·관찰자를 제외한 현재 팀장·팀원에게 알린다. 특정인에게만 의견을 구할 때는 ‘팀원에게 의견 요청’을 쓴다. 답변한 요청도 피드백함에서 사라지지 않는다. 댓글 답변이 업무 완료를 자동 승인하지 않는다.

최종 제출물: 검토 피드백 → 담당자·검토 파일 업로더 알림(둘 다 없으면 회차 개설자) → 수정 후 해결 사유 기록·새 검토 버전 → 원 피드백 작성자 알림 → 다른 팀원이 검토 승인 → 팀장 확정 → 학교에 직접 제출한 사실 기록.

자료실에만 올린 파일을 최종 제출물 수정으로 자동 추정하지 않는다. 새 검토 버전에 파일을 지정한다. ‘해결’ 기록과 최종 검토 승인은 별개다.

4. 이번 발표에서 구현 완료로 말하지 않을 것

• Flow의 커스텀 상태·다단계 하위업무·간트 편집·기업용 그룹웨어 전체를 재현한 제품.

• Slack식 채팅·화상회의 자동 업무 연결, Clova Note식 녹음 수집, 구글 연동 이메일 알림: 이후 검토 범위.

• 기한 초과에 따른 새로운 자동 기여도 감점 산식: 적용 완료로 설명하지 않는다.

• 사이트 알림을 휴대폰 OS 푸시·이메일 알림이라고 설명하지 않는다. 개인 알림은 활성 화면에서 약 10초, 피드백 목록은 약 30초 주기로 갱신하며 수동 새로고침도 있다.

• 학교 LMS 자동 제출 또는 학교의 접수 확인을 보증하는 서비스.

• 모든 화면의 실기기 모바일 검증·공개 서버 최신 배포 완료. 로컬·에뮬레이션·공개 환경의 검증을 구분한다.

관찰자는 선택 장면이다. 읽기 전용 권한 설명이 필요할 때만 별도 세션으로 보여준다. 4인 중 관찰자를 넣어 팀원 수를 줄이지 않는다.

• 프로젝트: ‘지역 상권 분석 · 촬영용 합성’. 최종 제출물: ‘상권 분석 보고서’.

• B 업무 ‘현장 조사 정리’: 완료 기준 ‘조사 대상 3곳 비교와 출처 포함’. 담당자는 B만 지정해 A가 확인할 수 있게 한다.

• A/C/D 업무는 사전 준비한 상태로 두고 B의 결과를 핵심 이야기로 보여준다. 최종 확정에 필요한 연결 업무·필수 조건은 촬영 전에 충족 가능 상태로 점검한다.

• 파일 준비: 현장조사.txt v1/v2, 상권분석_보고서.txt v1/v2. 버전을 보여주려면 같은 파일명을 유지하고 내용을 변경해 올린다. 확장자·용량은 실제 업로드 제한 안에서 준비한다.

• 비밀값 없이 합성 자료만 사용한다. .env·토큰·비밀번호 입력창·개인 이메일은 화면 녹화에서 제외한다.

S03에서 제안을 적용하면 중복 최종 제출물이 생길 수 있다. AI 장면은 별도 ‘AI 계획 시연’ 합성 프로젝트로 촬영한 뒤 핵심 4인 프로젝트로 돌아오거나, 적용할 항목을 사전에 정한다. AI 생성 업무에는 담당자·기한·완료 기준을 사람이 확인한다.

S07/S09는 멀티 계정 전환과 폴링을 포함하므로 편집 영상에서는 기다리는 부분을 줄일 수 있다. 현장 시연은 8~10분을 확보한다. 모든 장면을 한 번에 처음부터 생성하려 하지 말고 다음 장면에 필요한 상태를 사전에 준비한다.

특정 팀원에게만 의견을 구하는 기능은 추가 장면으로 보여줄 수 있다. ‘팀원에게 의견 요청’에서 수신자를 선택하고, 해당 팀원이 그 요청의 ‘답변·수정 내용 남기기’로 답하면 응답 완료가 된다. 일반 댓글을 새로 등록하는 것만으로 지정 요청이 응답 완료되지는 않는다.
