# Team Blackbox 엑스포 영상 — 스토리보드·자막 검토본

작성일: 2026-10-19

원본 `storyboard.md`의 약 5분 구성을 유지하면서 문장과 자막을 다듬었다. 아래 자막표는 편집에 바로 사용할 문장이다. 촬영·편집 메모는 영상에 표시하지 않는다. 원본에 적힌 리허설 결과는 이번 문서 검토로 재검증한 것이 아니며, 공개 서버 반영 여부는 촬영 전에 별도로 확인한다.

## 1. 영상의 중심 문장

**팀플을 진행하는 동안, 누가 무엇을 했는지도 함께 남습니다.**

다음 세 가지를 한 팀의 이야기로 보여준다.

1. 과제 안내문에서 AI가 계획 초안을 제안하고, 팀이 확인해 적용한다.
2. 업무 안에서 결과와 피드백을 주고받고, 다른 팀원의 확인으로 업무를 마친다.
3. 파일과 활동 기록을 모아 팀의 기여 과정을 설명한다.

기능을 나열하기보다 ‘과제 시작 → 업무 진행 → 피드백 → 최종본 확정 → 기록 확인’ 순서로 보여준다. 전시 영상을 중간부터 보는 관람객도 이해할 수 있도록 장면 제목을 짧게 표시한다.

## 2. 상영·편집 기준

- 약 5분, 소리 없이 봐도 이해되는 자막 중심 영상. 내레이션과 배경음악은 선택이다.
- PC 화면은 1920×1080 기준. 중요한 버튼과 글자가 읽히도록 장면별로 확대한다.
- 자막은 한 번에 두 줄까지. 아래 표의 ‘첫째 줄’과 ‘둘째 줄’을 그대로 줄바꿈한다. 둘째 줄이 비어 있으면 한 줄로 표시한다.
- 핵심 자막은 최소 4초, 설명이 두 줄이면 5~7초를 권장한다. 아래 시간은 5분 편집안이며 실제 촬영 길이에 맞춰 조정한다.
- 하단 자막 영역이 파일명·버튼·알림 내용을 가리지 않도록 화면을 배치한다. 배경 위에 반투명 검정 띠를 사용하고 흰 글자로 표시한다.
- 계정 전환은 로그인 과정을 반복해서 보여주기보다 ‘지호 · 결과 등록’, ‘현우 · 결과 확인’처럼 짧게 표시한다. 비밀번호·토큰·개인 이메일은 녹화하지 않는다.
- AI 응답과 알림 갱신을 기다리는 구간은 줄여 편집한다. 실제보다 즉시 응답한 것처럼 오해할 수 있는 장면에는 ‘응답 대기 시간 단축’ 또는 ‘대기 구간 편집’을 작게 표시한다.
- 실제 학교 제출이나 학생 평가를 수행한 것처럼 보이지 않게 한다. 예시 계정·과제·파일을 사용한다.

## 5. 촬영할 이야기와 자료

### 프로젝트와 역할

촬영용 프로젝트: **캡스톤 디자인 — 캠퍼스 분실물 찾기 앱 ‘찾아줘’**

| 이름 | 프로젝트 역할 | 보여줄 행동 |
| --- | --- | --- |
| 김민지 | 팀장 | 제출물·업무 확인, 검토된 파일의 최종본 확정 |
| 최현우 | 팀원 · API | 내 업무 확인, 의견 요청과 답변, 지호의 결과 확인 |
| 박유나 | 팀원 · 화면 설계 | 준비된 업무·파일 기록에 참여자로 표시 |
| 이지호 | 팀원 · DB | ERD 결과 등록, 확인 요청 |
| 지도교수 예시 계정 | 관찰자 | 필요한 경우에만 읽기 화면을 별도 촬영 |

모두 합성 이름·자료를 사용한다. 관찰자는 4인 팀의 기여도 집계에 포함시키지 않는다. 실제 팀원이 참여하지 않은 행동을 이름만 붙여 촬영하지 않는다.

### 장면 시작 전 준비할 상태

- 최종 제출물은 ‘요구사항 정의서’, ‘중간 발표 자료’, ‘설계 문서’ 세 개를 준비한다. 이전 제출 예시는 실제 제출 기록과 혼동되지 않게 표시한다.
- AI 장면에서는 ‘최종 결과 보고서’ 계획을 제안받는다. 이미 같은 제출물이 있으면 중복 적용하지 않는다.
- ‘DB 설계(ERD)’ 담당자는 지호로 둔다. 확인할 현우를 담당자로 함께 지정하지 않는다.
- ERD 결과 확인 장면은 요청 전후를 따로 촬영하거나, 요청을 보내기 전 상태의 별도 촬영용 업무를 준비한다.
- 최현우의 ‘API 명세 작성’에는 의견 요청·답변과 수정 파일을 준비한다. 수정 내용은 해당 원문에 답변으로 연결한다.
- 최종 제출물 ‘설계 문서’는 검토 중 상태에서 시작한다. 피드백을 보완한 뒤 **현재 파일 버전**에 대한 승인을 받아 최종 확정한다.
- 파일 버전 장면은 같은 파일명의 내용이 달라진 v1·v2를 사용한다. 버전 번호와 업로드 시각이 읽히도록 확대한다.
- PDF는 실제 촬영 대상 프로젝트에서 다시 내려받는다. 팀원 수·활동 내용·최종 파일과 화면 속 프로젝트가 일치해야 한다.
- ‘4주간의 실제 사용’ 같은 문구는 넣지 않는다. 기간을 설정한 합성 예시와 실제 사용 이력은 구분한다.
- 반복 촬영은 별도 합성 프로젝트나 아직 처리하지 않은 업무를 사용한다. 촬영을 위해 기존 기록·파일 시각을 바꾸거나 DB 보호 장치를 해제하지 않는다.

### AI에 넣을 과제 안내문

```text
캡스톤 디자인 최종 결과 보고서 제출 안내

제출 기한: 12월 12일 23:59
제출 경로: 학교 LMS 과제함
파일 형식: PDF
분량: 표지와 목차를 제외하고 15쪽 내외

반드시 포함할 내용
- 개발 배경과 목표
- 시스템 구조도
- 주요 기능 화면
- 사용자 5명 이상의 테스트 결과
- 팀원별 역할과 기여 내용

추가 권장 내용
- 향후 개선 계획
- 참고 문헌

3분 이내의 시연 영상 링크를 보고서에 포함해 주세요.
```

이 문장은 촬영용 합성 과제다. 학교가 실제로 공지한 안내문이라고 소개하지 않는다. 날짜는 촬영·상영일과 맞는 연도로 설정한다.

## 7. 기능 설명에서 지킬 표현

- **업무 확인 요청:** 담당자 등이 팀원에게 결과 확인을 요청하고 앱 안의 알림으로 연결된다. 완료 기준 텍스트는 선택이다. ‘파일 필수’ 설정이나 선행 업무·권한 조건이 있으면 별도로 충족해야 한다.
- **의견 요청과 완료 확인:** 중간 피드백이 필요할 때는 의견 요청·대화, 업무를 마칠 준비가 됐을 때는 결과 확인 요청을 보여준다. 결과 확인 요청을 누르는 즉시 업무가 완료되는 것처럼 편집하지 않는다.
- **알림:** 사이트 안의 알림이다. 휴대폰 푸시나 이메일 도착 장면으로 표현하지 않는다. 수정 답변은 피드백 원문에 연결하고, 수신 계정에서 실제 알림을 확인한다.
- **최종 제출물:** 업무 완료, 파일 검토 승인, 팀장의 최종본 확정, 학교에 직접 제출한 뒤의 기록을 서로 구분한다.
- **파일 해시:** 파일 내용이 일치하는지 비교하는 근거다. 해시만으로 내용의 진위나 작성자를 입증하거나 파일 변경을 막는다고 말하지 않는다.
- **기여 기록:** 누가 어떤 활동을 했는지 설명하는 근거다. 자동 성적 산정, 성실성 판정, 무임승차 탐지의 확정 결과로 소개하지 않는다.
- **교수자 화면:** 현재 프로젝트의 관찰자 권한과 회원가입의 계정 유형은 별개다. 교수자 전용 가입·평가 화면이 구현된 것처럼 말하지 않는다.
- **학교·학과:** 이번 5분 영상의 핵심 흐름에서는 생략한다. 추가할 경우 실제 촬영 서버 반영 후 촬영하며, 공식 목록 선택과 직접 입력이 재학 인증을 뜻하지 않도록 설명한다.
- **Flow 참고:** 관람객용 자막에는 다른 서비스와의 비교를 넣지 않는다. 팀 내부 설명이 필요하면 ‘목록·담당자 보기와 알림 흐름을 참고했다’고 구체적으로 설명한다.

## 8. QR과 마지막 화면

### QR을 넣을 경우

목적지 후보: **https://team-blackbox.duckdns.org/**

최종 편집 전에 실제 공개 주소에서 접속·로그인·화면 동작을 확인하고, 휴대폰 모바일 데이터로 QR을 스캔한다. 체험 계정과 이용 안내가 준비되어 있어야 한다. 로컬 주소 `127.0.0.3`은 QR에 사용하지 않는다.

QR은 별도 안내 글자가 읽힐 정도로 크게 두고 마지막 10초간 고정한다. PDF나 화면 메뉴 위에 겹쳐 넣지 않는다.

### 공개 체험 준비가 안 된 경우의 대체 자막

마지막 두 줄을 다음으로 바꾸고 QR은 빼 둔다.

```text
Team Blackbox
부스에서 직접 체험해 보세요
```

휴대폰 장면을 빼면 해당 20초를 업무 피드백과 PDF 장면에 각각 10초씩 배분한다. 주요 내용을 보태기 위해 새 기능 설명을 늘리지 않는다.

## 9. 촬영·최종 검수 체크

- [ ] 촬영할 공개 서버가 필요한 수정본인지 실제 화면으로 확인했다.
- [ ] AI 장면은 실제 응답이며 팀이 제안을 확인하고 적용하는 과정이 보인다.
- [ ] 담당자·요청자와 결과 확인자가 구분되고, 확인자가 해당 업무의 담당자가 아니다.
- [ ] 의견 요청, 수정 답변, 알림의 수신 계정이 맞는다.
- [ ] 완료 기준을 필수 입력으로 설명하지 않는다.
- [ ] 파일 필수 설정이 없는 업무까지 “파일을 올려야 한다”고 설명하지 않는다.
- [ ] 최종 파일의 버전과 검토·승인·확정 대상이 일치한다.
- [ ] 제출 기록 예시에 ‘실제 학교 제출 아님’을 표시했다.
- [ ] PDF가 최신 형식이며 교수자에게 보여줄 팀원별 활동 근거가 읽힌다.
- [ ] 합성 계정·과제임을 표시했고 개인정보·비밀값이 보이지 않는다.
- [ ] 무음으로 처음부터 재생해도 자막만으로 흐름을 이해할 수 있다.
- [ ] 빠른 계정 전환이나 작은 글씨 때문에 누가 무엇을 했는지 놓치지 않는다.
- [ ] 기다리는 구간을 편집했다면 그 사실이 필요한 장면에 표시돼 있다.
- [ ] QR을 실제 휴대폰에서 확인했거나, 준비되지 않았다면 대체 끝 화면을 사용했다.
- [ ] 마지막 화면에서 첫 질문으로 반복 재생해도 화면·음량 전환이 어색하지 않다.

검토 상태: 문장·기능 설명·자막 구성 검토 완료. 녹화본·공개 서버·QR 실기기 검수는 이 문서 작성 범위에 포함하지 않았다.
