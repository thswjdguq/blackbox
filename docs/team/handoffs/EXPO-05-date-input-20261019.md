# EXPO-05 잘못된 날짜 입력 안내

- 사용자 신고: 새 업무 생성 안 됨. 추가 확인에서 112122 같은 날짜 입력을 원인으로 지목했다.
- 기존 SmartDateInput은 네 자리 연도·월·일이 채워지면 22월 등도 문자열로 내보냈다. 실제 달력 검사와 폼 제출 전 오류 표시가 없어 생성 실패를 이해하기 어려웠다.
- 공통 입력 컴포넌트에 연도 형식, 1~12월, 월별 일수·윤년, 날짜 일부만 입력, 시간 범위 검사를 추가했다. 입력 아래 오류 안내와 브라우저 폼 유효성 검사로 잘못된 날짜 제출을 막는다. 유효한 값으로 고치면 정상화되고 선택 날짜를 전부 지우면 다시 기한 없이 생성할 수 있다.
- 기존 유효 날짜를 잘못 고친 경우 이전 값이 조용히 제출되지 않게 customValidity도 갱신한다. 입력 중 잘못된 값은 API용 값으로 내보내지 않는다.
- npx tsc --noEmit, verify-task-workflow.cjs, verify-date-input.cjs 통과. 날짜 검사는 윤년, 월별 말일, 불완전 입력, 시·분 범위, 오류 표시·전송 차단, 수정·전체 지우기 복구를 포함한다.
- 현재 세션의 browser 도구는 사용 가능한 브라우저가 없고 iab 생성도 불가능해 실제 브라우저 클릭 검사는 수행하지 못했다. 컴포넌트 이벤트·유효성 연동을 테스트했다.
- 기존 footer·프로젝트 삭제·업무 수정 변경을 보존했다. API·DB 변경, 신규 push/merge/배포 없음.
- webpack 프로덕션 빌드 통과 후 http://127.0.0.3:13000 로컬 화면에 반영했다.
