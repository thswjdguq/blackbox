## 1. 사용자 경로와 막히는 지점

경로: 프로젝트 홈 → 제출물 → 요구사항 → 업무 보드

main(1단계 `fbbb3cb`)의 제출물 화면은 목록과 상세를 한 페이지에 두고, 요구사항 추가·수정·삭제, 요구사항별 업무 만들기, 미연결 업무 연결까지 갖추고 있다. #53은 이를 목록·상세 두 페이지로 나눈다.

| 이동 | main | #53 반영 후 | 남은 문제 |
| --- | --- | --- | --- |
| 프로젝트 홈 → 제출물 | 홈의 "제출물부터 계획하기" 카드 | 동일 | 없음 |
| 제출물 목록 → 상세 | 같은 페이지 왼쪽 목록에서 선택 | 카드 클릭으로 상세 페이지 | 없음 |
| 상세 → 목록·프로젝트 홈 | 상단 프로젝트 홈 링크 | 상세 상단 "제출물 목록", 목록 상단 프로젝트 홈 | 없음 |
| 요구사항 → 업무 만들기 | "이 요구사항의 업무 만들기" | 동일 (상세) | 없음 |
| 제출물 → 기존 업무 연결 | 미연결 업무 선택 후 연결 | 동일 (상세) | 없음 |
| 연결 업무 → 보드의 해당 업무 | `board?task=<id>` | 동일 | 없음 |
| 제출물 → 이 제출물 업무만 보이는 보드 | 없음 | `board?deliverable=<id>` | 보드의 처리는 C-01 브랜치에 있음. 병합 전에는 전체 보드가 열림 |
| 업무 보드 → 제출물 | 보드 상단 "제출물·요구사항 관리" | 동일 | 목록으로만 이동 |

점검 중 발견해 고친 막힘: 상세에서 목록으로 돌아가는 경로, 진척 조회 실패 시 재시도, 보드를 제출물 필터로 여는 경로.

## 3. 화면별 상태표

| 화면 | 로딩 | 0건 | 권한 없음 (관찰자) | 저장 실패 | 재시도 | 저장 성공 |
| --- | --- | --- | --- | --- | --- | --- |
| 제출물 목록 | 카드 skeleton | "첫 제출물을 등록하세요" + 예시. 관찰자는 "팀원이 등록하면 확인" | 추가·삭제 버튼 숨김 | 등록: 창 안에 서버 detail / 삭제: 확인 창 안에 409 또는 detail | 목록 오류 시 다시 시도 | 성공 안내 + 재조회 |
| 제출물 상세 | 스피너 | 요구사항 예시 문구 / "필요한 업무를 추가하거나 기존 업무를 연결하세요" | 수정·삭제·추가·연결 숨김, 충족 체크 비활성 | 요구사항: 폼 안 / 삭제: 확인 창 안 / 충족 확인: 해당 항목 원복 + 안내 / 연결: 상단 안내 | 페이지 오류 다시 시도 | 성공 안내 + 진척 재조회 |
| 진척 현황 | (상세와 함께) | 업무 0 → "연결 업무 없음", 필수 0 → "필수 요구사항 없음" (0% 아님) | 조회 가능 | 조회 실패 시 가짜 0% 대신 오류 | 다시 시도 버튼 | 재조회 성공 시 오류 해제 |
| 멤버 관리 (설정) | 줄 skeleton | 해당 없음 (본인 최소 1명) | 팀장 아님: 역할 뱃지 + "팀장만 가능" 안내 | 서버 detail 안내 (예: 마지막 팀장) | 목록 오류 시 다시 시도 | 역할 즉시 반영 / 내보낸 멤버 제거 / 나가기 후 대시보드 |
| 업무 보드 | (기존) | (기존) | **역할 구분 없음.** 관찰자에게도 쓰기 버튼이 보이고 서버 거절 안내만 뜸 | 상단 오류 문구 | 없음 | — |

알려진 부족한 점:

- 제출물 목록·상세의 불러오기 실패는 403·404·500을 같은 방식으로 보여준다 (서버 detail 이 있으면 그 문구). 단건 조회 404 처리는 A-05(#56) 병합 후 적용한다.
- 업무 보드의 관찰자 읽기 전용은 C-01 후속 항목이다.
- 비회원이 URL로 직접 들어온 경우의 화면은 브라우저로 확인하지 않았다.

## 4. 멤버 관리 API 연결

| API | 서버 코드 | 화면 연결 | 실제 동작 확인 |
| --- | --- | --- | --- |
| `GET /projects/{id}/members` | 있음 (`ProjectController.listMembers`) | 설정 > 멤버 목록, 프로젝트 홈 아바타, 제출 담당자·업무 담당자 후보 | 미확인 |
| `PATCH .../members/{memberId}/role` | 있음, 팀장만, 마지막 팀장 강등 403 | 설정 > 역할 선택 (팀장에게만). 마지막 팀장은 강등 옵션 비활성 | 미확인 |
| `DELETE .../members/{memberId}` | 있음, 팀장만, 자기 자신 403 | 설정 > 내보내기 (확인 후). 본인 행에는 버튼 없음 | 미확인 |
| `DELETE .../members/me` | 있음, 혼자 남은 팀장 403 | 설정 > 프로젝트 나가기 (확인 후 대시보드). 혼자 남은 팀장은 버튼 비활성 + 이유 안내 | 미확인 |

"미확인"은 코드가 없다는 뜻이 아니라 실제 서버에 요청해 보지 않았다는 뜻이다.
