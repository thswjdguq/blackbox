# EXPO-01 로그인·용어·실제 AI 검증

## 기준과 변경

- 저장소: teamplay-ui, shinguexpo, 기준 커밋 1eb57b2c.
- 로그인에 제품 소개와 명시적인 프로젝트 예시를 추가했다. PC는 소개/로그인 두 영역, 모바일은 간결한 소개를 사용한다. 기존 로그인 처리와 비밀번호 표시 기능은 유지했다.
- 메뉴와 관련 문구를 최종 제출물, 팀 업무, 피드백, 알림, 파일 모아보기, 활동·기여 기록으로 정리했다. 업무 파일 등록은 업무 결과 올리기로 구분했다. API 경로나 DB 계약은 변경하지 않았다.
- start-local-expo.ps1에 -EnableAi 옵션을 추가했다. .env에서 AI 관련 키만 읽으며 비밀값을 출력하지 않는다. 이미 실행 중인 백엔드는 자동 재시작하지 않는다.
- 10/18 검증 당시에는 로컬 미커밋 상태였다. 10/19 사용자가 현재 검증본의 shinguexpo 업로드를 명시적으로 요청해 소스·작업 문서를 커밋/push하는 범위로 진행한다. AWS 배포는 포함하지 않는다.

## 검증

- 프론트 타입 검사와 기존 회귀 스크립트 7개 통과.
- Windows webpack 프로덕션 빌드 통과. 최종 모바일 문구 수정 후 재빌드도 통과.
- 실제 Chrome에서 PC/390px 로그인 화면, 잘못된 비밀번호 오류와 입력 유지, 정상 로그인 및 메뉴 용어를 확인했다. 최종 모바일 화면도 다시 확인했다. 실제 휴대폰 검사는 아니다.
- .env의 기존 OpenAI 키로 PLAN_FROM_BRIEF를 실제 실행했다. SSE step/text/proposal/done 수신, 제안 적용 성공, 최종 보고서 1개·완료 기준 2개·업무 3개를 합성 프로젝트에 생성했다.
- 브라우저 AI 패널에서도 ASK를 실제 실행해 해당 프로젝트 내용에 대한 답변 완료를 확인했다. 실제 에이전트 실행은 2회이며 내부 모델 호출 수는 별도 계측하지 않았다.
- AI 합성 프로젝트: 740f2547-4591-4d85-962c-1d42fca1e5a5. 기존 월요일 시연 프로젝트는 변경하지 않았다.
- 이번 작업은 백엔드 Java 변경이 없으므로 전체 백엔드 테스트를 다시 실행하지 않았다. 이전 검증본의 275/275 결과와 구분한다.
- 로컬 주소: http://127.0.0.3:13000. 시작 직후 브라우저 접속 거부는 서버 준비 후 재접속으로 해소됐다.
