## 변경

`CurrentEmailDeliveryAuthorization`은 실제 설정 저장 클래스와 A 인증 Reader를 읽어 현재 users.email 원문, 수신 의향, 마지막 enabledAt, 현재 주소 verifiedAt을 제공한다. 기존 예약/발송 조건을 완화하지 않고 `State.permits`를 사용한다. 누락 의존성은 필수 주입으로 검출하며 DB 장애를 미인증/기본 off로 숨기지 않는다. 가입과 프로젝트 활동은 주소 인증 없이 유지한다.

실제 DB 검사7건은 인증/동의 중 하나라도 없으면 앱 알림만 유지하는 경로, 혼합 대소문자 현재 주소 수신, 대기 뒤 해제/재활성화/늦은 재인증의 제외, 실제 최종 제출물 검토 생산자를 확인한다. SMTP는 이 DB 검사에서만 대역이다.

### Mailpit 실제 수신

공식 이미지 `axllent/mailpit:v1.27.4`, digest `sha256:df6c2541907e1be6fac21f509927cf6ed771617a1f4b361ef66d97bd05593d2d`를 loopback에만 매핑했다. 컨테이너 `blackbox_mail_b_test`, SMTP28135·수신 API/UI28035. 외부 전달/릴레이 설정 없음.

1. 합성 계정이 수신을 켰지만 미인증이면 업무 요청은 앱 알림만 기록되고 메일은0건.
2. 실제 인증 서비스가 SMTP 어댑터를 통해 확인 메일1통을 보내고, 수신 본문의 fragment 토큰으로 실제 confirm을 완료.
3. 이후 새 업무 확인 요청1통 수신, 대기SENT·원문 업무 링크 확인.
4. 설정을 끄면 새 요청은 앱 알림만 기록, 메일 수신 수 유지.
5. 대기 뒤 off→on이면 과거 대기SKIPPED, 수신 수 유지.
6. 이후 새 업무 요청1통과 새 최종 제출물 검토 요청1통 수신.

최종 수신4통(인증1·업무2·검토1), 업무 발송 대기SENT3건이다. `EmailSmtpEndToEndTest`는 `BB_MAILPIT_SMOKE=true`에서만 실행하며 테스트 안에서 SMTP를127.0.0.1:28135로 고정한다. 일반 CI는 이 실제 메일함을 요구하지 않는다.
