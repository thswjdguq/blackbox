# B · 업무 확인 요청 사건 키의 공통화

- #218 A 리뷰1 / 기준 main `eec7948e`(#217 병합) / K-41 0.4의 사건 형식은 변경하지 않는다.
- B의 NotificationService·업무 메일 재확인·대응 테스트·개인 문서만 수정한다. DB/번호/API/설정/A·C 코드는 변경하지 않는다.

## 문제와 수정

발행자와 발송 전 재확인, DB fixture가 `COMPLETION:{taskId}:{micros}`를 각각 조립했다. 생산자의 형식만 바뀌면 fixture/guard는 같은 옛 형식으로 검사해 통과하는데 실제 메일은 조건 소멸로 제외될 수 있다는 A의 리뷰를 반영했다. 운영에서 누락이 발생했다고 확인한 사고는 아니다.

NotificationService.completionKey(UUID,OffsetDateTime)를 발행·재확인·fixture가 함께 사용한다. 기존 사건 형식·UTC 마이크로초 정밀도를 유지해 기존 저장 자료를 고치거나 재발행하지 않는다.

실제 NotificationService가 DB에 저장한 UserNotification을 key 재조립 없이 guard에 넘기는 검사를 추가했다. 다른 시간대 표현/서브마이크로초는 같은 사건, 마이크로초·업무가 다르면 다른 사건인 단위 검사도 추가했다. 고정 형식 문자열의 조립은 생산자 한 곳에만 남는다.
