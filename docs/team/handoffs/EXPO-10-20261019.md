# EXPO-10 — 회원가입 소속 학교·학과

## 변경

- 공식 공개 파일을 정규화한 오프라인 목록: 자료 연도 2025, 기준일 2026-03-18. 원본 101,238행 → 학교명/시도/학교유형 조합 447개, 학과 15,189개.
- 회원가입: 학교 검색 → 학교 선택 → 해당 학교 학과 선택. 목록 미반영 시 학교/학과 직접 입력 허용.
- 목록 선택은 `CATALOG`, 직접 입력은 `SELF_REPORTED`. 두 방식 모두 재학 인증이 아님을 표시.
- 가입 시 소속 필수. 기존 계정 로그인은 유지하며 프로필에서 소속 추가·수정 가능. 이름만 바꾸면 기존 소속 유지.
- 공개 GET `/api/auth/affiliation/schools`, `/api/auth/affiliation/schools/{id}/departments` 추가. 가입·프로필은 기존 인증/권한 유지.
- SignupRequest에 필수 affiliation 객체, ProfileUpdateRequest에 선택 affiliation 객체 추가. ProfileResponse에 affiliation 반환. 목록 선택은 source/schoolId/departmentId, 직접 입력은 source/schoolName/departmentName 전송.
- 임의 학교 ID, 타 학교 학과 ID 거절. 직접 입력은 공백/길이/제어문자 및 ID 혼용 검사. 학교·학과명은 CATALOG 모드에서 서버의 정식 이름 사용.

## DB 번호 및 보존

- 변경 전 GitHub 최신 main 및 모든 열린 PR migration 경로 대조. #133이 V32 사용 중.
- 새 migration `V31_2__user_university_affiliation.sql` 사용: V31_1 → V31_2 → V32. 기존 migration은 수정하지 않음.
- users에 소속 ID/명칭/입력 방식/자료 연도 nullable 컬럼 추가. 기존 회원은 NULL 유지. DB CHECK로 목록 선택·직접 입력·미설정의 저장 형태 구분.
- 기존 시연 DB를 `/tmp/expo10-before.dump`(테스트 DB 컨테이너 내부)로 백업하고 `bb_expo10_upgrade`에 복제한 후 먼저 검증.
- 원래 사용자 38명의 기존 모든 필드를 해시 비교해 업그레이드 전후 보존 확인. 이후 로컬 시연 DB에도 적용·재확인. 신규 테스트 가입 계정은 복제/빈 DB에서 트랜잭션 롤백.
- 이미 V32 이상인 다른 DB에는 이 분기를 바로 적용하지 말고 순서 조정 필요. 공개 서버 DB는 확인/변경하지 않음.

## 검증

- 전체 백엔드: **294/294 통과** (복제 DB).
- 신규 실제 DB HTTP 검사: **7/7 통과**, 복제 DB와 빈 DB 각각 수행.
- 빈 DB `bb_expo10_clean`: V1부터 V31.2까지 적용 성공. 복제 DB는 V31.1 → V31.2 성공. 재시작 검증에서도 정상.
- 첫 전체 실행은 이전 완료 기준 필수 테스트 1건과 DB 연결 한도 6건 실패. 이전 기준 테스트를 EXPO-09 요구사항에 맞춰 수정.
- 풀을 4개로 제한한 두 번째 실행은 6개 동시 요청 잠금 검사의 연결 부족으로 1건 실패. 제품 코드/검사 기준은 유지하고, 풀 10개 + JVM `-Dspring.test.context.cache.maxSize=3`으로 컨텍스트 보관 수를 줄여 전체 통과.
- frontend `npx tsc --noEmit`, webpack production build, git diff 공백 검사 통과.
- 실제 로컬 API·프론트 프록시 모두 200. 학교 목록 447개 조회.
- 실제 브라우저에서 학교 검색 ‘신구’ → 신구대학교 선택 → 해당 학과 조회·선택 → 직접 입력으로 전환 시 명칭 유지 확인. 브라우저에서는 실제 가입 제출을 하지 않음.
- 기존 완료 기준 선택 변경도 포함: NotificationAssignmentDatabaseTest에서 기준 없는 요청의 실제 DB 알림 저장과 본인 승인 금지 검증 통과.

## 적용과 남은 범위

- 로컬 18083/13000 수정본 실행 중. 공개 서버 배포·커밋·push 없음.
- 공개 서버에 반영하려면 이미지 재빌드와 실제 Flyway 이력 확인 후 배포 필요. 기존 가입 호출 스크립트도 affiliation 객체를 보내야 함.
- 실제 휴대폰·공개 HTTPS에서 새 가입 화면은 미검증. 오프라인 목록은 정기 갱신이 필요하며 직접 입력으로 누락을 보완함.
- 원본 데이터 및 테스트 로그는 로컬 backend/build/university/에 보관. 변환 스크립트와 출처 문서는 저장소에 포함.
