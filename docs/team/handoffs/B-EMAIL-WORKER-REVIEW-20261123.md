## 수정

이전 worker는 SMTP 결과와 관계없이 한 회차에25건까지 계속 처리했다. 이제 ACCEPTED와 수신자별 PERMANENT_FAILURE 뒤에만 다음 건을 획득한다. TEMPORARY_FAILURE와 UNKNOWN_OUTCOME은 기존 재시도 결과를 저장한 뒤 현재 회차를 끝낸다. 인증 상태의 DB 조회 장애도 한 회차를 중단하며, 장애를 미인증이나 저장 성공으로 숨기지 않는다.

AUTHENTICATION_FAILURE를 받으면 현재 건은 FAILED로 기록하고 프로세스의 worker 인스턴스를 일시 중단한다. 이 중단 표시는 결과 저장보다 먼저 설정한다. 결과 기록이 실패해도 다음10초 회차에서 새 로그인을 반복하지 않으며, 설정 off→on으로 해제하지 않는다. 비밀번호를 고친 뒤 서버 재기동으로 새 worker가 생성돼야 다시 획득한다. 최초 인증 실패 건은 자동 재발송하지 않으며 나머지 대기는 PENDING으로 보존한다.

중단 경고는 한 번만 기록한다. 획득 뒤 예외 로그에는 해당 delivery UUID와 예외 클래스만 남기고 주소·본문·SMTP 응답 원문·예외 메시지/스택은 남기지 않는다. 획득 전 오류에는 id를 `-`로 표시해 이전 건으로 오해하지 않게 한다.
