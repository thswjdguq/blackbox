# B · 관찰자 기여도 계산 제외

- 기준 main `b2a26cec`(Java 25, #159 병합 뒤), 작업 `codex/b-score-contributors`
- 관련 #134 8.4 / #158 / K-40 #163과 독립적인 대상 역할 결함 수정

## 결과

ScoreService 재계산 진입 시 `ProjectAccessChecker.canContribute`로 현재 팀장·팀원만 고른다. 관찰자는 집계 쿼리·저장·경보 입력에서 제외한다. 조회에서만 숨기던 기존 처리를 저장에도 적용한 것이다.
옛 관찰자 점수 행은 삭제/초기화하지 않는다. 팀원으로 바뀌면 같은 행으로 다시 계산하고, 관찰자로 바뀌면 이후 계산에서 갱신하지 않는다. 팀장·팀원의 네 불리언과 판정 산식·API 응답 모양은 그대로다.

## 검사

- Java 25.0.3, Gradle 9.8.2, PostgreSQL 16 전용 DB `bb_b_score_20261109`.
- 새 단위 3건 + 실제 PostgreSQL·인증 필터 MVC 2건, **5/5 통과**. 관찰자의 불필요한 집계 쿼리/저장 없음, 관찰자 재계산 403, 새 행 미생성, 옛 행/ID/시각 보존, 역할 전환 뒤 동일 행 재사용을 확인했다.
- 첫 명령은 PowerShell이 Gradle 옵션을 나눠 검사 전에 실패했다. 수정 후에는 사용자 전역 Gradle 설정이 JDK 23을 가리켜 컴파일 전 실패했다. 전역 설정은 수정하지 않고 이번 명령의 `org.gradle.java.home`에 JDK 25를 지정했다.
- 최초 실행된 검사는 4/5 통과했다. 실패는 테스트 바깥 트랜잭션 때문에 HTTP 저장이 커밋되지 않은 채 refresh로 덮이는 검사 문제였다. MVC 호출 뒤 flush해 실제 요청 커밋에 해당하는 DB 반영을 확인하도록 고친 뒤 5/5를 재실행해 통과했다. 검사 삭제/조건 완화로 숨기지 않았다.
- 기존 Spring MockBean 폐기 예정·Netty Unsafe 경고가 있다. 무관한 의존성 변경은 하지 않았다.
- 로컬 전체 검사는 반복하지 않고 PR CI의 전체 backend·DB·frontend 검사 결과를 별도 기록한다. 이 문서는 로컬 전체 검사를 통과했다고 주장하지 않는다.

## 경계와 남은 일

실제 개발·시연·운영 DB/업로드 변경, 기존 자료 삭제, 새 migration, 점수 snapshot/집계 확대, 라이브러리/프론트 변경은 없다. 합성 DB 자료는 테스트에서 롤백했다. 유료 AI/브라우저 호출 없음.
K-40 0.2의 snapshot 컬럼은 C 소비자 확인과 A의 번호 배정/SQL 선행 뒤 별도 PR이다. 작성자 외 A 리뷰/병합을 요청한다. #160 이후에 병합한다면 신규 MVC 테스트의 어노테이션 패키지 등을 최신 main에 맞춰야 한다.
