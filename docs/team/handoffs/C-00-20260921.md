## 2. 화면별 상태 표

### 2-1. 제출물 목록 (`/projects/[id]/deliverables`)

| 상태 | 처리 방법 |
|---|---|
| 로딩 | 스켈레톤 카드 3개 표시 |
| 0건 | "등록된 제출물이 없습니다" + 팀장·팀원만 "제출물 추가" 버튼 노출 |
| 권한 없음(관찰자) | 목록은 읽기 가능, 추가/수정/삭제 버튼 숨김 |
| 403 응답 | "이 프로젝트에 접근 권한이 없습니다" 안내 |
| 저장 성공 | 서버 응답으로 목록 갱신, 입력 폼 닫기 |
| 저장 실패 | 에러 메시지 표시, 입력값 보존, 재시도 가능 |
| 네트워크 오류 | "불러오기 실패" 배너 + 재시도 버튼 |

### 2-2. 제출물 상세 (`/projects/[id]/deliverables/[delId]`)

탭 구성: **요구사항·업무** | 검토 | 최종 제출

| 상태 | 처리 방법 |
|---|---|
| 로딩 | 스켈레톤 |
| 요구사항 0건 | "요구사항이 없습니다" + 팀장·팀원만 추가 버튼 |
| 연결 업무 0건 | "연결된 업무가 없습니다" 안내 |
| 진척(K-13) | 업무 완료율·필수 요구사항 충족률 별도 표시. API 미구현 시 fixture 사용 |
| 진척 API 실패 | 수치 숨김, "진척 정보를 불러올 수 없습니다" — 가짜 0% 표시 금지 |
| 진척 0건(total=0) | "연결 업무 없음" / "필수 요구사항 없음" 문구 — 100% 표시 금지 |
| 검토 탭 | 미구현. "검토 기능 준비 중" 비활성 표시. 사용 가능처럼 표시 금지 |
| 최종 제출 탭 | 미구현. "최종 제출 기능 준비 중" 비활성 표시. 사용 가능처럼 표시 금지 |
| 제출물 삭제 시 업무 연결 있음 | 409 → "연결된 업무를 먼저 해제하세요" 안내 |
| 저장 실패 | 에러 표시, 입력값 보존 |

### 2-3. 업무 모달 — 제출물 연결 섹션

| 상태 | 처리 방법 |
|---|---|
| 제출물 목록 로딩 | 드롭다운 비활성 + 로딩 표시 |
| 제출물 0건 | "연결할 제출물이 없습니다" 안내 |
| 제출물 선택 후 요구사항 목록 | 선택한 제출물의 요구사항만 표시 |
| 연결 해제 | clearDeliverable·clearRequirement 전송 |
| 완료 기준 저장 | completionCriteria 텍스트 저장 |
| 서버 API 미준비 | API 미준비 시 이 섹션만 숨기거나 비활성 표시. mock 저장 성공 노출 금지 |

## 4. K-13 계약 검토 응답

K-13 § 5 손정효에게 항목 답변:

1. **업무 진척과 요구사항 충족 별도 표시 여부**: 가능. 두 수치를 각각 다른 행·섹션으로 표시할 수 있음.
2. **세 예시 fixture 사용**: 사용 가능. "현행(연결 있음)", "빈 상태(total=0)", "미래(met≠null)" 세 가지를 `frontend/src/__fixtures__/deliverable-progress/` 경로에 관리. 미래 예시를 실제 기능처럼 노출하지 않음.
3. **응답 실패와 0건 다른 UI**: 실패 → "정보를 불러올 수 없습니다" 오류 표시. 0건 → "연결 업무 없음" / "필수 요구사항 없음" 문구. 구분해서 처리.
