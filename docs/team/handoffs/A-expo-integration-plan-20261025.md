- 결론: **엑스포가 끝났으니 시연 브랜치의 기능 11가지를 기능별 PR로 main에 옮긴다.** 시연 쪽 AI 공급자 경로와 엑스포 전용 자료는 두고 온다. 마이그레이션은 겹치는 V25 하나만 V25_1로 바꾸고, 나머지는 시연 브랜치의 이름을 그대로 쓰되 번호 순서대로 병합한다. 범위(1장)와 번호(3장)에 동의하면 이 문서를 기준으로 PR을 낸다

## 5. 위험과 미리 정할 것

1. **기존 완료 업무를 고칠 수 없게 된다(V27).** 승인 없는 완료 금지 검사를 `NOT VALID`로 걸어 기존 완료 업무는 그대로 두지만, 그 행을 수정하면 검사를 받는다. 승인 기록이 없는 기존 완료 업무의 제목 수정, 제출물 연결 변경 등이 DB에서 막힐 수 있다. 정할 것: (a) 마이그레이션에서 기존 완료 업무에 "이전 기록" 표시로 승인 칸을 채운다, (b) 검사를 "새로 완료로 바뀌는 행"만 보게 트리거로 바꾼다, (c) 기존 완료 업무는 고치지 않는 것으로 두고 화면에서 막는다. 2번 PR 전에 B가 정한다
2. **업무 완료 규칙이 바뀐다.** 지금 main은 담당자가 업무를 바로 완료로 옮긴다. 통합 뒤에는 다른 팀원의 확인이 있어야 완료다. 점수의 "업무 완료"와 무임승차 경보가 이 판정을 그대로 따라간다. #108의 시연 자료 스크립트는 업무를 바로 완료로 만들어서 고쳐야 한다(손정협님 10/13 지적). K-20의 "확정 뒤 연결 업무 잠금"과 완료 요청의 관계도 2번 PR에서 확인한다
3. **보고서가 세 갈래다.** main의 #131(병합)과 #132(리뷰 중), 시연 브랜치의 EXPO-08이 같은 `ReportService`를 고쳤다. #132를 먼저 병합하고, A가 개편 PR에서 셋을 합친다. 남길 것: 해제 여부 기준의 경보, 정렬한 해시, 한국 시간(#131), 제출물 기록(#132), 개편된 구성과 중립 문구·관찰자 제외(EXPO-08)
4. **학교·학과는 개인정보가 늘어난다.** 학교·학과는 선택 입력으로 두고, 개인정보 처리 안내(동의 화면이 생기면 그곳)에 항목을 더한다. 목록은 공공데이터포털 "전국대학별학과정보표준데이터"(2025년 자료)의 공개 파일로 만든 스냅샷이고 외부 호출이 없다. 갱신 방법(`scripts/build-university-catalog.cjs`)을 PR 본문에 적는다
5. **화면이 크게 바뀐다.** 화면 87개 파일이 다르다. 서버 PR마다 그 화면만 옮기고, 마지막에 메뉴를 바꾼다. 중간 상태에서도 main의 화면이 깨지지 않는지(새 서버 필드가 없을 때의 동작) 화면 PR마다 확인한다
6. **계약을 옮긴다.** K-54, K-58, K-EXPO-06, K-EXPO-07은 시연 브랜치의 "로컬 시연 승인" 초안이다. 해당 기능 PR에서 main의 계약 형식(생산자·소비자·버전·수용 테스트)으로 다시 쓰고 B·C 확인을 받는다. 번호는 그대로 둔다
