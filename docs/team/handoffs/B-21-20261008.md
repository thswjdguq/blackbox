## 문제와 결과

피드백을 실제 업무로 옮기는 API를 구현했다. 새 업무는 TODO·담당자 미설정·해당 제출물 연결·요구사항 미설정이며 설명에 피드백 원문을 복사한다.
같은 피드백 재시도는 기존 업무의 200·created=false를 돌려주고 입력으로 기존 제목을 덮어쓰지 않는다. 처음 생성은 201·created=true다.
생성·연결·활동 기록은 같은 트랜잭션과 제출물 잠금을 사용한다. 기존 업무 생성 규칙은 TaskService.createTask를 재사용한다.
연결된 업무의 제출물 이동·해제는 TaskService에서 409로 안내하고 DB 복합 외래키도 최종 방어로 유지한다.
업무 완료는 피드백을 해결하지 않는다. 업무 삭제는 DB가 연결만 비우며 해결 사유·담당자·시각은 유지한다.

## 수행한 검사

- 실제 PostgreSQL 16.13 전용 DB를 사용한 전체 백엔드 테스트 130건, 실패 0. 기존 121건에 전환 단위 7건(매개변수 포함), 연결 이동 차단 1건, 실제 DB 롤백 1건이 반영된 최종 집계다. 실제 결과의 합계는 XML 기준이며 130건이다.
- 실제 인증 HTTP: B20-http.ps1 46건 + B21-http.ps1 추가 28건 통과.
- 전환 동시 요청 8건: 최초 201 한 건·재요청 200 일곱 건, taskId 한 개.
- 제목·설명·제출물·TODO·담당자 없음·요구사항 없음 확인, 관찰자 403, 이동·해제 409, 업무 완료 뒤 REFLECTION_PENDING, 삭제 후 RESOLVED·사유 보존, 다시 열기 후 재생성, 승인 이후 기존 링크 200·삭제 뒤 새 생성 409 확인.
- 실제 DB의 원자성 검사: TASK_CREATE는 실제 ActivityLogService로 기록하고 FEEDBACK_TASK_LINK만 spy로 강제 실패시켰다. 트랜잭션 종료 후 tasks 0건·activity_logs 0건·linked_task_id null을 확인했다. mock 저장소 검사와 구별한다.
- git diff --check 통과. 스키마·라이브러리·프론트 변경 없음.

실행 JVM은 로컬 도구 체인의 Java 23.0.2이며 Java 17 실행 결과로 보고하지 않는다. 검사용 DB/더미 계정만 사용했고 토큰·쿠키·운영 환경값은 출력하거나 저장하지 않았다.
