## 남은 일 / 주의

- **원격 CI 미실행**: job 3개가 실제로 green인지는 PR을 올려야 확인된다. 그전까지 '설정됨'으로 적지 않는다.
- job별 타임아웃은 backend 20분, migrations 25분, frontend 15분으로 뒀다. 필수 검사로 지정할 job에는 paths 필터를 걸지 않는다. 건너뛴 job은 상태를 보고하지 않아 PR이 영구 대기 상태가 된다.
- **브랜치 보호·필수 검사 미설정**: main 직접 push 제한, 1인 승인, 필수 검사 지정은 PR 병합 후 설정하고 실제 값과 함께 여기에 추가한다.
- `refactor-guard.yml`은 `refactor/**`에서만 동작해 이번 흐름에는 영향이 없다. 삭제하지 않고 그대로 둔다.
- 검사 DB는 `docker compose -f docker-compose.test-db.yml -p blackbox-test down`으로 정리 가능(볼륨 유지). 일반 검증에서 `down -v`는 쓰지 않는다.
- 스크립트의 psql 실행 방식은 세 가지 중에서 고른다. 호스트에 psql이 있으면 그것을 쓰고(CI 러너), 없으면 이미 떠 있는 검사 DB 컨테이너에 `docker exec`으로 붙고, 그것도 아니면 psql 이미지를 띄운다.
  SQL마다 새 컨테이너를 만들던 처음 방식은 Docker Desktop에서 컨테이너가 멈춘 채 끝나지 않는 일이 두 번 있었다. `docker exec` 방식으로 바꾼 뒤 전체 실행 시간이 약 3분에서 1분 8초로 줄었다.
- 모든 psql 호출에 120초 타임아웃을 두고, 제약 거절 판정은 종료코드와 stderr의 제약 위반 문구를 함께 확인한다. 그러지 않으면 SQL 오타나 접속 실패가 '제약이 막았다'로 집계된다.
- 기대하는 마이그레이션 개수와 업그레이드 target은 `db/migration` 파일 목록에서 계산한다. V20이 추가돼도 스크립트를 고칠 필요가 없다.
