# EXPO-04 프로젝트 삭제·업무 편집

- 기준: shinguexpo cb23907d. 기존 footer 변경 보존. 신규 push/merge/배포 없음.
- 프로젝트 삭제 500 원인은 권한 확인 중 로딩된 ProjectMember가 remove된 Project를 참조하는 Hibernate TransientObjectException이었다. 권한 검사 후 repository의 단일 DELETE 쿼리를 실행하고 영속성 컨텍스트를 비우도록 수정했다. 기존 DB의 외래키·CASCADE·기록 보호는 그대로다.
- 빈 프로젝트는 삭제할 수 있다. 활동·파일·점수 등 보존 대상 기록이 있으면 기존 정책대로 409 안내한다. 실제 사용자 프로젝트를 삭제하지 않았다. 대시보드 확인 문구를 이 정책에 맞췄다.
- 업무 목록에 수정·삭제 버튼을 추가해 편집 탭으로 바로 들어가게 했다. 상세의 업무 설정 탭도 수정·삭제로 표시했다. 확인 요청 중이면 요청 취소, 완료 상태면 팀장의 업무 다시 열기 절차를 안내한다. 취소 상태를 새로 추가하지 않았다.
- 업무 삭제는 기존 규칙대로 생성자·팀장만 가능하다. 선행/확정 업무·관찰자 제한은 서버에서 유지한다.
- 전용 DB bb_expo_20261016_test에서 단위 검사 2건 + 실제 MockMvc/PostgreSQL 검사 3건 = 5/5 통과. 빈 프로젝트/멤버 동시 삭제, 사용자 보존, 팀원 거절, 활동 기록 시 409를 확인했다.
- 프론트 타입 검사, verify-task-view.cjs, verify-task-workflow.cjs 통과. webpack 프로덕션 빌드와 backend bootJar 통과.
- 로컬 실제 HTTP: 빈 합성 프로젝트 생성→삭제→404, 담당 업무 생성→제목/마감 수정→재조회→삭제→목록 제외, 활동 기록 프로젝트 삭제 409→프로젝트 보존을 확인했다. 스크립트: outputs/expo04-verify.cjs.
- 남겨 둔 합성 프로젝트: 87f45c28-c5d0-48ac-9e3d-3fb8e1362731. 테스트 시작 직후 백엔드 준비 전 접속 실패 1회 후 준비 완료를 확인해 재실행했다.
- 로컬 확인 주소: http://127.0.0.3:13000/login. 실제 브라우저 클릭 검사는 이번 작업에서 수행하지 않았다.
