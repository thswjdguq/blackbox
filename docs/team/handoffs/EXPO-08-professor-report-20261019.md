# EXPO-08 교수자 열람용 기여 활동 보고서

2026-10-19 / teamplay-ui / shinguexpo cdae9636 이후 로컬 변경.

## 변경 목적과 구조
- 기존 참여 표시·해시 중심 PDF를 교수자가 결과와 수행 근거부터 읽는 보고서로 변경했다.
- 첫 페이지: 과목·학기·기간, 팀 업무 현황, 현재 팀원별 담당/완료·파일·의견/답변·확인/검토, 최종 제출물 상태.
- 팀원 상세: 실제 업무명·상태, 최근 파일, 업무 대화/검토 피드백/해결 기록 수, 검토 의견 또는 수정·반영 내용 예시.
- 집계 기준: 기존 네 항목의 실제 조건과 저장된 집계 시각. 기록 없음과 아직 미집계를 구별한다.
- 부록: 업무 담당·완료 확인자와 파일 버전·등록 시각·파일 내용 식별값. 한글 임베드와 KST 표기를 유지한다.
- 4인 합성 예시는 본문 4페이지 + 부록 2페이지. 실제 분량은 업무·파일·제출물 수에 따라 달라진다.

## 해석과 보존
- ScoreService·계산 산식·저장 값·DB migration·기존 API 경로를 변경하지 않았다. 기여율(%)·100점 성적을 만들어 내지 않는다.
- 팀원은 현재 팀장·팀원만, 팀장 우선 이름순. 과거 원 기록의 담당자·등록자는 부록에 보존한다.
- ‘기록 없음’은 성실성 판단이나 자동 감점이 아니다. 회의를 하지 않은 팀과 플랫폼 밖 활동도 고려하도록 안내한다.
- 개인별 횟수는 질적 기여 점수가 아니다. 공동 담당 건수와 버전별 업로드의 중복 집계 특성을 설명한다.
- 생성 시점 원 기록과 마지막 저장 집계는 시점이 다를 수 있음을 명시한다. PDF 다운로드가 점수를 재계산하지 않는다.
- 보고서 번호는 문서 식별용이다. 기존의 ‘보고서 해시가 전체 무결성을 보장한다’는 문구를 제거했다. 파일 SHA-256은 내용 비교용 부록에만 남겼다.

## 변경 파일
- ReportService, 신규 ReportEvidenceReader: 기존 프로젝트별 저장소를 통한 읽기 조회·PDF 조판.
- EvidencePackageService: 동일 PDF를 ZIP에 포함, README의 형식/해시 설명·팀원 수·KST 안내 정정.
- 프로젝트 홈·활동/기여 페이지: 다운로드 이름과 설명을 보고서 내용에 맞춤.
- ReportParticipationTest 보완, 신규 ProfessorReportHttpTest.

## 검증 기록
- 별도 DB bb_expo_20261016_test 사용. 전체 백엔드 286/286 통과 후 최종 문구·조판·ZIP 안내는 보고서 관련 5/5 검사로 재확인했다.
- 보고서 HTTP 검사는 실제 DB와 MockMvc를 사용하며, 4인+관찰자 제외, 외부인 403, ZIP 동일 PDF, 집계 저장 보존, 긴 제목·공동 담당·최종 제출물 2개를 포함한다.
- 조판 검수: 번들 pypdfium2로 PNG 렌더, pdfplumber로 텍스트·범위 확인. 일반 합성본 전체 페이지와 긴 제목 부록을 눈으로 확인했다.
- 추가 회귀 검사에서 ‘최종 제출물 2개일 때 파일 안내 한 줄만 다음 장에 남음’을 발견하여 표·설명을 한 묶음으로 배치하고, 파일 미지정의 불필요한 반복 안내를 생략했다.
- 최종 합성본 6페이지 전체 PNG와 2개 제출물의 첫 페이지를 재검수했고, 긴 제목 부록에서도 잘림 없이 끝 문구를 확인했다. 보고서 3건 HTTP/DB 검사와 참여 보고서 2건 검사는 최종 조판에서 모두 통과했다.
- 프론트 타입 검사와 webpack production 빌드 통과. 전체 테스트 이후 PDF 표·여백 및 ZIP 안내 문구를 보완한 이력은 최종 검사 로그와 구분한다.

## 사용 위치와 실행
- 로컬 http://127.0.0.3:13000/login.
- 프로젝트 → 자료·활동·설정 → 활동·기여 기록 → ‘기여 활동 보고서 PDF’.
- 프로젝트 홈 ‘팀 활동 내보내기’의 ZIP에도 같은 보고서가 포함된다.
- 공유 검수본: output/pdf/team-contribution-report-example.pdf. 테스트가 만든 합성 자료이며 실제 학교 제출 자료가 아니다.
- PDF 생성 검사 산출물과 렌더: backend/build/reports/professor-report/ (임시/미추적).
- 원격 push·AWS 배포는 하지 않았다. 실제 사용자 프로젝트의 삭제·초기화·데모 생성 스크립트 실행도 하지 않았다.

로컬 기존 합성 계정의 로그인과 보고서 GET으로 실제 HTTP 다운로드도 확인했다(health/로그인/보고서/프론트 모두 200). 재기동 직후 준비 중 접속 거부는 /api/health 200 이후 재검사해 해소됐다. 이 과정의 조회는 사용자 프로젝트를 수정하지 않았으며, 시작 시 기존 ScoreScheduler의 정기 재계산은 기존 동작대로 실행됐다.
