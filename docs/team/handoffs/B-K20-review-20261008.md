# B의 K-20 v0.1 검토 의견

대상: PR #93 `1f27362` 원문. 문서 검토이며 A-20 API·DB 검증이 아니다. 생산자·소비자 합의 전 구현 기준으로 확정하지 않는다.

## A에게 답할 사항

1. 확정 뒤 연결 업무의 수정·상태·담당자·삭제·이동·해제를 막는 방향에 동의한다. 완료되지 않은 업무도 읽기 전용이 되므로 C의 확정 전 안내가 필요하다.
2. DeliverableStatusReader의 조회와 잠금 메서드는 충분하다. B의 쓰기는 statusOf만 쓰지 않고 lockForWrite를 사용해야 확정 후 변경을 막는 약속을 지킨다. 이동은 이전·새 제출물을 UUID 순서로 잠근다. 업무 행을 읽은 뒤 잠금을 기다리는 동안 소속이 바뀔 수 있으므로 잠금 후 최신 소속을 다시 확인하는 구현·경쟁 검증이 필요하다.
3. 이미 연결된 업무의 전환 재요청은 권한·전체 소속 확인 후 200·created=false로 반환하는 데 동의한다. 확정 후 새 연결은 409다.
4. 확정 기록은 회차 id로 파일 버전을 가리키는 방식에 동의한다. 회차의 file_id 불변을 서비스·DB에서 유지해야 한다. 동일 내용의 높은 버전이 있어도 승인 회차의 버전이 확정본이다. 업로드는 제출물 잠금을 공유하지 않으므로 최신 파일 여부 보장으로 보고하지 않는다.
5. 회차 열기·결정, 확정·제출 기록은 활동 기록에 남기는 것을 제안한다. 상태를 실제로 바꾼 최초 요청만 기록하고 중복 요청은 추가하지 않는다. 피드백 기록과 마찬가지로 별도 합의 전 기여도 점수에는 추가하지 않는다. 정확한 actionType·metadata는 A·B 합의 후 구현한다.

필수 요구사항 0개 통과에 동의한다. 파일을 포함한 최신 회차의 타인 승인과 미해결 0건은 여전히 필요해 파일 없는 빈 제출물이 자동 확정되는 것은 아니다.

## 제안할 문구 보완

6장 동시성 첫 문장의 “확정과 다른 내용 업로드를 동시에 보내면 둘 다 성공한다”는 뒤의 업로드 선행 시 확정 409와 함께 읽히도록 “잠금·검사 순서에 따라 둘 다 성공하거나 확정이 409이며, 확정 성공 시 승인 회차의 파일 버전이 확정본”으로 정리하면 정확하다.
제출 시각 검사는 2장 기준 5분 허용 오차가 있으므로 11장의 “미래면 400”을 “서버보다 5분 초과 미래면 400”으로 맞추는 것을 제안한다.
