## 문제와 변경

최종 확정 API가 있어도 연결 업무의 제목·상태·담당자·삭제·연결을 계속 바꾸면 확정 결과와 진행 정보가 어긋난다. TaskService의 쓰기는 권한 확인 후 A의 DeliverableStatusReader.lockForWrite로 제출물을 잠그고 CONFIRMED/SUBMITTED를 409로 거절한다. 새 업무 연결, 연결 해제, 이동도 포함한다. 진행 중인 다른 제출물과 미연결 업무는 계속 수정할 수 있다.

이동은 기존·대상 제출물 UUID 순서로 잠근 다음 업무 행을 잠가 다시 읽는다. 잠금을 기다리는 사이 업무 연결이 바뀌면 새로운 잠금을 뒤늦게 잡지 않고 409로 재시도를 안내한다. 반대 방향 이동의 교착과 오래된 연결을 믿고 수정하는 경로를 함께 막는다. 피드백의 확정 상태 판단도 A의 공통 isConfirmed 함수에 맞췄다.

## 수행한 검사

- 별도 PostgreSQL 16 검사 DB에서 `gradlew.bat build`: 175건, 실패·오류·생략 0, 49초. 로컬 Java 23이며 Java 17 원격 CI 결과와 구별한다.
- 추가 전 #104/#106 통합 기준선은 167건 통과했다.
- TaskFinalizationIntegrationTest 4건: 실제 JWT 인증 필터 + MockMvc + PostgreSQL + 실제 미해결 집계. CONFIRMED/SUBMITTED 각각 수정·상태·담당자·삭제·해제·이동·신규 연결 409, 업무·활동 자료 보존, 관찰자 조회, 관찰자/비회원/미인증 쓰기 차단을 확인했다.
- 과거 회차의 DONE 업무 연결 피드백도 미해결 1건으로 집계되어 확정을 막는다. 해결 뒤 0건으로 확정되고 이후 다시 열기와 새 의견 작성은 409다.
- TaskWriteConcurrencyTest 2건: 실제 PostgreSQL 잠금 대기를 관찰한 뒤 연결 변경 시 409·제목 보존, 반대 방향 이동 두 요청의 정상 종료를 확인했다. 이는 서비스 트랜잭션 검사이며 네트워크 요청 검사는 아니다.
- 신규 HTTP 계층 검사의 자료는 테스트 트랜잭션 롤백으로 제거된다. 동시성 검사는 본인이 생성한 프로젝트·업무·사용자만 정리하고 스케줄러를 대체한다. 운영 DB·볼륨과 기존 테스트 자료는 건드리지 않는다.
- 첫 전체 실행은 기존 TaskListDatabaseTest에 새 의존성 대역이 없어 1건 실패했다. 해당 테스트 설정에 DeliverableStatusReader를 추가한 뒤 전체 재실행해 통과했다. 목록 쿼리 4회 검증도 유지된다.
- 경쟁 테스트 추가 중 준비/정리 코드 배치 오류로 4건이 실패했으나 수정 후 최종 전체 175건이 통과했다. 경쟁 검사의 준비 파일은 본인 프로젝트로 한정해 정리하고 불변 트리거 복구도 같은 트랜잭션에 묶는다.
- `git diff --check` 통과. 기존 migration 변경·새 라이브러리·비밀값 추가 없음.

- C 화면에서 전체 사용자 흐름과 409 안내를 확인하지 않았다. MockMvc는 실제 포트를 연 HTTP 서버가 아니다.
