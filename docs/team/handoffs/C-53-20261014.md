## 실제 구현

- Sidebar의 일반 사람 아이콘을 현재 계정 이름·이메일·이니셜로 교체. 모바일은 이니셜과 접근성 이름 제공.
- AccountIdentity와 profileStore 추가. 프로필 조회 중복 방지, 조회 실패 재시도, 로그아웃 시 초기화, 이전 계정의 늦은 응답 무시.
- 프로필 이름 저장 성공 시 메뉴에도 즉시 반영. 저장 중 계정이 바뀌면 이전 계정 결과를 반영하지 않음.

## 현재 알림: 코드 확인 결과

- TaskMessageService.inbox / useFeedbackInbox: 명시적으로 요청한 의견, 업무 완료 확인 요청, 보완 요청을 받은 피드백함과 메뉴 숫자로 확인 가능. 프론트는 화면 활성 상태에서 주기적으로 갱신. 실시간 푸시와 구별해야 함.
- FileVaultService: 업로드 버전 보관, 활동 기록, 위험 알림 재평가는 있으나 팀원에게 신규 업로드를 알리는 전용 알림은 확인되지 않음.
- Sidebar의 기존 알림은 참여·위험 유형 중심. 읽음 상태를 새 개인 알림과 그대로 공유하면 안 됨.
- ReviewRoundService 및 DiscordNotificationService: 제출물 업로드·검토 요청·최종본 확정을 연결하는 일관된 팀원 알림 흐름은 확인되지 않음. Discord의 업무 배정·완료 등과 혼동하지 않음.
- 위 결과는 소스 감사이며 운영 DB나 실제 4인 계정 수신 테스트 결과가 아님.

## 권장 UX: 일하는 동안 기록이 남도록

주 메뉴는 **오늘 할 일 / 업무 / 최종 제출물**로 줄인다. 회의·모든 자료·활동·기여도는 보조 메뉴에 둔다. 오늘 할 일은 내 미완료 업무와 내가 확인할 요청만 우선 표시한다. 기여도 점수나 중복 안내 카드를 업무보다 앞세우지 않는다.

1. 분배: 팀장이 최종 제출물 아래 업무를 만들며 담당자·기한·완료 기준을 한 번 지정한다. 팀원 기본 화면은 내 업무, 팀 전체 전환은 유지한다.
2. 진행: 목록의 업무를 누르면 옆 상세 패널에서 설명·결과 파일·대화·상태를 함께 처리한다. 단순 업무는 파일을 강제하지 않는다. 일반 질문은 완료 승인과 분리한다.
3. 피드백: 담당자가 결과를 등록하고 확인을 요청한다. 받는 사람은 알림에서 해당 업무의 해당 버전으로 바로 들어간다. '확인하고 완료 / 보완 요청'을 제공하고 본인 승인과 권한 없는 승인은 막는다. '검토 회차'보다 '확인 요청', '보완 후 다시 요청'을 기본 문구로 쓴다.
4. 최종본: 통합 담당자가 업무 결과를 참고해 실제 최종 파일을 등록한다. 자동 파일 병합으로 오해시키지 않는다. 검토자 확인과 미해결 의견을 확인한 뒤 권한 있는 팀장이 특정 버전을 최종본으로 확정한다.
5. 제출: 확정과 실제 학교 제출을 분리한다. 학교에 직접 제출한 사람이 접수 화면·시각·제출한 버전을 기록한다. 단순 버튼 클릭을 학교 제출 성공으로 표시하지 않는다.

4인 예시: 민지는 통합 및 제출, 지호는 설문, 유나는 비교 조사 및 최종본 검토, 현우는 현장 조사. 현우의 결과 알림 → 민지의 보완 요청 → 현우의 새 버전 → 다른 팀원의 확인 → 민지의 통합 파일 → 유나 검토 → 민지 확정·학교 제출 기록. 각 화면에서 다음 담당자와 다음 행동을 보여준다.

## 알림 추가 설계 — 아직 구현하지 않음

- 파일 등록: 나를 제외한 관련 팀원에게 활동 알림. 같은 업무의 연속 업로드는 묶어 과도한 알림 방지.
- 확인 요청: 실제 검토 가능한 대상에게 행동이 필요한 요청. 일반 업로드와 중복 숫자로 쌓지 않음.
- 보완/답변: 담당자 및 대화 대상에게 전달. 특정 파일 버전과 업무로 이동.
- 최종본 확정/제출 기록: 팀 전체에 정보 알림. 학교 수신 확인 여부는 별도 표시.
- 사용자별 읽음, 이벤트 중복 방지, 트랜잭션 성공 후 발행, 프로젝트 권한 검증, 재시도 정책이 필요. 실패한 업로드는 알림을 만들지 않음.
- A(제출물/파일)·B(업무/알림)와 이벤트 및 API 계약을 먼저 합의하고 C가 알림함을 연결해야 함. 새 DB/API 계약은 이번 변경에 포함하지 않음.
- 파일 버전·활동 기록 등 기존 증빙을 활용하되, 최종 검토/확정/제출 이벤트의 감사 기록 범위는 별도 확인한다. 모든 단계의 증빙이 이미 완성되어 있다고 표시하지 않는다.
- 자동 감점은 이전 합의대로 초안 검토 단계. 이메일·녹음·채팅 연동은 엑스포 이후.

## 적용 순서와 수용 기준

우선 업무 상세에 결과·피드백을 모으고 요청함에서 직접 연결한다. 다음으로 개인 알림 계약을 구현하고, 마지막으로 최종본 확정 및 외부 제출 기록 화면을 연결한다. 전면 개편은 이 문서의 제안이며 아직 적용하지 않았다.

4인 계정으로 배정 → 결과 등록 → 알림 수신 → 보완 → 재등록 → 타인 확인 → 최종본 검토 → 확정 → 제출 기록을 통합 검증해야 한다. 본인 승인 차단, 다른 프로젝트 접근 차단, 이전 버전 보존, 사용자별 읽음, 중복 알림 방지, 실패 시 입력 유지, 모바일 뒤로 가기 후 문맥 유지도 확인한다.
