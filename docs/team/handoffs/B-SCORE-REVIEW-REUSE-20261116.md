## 변경

ScoreService는 snapshot을 만들 때 이미 읽은 검토 횟수를 불변 Map으로 경보 검사에 전달한다. AlertService는 전달된 값을 재사용해 같은 계산의 ScoreReviewActivityReader 호출을2회에서1회로 줄인다. 판독기에는 묶음 집계 쿼리7개가 있으므로 이 묶음을 중복 실행하지 않으며, 점수 항목과 경보도 같은 횟수를 사용한다. 실제 전체 응답 시간의 개선율을 측정한 것은 아니다.

기존3인자 독립 경보 검사는 직접 읽는 경로로 유지한다. 이벤트 reevaluate의 조회 방식은 바꾸지 않았다. 두 경보 진입점 모두 기존 REQUIRED 트랜잭션 방식을 유지하며, 새 캐시 인자를 받아도 현재 기여자/최소 팀원 수 필터를 항상 적용한다. 저장·판정·경보 조건과 API 모양은 그대로다.
