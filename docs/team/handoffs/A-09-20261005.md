# 송승준 · A-09 · 2026-10-05 G1 화면 확인 기록

주간 계획(2026-09-29 주)의 통과 조건 "제출물·요구사항·업무를 실제 화면에서 저장하고 새로고침한 뒤 다시 조회된다(팀장·팀원·관찰자 각각)"를 브라우저로 확인한 기록이다.

## 환경

- main `25ccca5` (#53 제출물 화면 병합 시점)
- 검사용 PostgreSQL 16(`docker-compose.test-db.yml`, 25432)에 임시 DB를 만들어 V1~V20을 적용했다. 개발 DB는 쓰지 않았다
- 백엔드 `./gradlew bootRun`(18080), 화면 `npm run dev`(13000, `NEXT_DEV_BACKEND=http://localhost:18080`)
- 브라우저: 화면 없이 실행한 Chromium을 스크립트(Playwright)로 조작했다. 사람이 화면을 보며 누른 것은 아니다

## 방법

계정 3개(팀장, 팀원, 관찰자)를 만들었다. 계정 생성, 프로젝트 생성, 참여, 관찰자 역할 지정은 API로 준비했고, 그 뒤는 모두 **브라우저에서 로그인 화면으로 들어가 버튼을 눌러** 확인했다. 저장 뒤 새로고침해 다시 보이는지, 저장 버튼을 연달아 두 번 눌렀을 때 서버로 나간 쓰기 요청 수, 끝난 뒤 DB의 행 수를 봤다.

팀원의 업무 저장과 관찰자 6건은 확인 스크립트의 버튼 선택 오류를 고친 뒤 다시 실행한 결과다.

## 발견한 것

**관찰자에게 업무 보드의 추가 버튼이 보인다.** 눌러서 입력하고 "추가"를 누르면 서버가 403으로 거절하고, 화면에 "관찰자는 프로젝트를 수정할 수 없습니다"가 표시되며 입력 창은 닫히지 않는다. 저장되는 것은 없다. 권한은 서버에서 지켜지지만, 관찰자가 쓸 수 없는 버튼을 누르게 된다.

#63(업무 보드 관찰자 읽기 전용)이 이 문제를 고쳤다. 병합 뒤 다시 확인한 결과는 아래 "재확인"에 있다.

## 판정

저장과 재조회 범위는 **충족**으로 본다. 관찰자는 저장할 수 없으므로 조회로 확인했다. 10/5에는 관찰자 업무 보드의 읽기 전용 처리가 끝나지 않았고, #63 병합 뒤 다시 확인해 통과했다(아래).
