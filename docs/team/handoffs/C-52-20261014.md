## 적용

- 신규 기본은 목록. 팀원은 내 업무, 팀장·관찰자는 전체 업무. 완료 업무는 기본 숨김, 목록은 마감순 정렬.
- 목록/칸반, 업무 범위, 완료 포함 설정을 사용자 ID·프로젝트 ID·역할 조합으로 이 브라우저에 저장. 정렬 열과 외부 우선순위/태그 필터는 저장하지 않는다. 예전 전역 `task-view`는 계정 간 공유 문제를 피하기 위해 승계하지 않는다.
- 내 업무 / 내가 검토할 업무 / 전체 업무 / 미배정 버튼과 건수. 건수는 프로젝트 전체 기준임을 명시하고 실제 필터 결과 건수를 별도로 표시.
- 제출물 링크는 개인 기본 범위보다 우선하여 다른 담당자의 연결 업무도 표시. 직접 업무 링크는 완료 숨김 여부와 관계없이 상세창을 연다.
- 비어 있는 필터 결과에는 모든 필터 해제·완료 포함 이동 제공. 완료 업무는 체크박스로 다시 표시.
- 목록·칸반 모두 상태 선택으로 할 일↔진행 중 변경. 성공한 서버 응답으로 갱신, 처리 중 중복 요청 방지, 실패 시 기존 상태와 오류 안내 유지.
- 완료 요청/요청 확인은 기존 상세창으로 연결. DONE 직접 선택 없음. 완료·검토 대기 업무 상태 선택 잠금, 관찰자는 변경 컨트롤 없음. 실제 권한과 완료 조건은 기존 서버에서 검증.
- 검토 범위는 기존 `/tasks/{id}/completion`의 `canReview`에 기반한다. 미완료 요청 업무만 최대 4건씩 병렬 조회하며 실패/로딩을 표시하고 재시도 제공. 요청당 조회이므로 향후 대규모 프로젝트는 B가 집계 API를 별도 계약으로 제공하는 편이 효율적이다.
- DndContext/센서/드래그 이벤트/정렬 컨텍스트/드롭 영역/손잡이·커서·안내 제거. 칸반은 상태별 보기로 유지. 의존성 버전/lockfile 변경 없음.
