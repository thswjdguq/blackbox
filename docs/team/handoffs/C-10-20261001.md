## 방법

화면이 호출하는 API 순서를 그대로 스크립트로 실행했다. 계정 4개: 팀장 A, 팀원 B, 관찰자 C(초대 후 A가 역할 변경), 다른 프로젝트 사용자 D.

**이 기록은 API 수준 확인이다.** 브라우저에서 버튼을 눌러 본 결과가 아니며, 화면 확인은 아래 "남은 확인"에 따로 둔다.

### 브라우저 확인으로 찾은 버그 (수정함)

처음 실행에서 **프로젝트를 만든 팀장이 관찰자처럼 보였다** (추가 버튼 없음, "팀원이 등록하면 확인할 수 있습니다"). 원인은 서버 `GET /api/projects/{id}`가 `myRole: null`, `memberCount: 0`을 돌려주는 것이다 (`ProjectService.getProject`가 역할 없이 `ProjectResponse.from(project)`를 쓴다. 목록 `GET /api/projects`는 정상). 1단계 화면은 멤버 목록과 내 id로 역할을 정했는데 이 PR이 `myRole`로 바꾸면서 드러났다. 목록·상세가 다시 멤버 목록과 `/auth/profile`로 역할을 정하도록 고쳤다. 서버 수정은 A에게 따로 요청한다. API 수준 확인(위 27건)은 서버만 봐서 이 문제를 잡지 못했다.

## 실행 방법

```powershell
docker compose -f docker-compose.db-only.yml up -d
# 백엔드 (JDK 17): SPRING_DATASOURCE_* / JWT_SECRET 설정 후
cd backend; .\gradlew.bat bootRun
# 프론트
$env:NEXT_DEV_BACKEND='http://localhost:8080'; cd frontend; npm run dev
```

`start-local.ps1`은 프론트에 `NEXT_DEV_BACKEND`를 넘기지 않아 화면의 API 호출이 실패한다. A-06에서 수정 예정.
