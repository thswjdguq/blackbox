# 업무 결과 확인 UI와 팀원 확인 정책

2026-10-12 사용자 요청에 따른 별도 UI 구현. 기준 폴더 `C:/blackbox/teamplay-ui`, HEAD `98d073b`와 기존 미커밋 변경.

## 이번에 적용한 흐름

`업무 수행 → 결과 파일 등록 → 결과 제출하고 확인 요청 → 다른 팀원이 확인하고 완료`

- 업무는 확인할 결과 단위로 만들고 작은 수행 단계는 설명 안의 Markdown 체크리스트로 묶는다.
- 체크리스트는 진행 메모다. 체크 수나 파일 존재만으로 작업의 품질을 인정하지 않는다.
- 업무 창은 기본적으로 ‘수행·결과 확인’을 연다. 완료 기준, 설명·체크리스트, 결과 파일, 보완 사유와 확인 버튼을 한 화면에 둔다.
- 제목·담당자·기한·완료 기준 등 변경은 ‘업무 설정’에서 한다. 미저장 변경이 있으면 결과 요청/확인을 잠그고 먼저 저장하도록 안내한다.
- 파일을 추가하면 완료 조건 조회가 갱신된다. 결과 등록 자체는 완료나 승인으로 처리하지 않는다.
- 업무 창에서 제출물 검토 회차를 만들던 버튼과 전체 제출물 ReviewPanel을 제거했다. 최종 취합 검토는 연결된 제출물에서 진행한다.
- 업무 자료 조회에서 사용자 정보와 프로젝트 전체 업무를 반복 조회하지 않는다.

## 서버 권한 변경

- 모든 결과 업무에 다른 팀원의 확인이 필요하다. 확인과 업무 완료를 한 번의 명령으로 처리하고 추가 팀장 승인을 받지 않는다.
- MEMBER와 LEADER가 확인 가능하되 업무 담당자와 현재 요청자는 본인 결과를 확인하거나 보완 판정할 수 없다. 담당자 미지정이면 생성자를 수행자로 본다.
- 팀장 본인 업무도 다른 팀원이 확인한다. 관찰자는 쓰기 불가다. 기존 제출물 최종 확정 권한은 변경하지 않았다.
- GET completion의 `canReview`는 보완 판정 포함 권한, `canApprove`는 완료 조건도 통과한 확인 권한이다. 화면이 역할 이름만으로 승인 버튼을 켜지 않는다.
- 완료 후 재전송은 실제 확인자에게만 기존 결과를 반환한다. 다른 확인자의 중복 완료 시도는 409다.
- 요청 중 내용·담당자·파일을 동결하는 기존 정책, 직접 DONE 우회 차단, 선행 업무 조건을 유지한다.
- 재오픈은 기존 팀장 권한이다. 승인 회차별 불변 이력은 이번에 추가하지 않았다.

## 제한

- 모든 팀원을 업무 담당자로 넣으면 독립 확인자가 없어 요청이 대기한다. 실제 수행 담당자와 확인자를 구분해야 한다. 이를 우회하는 본인 승인은 허용하지 않는다.
- 체크리스트는 기존 description에 저장한다. 현재 일반 업무 수정과 같은 동시 수정 한계가 있으며 실시간 공동 편집·원자적 버전 충돌 방지는 구현하지 않았다.
- 파일은 등록 후 요청하는 흐름이다. 파일 업로드와 완료 요청을 하나의 서버 트랜잭션으로 합치지 않았다.
- 회의 AI 초안 영속화·제출 후보 구성·기여도 스냅샷은 이번 UI 작업에 포함하지 않았다.
- 새 DB migration은 없다. 기존 로컬 V25~V27 및 이번 권한/API 의미는 main 반영 전에 A·C 검토가 필요하다.
