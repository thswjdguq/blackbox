# 처음 사용하는 팀을 위한 메뉴 정리

## 범위

2026-10-12 사용자의 네비게이션 단순화 요청으로 별도 UI 폴더에서 작업한다. 기준 `98d073b`, 브랜치 `codex/ui-flow-redesign`. 기존 미커밋 변경을 보존하며 frontend와 이 문서만 변경한다. API·DB·원격 저장소 변경은 없다. main 반영 전 C가 기존 화면과 비교 검토한다.

## 사용 흐름

1. 내 프로젝트에서 프로젝트를 만들거나 초대 코드로 참여한다.
2. 프로젝트 홈에서 팀원 초대와 다음 할 일을 확인한다.
3. 제출물에서 제출할 결과물·마감·요구사항을 정한다.
4. 업무를 나누고 업무 상세에서 자료 등록·검토·피드백을 처리한다.
5. 제출물에서 검토·수정을 반복하고 최종 확정·제출 기록을 진행한다.

회의와 회의록은 `회의`에서 사용한다. 검토는 작업 중에도 가능하며 순서 안내가 검토를 막는 게이트는 아니다.

## 메뉴 원칙과 변경

- 주요 메뉴 4개: 프로젝트 홈 / 제출물 / 업무 / 회의.
- 프로젝트 선택 전에는 내 프로젝트만 보여준다. 존재하지 않는 폴백 경로나 클릭 후 차단되는 메뉴를 제거한다.
- 전체 프로젝트로 돌아가기와 프로젝트 전환을 구분한다. 프로젝트를 바꾸면 새 팀의 홈에서 시작한다.
- 모든 자료 / 팀 활동 / 팀 설정은 `자료·활동·설정` 안에 둔다. 해당 보조 화면에 직접 들어오면 메뉴를 펼쳐 현재 항목을 보여준다.
- 일정 조율은 독립 주 메뉴에서 제거하고 회의 화면의 `회의 시간 정하기`로 접근한다.
- 사이드바와 중복되던 상단 5개 탭은 `내 프로젝트 > 프로젝트 홈 > 현재 화면` 경로로 바꾼다. 상세 화면에서는 목록으로 돌아갈 수 있다.
- 메뉴 이름·경로·선택 상태는 projectNavigation.ts 한 곳을 기준으로 한다.
- 프로젝트 홈의 반복된 기능 카드 4개를 간단한 진행 순서로 바꾼다. 다음 할 일을 먼저 보여주며, KPI·기여도·자료는 접힌 보조 영역으로 옮긴다.
- 팀원 초대 코드 버튼에 `팀원 초대`를 표시한다. 검토 안내는 자료를 업무 상세에서 등록하는 현행 흐름과 맞춘다.
- 알림·프로필·테마·로그아웃은 유지한다. Notion 연동은 주요 작업 메뉴에서 제거하며 기존 연결 정보·페이지를 삭제하지 않는다.
- 메뉴 숨김은 권한 검사를 대신하지 않는다. 기존 서버 권한과 읽기 전용 규칙을 유지한다.

## 검증

- 타입 검사와 git diff --check 통과.
- 프론트 운영 빌드 및 실제 페이지 응답 확인은 실행 후 아래 기록한다.
- 백엔드 변경이 없어 서버 테스트를 반복하지 않는다. 이전 출석/파일/검토 API 검증 결과는 ATTENDANCE_AND_TASK_FILES.md에 있다.
- 브라우저 클릭·모바일 메뉴·키보드 조작·사용자 사용성 검증은 아직 완료하지 않았다. HTTP/초기 HTML 확인을 전체 브라우저 검증으로 표현하지 않는다.
- 커밋·push·main 병합 미수행.

## 실행 결과

- 타입 검사 및 최종 프론트 Docker 운영 빌드 통과. UI 컨테이너 갱신·nginx 재연결 완료.
- 인증된 페이지 9개(대시보드, 프로젝트 홈, 제출물, 업무, 회의, 모든 자료, 팀 활동, 팀 설정, 일정 조율) HTTP 200과 초기 HTML 확인 통과.
- 초기 응답에서 프로젝트 선택 전 메뉴 숨김, 프로젝트의 주요 메뉴 4개, 각 페이지의 현재 위치 표시를 확인했다. 최초 검사에서 업무 화면의 위치 표시 누락을 발견해 보완했다.
- 업무 화면의 중복 프로젝트 선택 드롭다운과 Notion 내보내기 진입점을 제거했다. 기존 내보내기 API·연동 데이터는 변경하지 않았다.
- 별도 UI DB의 검증 프로젝트 `7747e9b8-e627-4f73-bbe1-fcb9e0799309` (`[검증용] 처음 시작하는 프로젝트`). 기존 시연 DB는 변경하지 않았다.
- 브라우저에서 실제 메뉴 펼치기·클릭·모바일·키보드 검증은 여전히 미완료다.
