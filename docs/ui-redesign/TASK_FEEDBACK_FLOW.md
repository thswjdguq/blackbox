# 업무 대화·의견 요청·피드백함

2026-10-12 사용자 승인 범위. 기준: `C:/blackbox/teamplay-ui`, `98d073b` 및 기존 미커밋 변경. 별도 UI 환경에만 적용한다. main 반영 시 A의 DB/권한 검토와 C의 화면 계약 검토가 필요하다.

## 사용자 흐름
- 의견 요청: 업무에서 대상 팀원·내용·선택 파일 버전을 지정 → 피드백함 받은 요청 → 같은 업무의 대화에서 답변. 업무 상태와 수정 가능 여부는 바꾸지 않는다.
- 완료 요청: 기존 완료 조건 검사 → 담당자와 요청자를 제외한 팀원 확인 → 완료 또는 보완. 의견 답변으로 완료되지 않는다.
- 일반 댓글: 프로젝트 팀장·팀원이 작성. 관찰자는 읽기만 가능. 완료 후에도 대화 이력에 의견을 남길 수 있다.
- 의견 요청은 지정된 수신자의 답변으로 응답 완료된다. 다른 팀원의 답글은 대화로 보존하되 수신자가 응답했다고 표시하지 않는다.
- 파일 연결은 해당 업무에 실제 연결된 파일 버전만 허용한다. 다른 업무·프로젝트 파일을 연결할 수 없다.

## 허용 파일 및 구현
B 업무 도메인 신규 TaskMessage entity/repository/service/controller/test, 별도 UI V28, frontend 업무 상세·피드백함·네비게이션, 이 폴더의 구현/검증 기록. 기존 migration·main 환경·기존 사용자 데이터는 변경/삭제하지 않는다. 새 라이브러리는 추가하지 않는다.

API는 프로젝트/업무 경계를 서버에서 확인한다.
- GET/POST `/api/projects/{projectId}/tasks/{taskId}/messages`: 50건 페이지, 댓글·의견 요청·답글. POST `{body, recipientId?, parentId?, fileId?}`. recipientId가 있으면 의견 요청, parentId가 있으면 그 요청의 답글. 동시 지정 400.
- GET `/api/projects/{projectId}/feedback`: 받은/보낸 미응답 의견 요청, 독립 확인 가능한 완료 요청, 내가 수행할 보완 업무. 완료 요청 수신자는 서버에서 담당자와 요청자를 제외한다.
- 관찰자 조회 가능/쓰기 403, 비회원 403, 타 프로젝트 업무·대화·파일 404, 빈 내용/자기 요청/관찰자 수신자 400. 파일·업무 상태를 의견 요청으로 자동 변경하지 않는다.

## UI 원칙
- 댓글 입력은 업무 본문·파일 바로 아래. 일반 댓글과 의견 요청은 같은 대화에 보존한다.
- 의견 요청은 수신자 선택이 필요하다. 완료 요청과 문구/버튼을 구별한다.
- 피드백함은 대화를 복제하는 게시판이 아니라 해당 업무를 바로 여는 입구다.
- 최신 completion 응답의 task와 권한을 같은 기준으로 렌더링한다. 창 복귀 시 갱신하고 작성 중 입력을 보존한다.
- 서버에 저장 성공한 내용만 표시한다. 오류는 입력을 유지하고 알린다.
