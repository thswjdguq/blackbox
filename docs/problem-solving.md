# 문제 해결 기록

개발 중 실제로 겪었거나 코드로 막은 문제입니다. 각 사례의 근거는 PR과 커밋 링크로 남겼습니다.

## 회의록 AI 추출이 매번 502로 실패

- **문제:** 회의록에서 결정사항과 할 일을 뽑는 기능이 매번 502를 돌려줬습니다. 환경 차이로 의심했지만 재현 결과 같은 모델이면 항상 실패했습니다.
- **원인:** 지시문은 JSON만 반환하라고 하지만 모델이 응답 전체를 ` ```json ` 코드 블록으로 감쌌습니다. 파서가 응답을 그대로 읽어 첫 글자에서 실패했습니다.
- **해결:** 응답 전체를 감싼 코드 블록만 벗기도록 했습니다. 블록 밖에 설명 글이 붙은 응답과 근거 검사 실패는 그대로 거부합니다. 정상 형식 2개와 거부 형식 1개를 테스트로 추가했습니다.
- **결과:** 실제 AI 호출 기준 수정 전 4회 모두 502, 수정 후 2회 모두 200입니다.
- **근거:** [PR #154](https://github.com/thswjdguq/blackbox/pull/154)

## 갈라진 DB 마이그레이션 이력 통합

- **문제:** 시연 브랜치와 main의 마이그레이션 번호와 내용이 달라 그대로 병합하면 이미 배포한 DB 이력이 깨지는 상황이었습니다.
- **해결:** main에 배포된 이력은 건드리지 않고 V26~V35로 통합 경로를 추가했습니다. 배포된 마이그레이션의 파일명과 내용을 원본과 비교하는 검사를 CI에 넣었습니다(`scripts/verify-main-migration-history.cjs`).
- **결과:** 빈 DB에 V1~V35를 적용하고 시연 자료를 옮기는 시험에서 표 32개 4,477행의 md5, 외래 키 72개(위반 0), 파일 211개의 해시가 일치했습니다.
- **근거:** [PR #143](https://github.com/thswjdguq/blackbox/pull/143), [커밋 8dd640ab](https://github.com/thswjdguq/blackbox/commit/8dd640ab)

## 이미지가 일부만 교체되어 버전이 섞일 위험

- **문제:** backend, frontend, nginx 이미지를 따로 올리고 받기 때문에, 중간에 실패하면 서비스마다 다른 커밋이 뜰 수 있었습니다.
- **해결:**
  - CI: 커밋 태그만 빌드해 올리고, 세 이미지가 모두 올라간 뒤에 따라가는 태그를 맞춥니다.
  - 서버: 하나라도 받지 못하면 교체하지 않습니다. 바뀐 것이 있을 때만 DB를 백업하고, 교체 뒤 상태가 나쁘면 이전 이미지로 되돌립니다.
- **근거:** [커밋 cae76687](https://github.com/thswjdguq/blackbox/commit/cae76687), [커밋 e3491b6a](https://github.com/thswjdguq/blackbox/commit/e3491b6a), `scripts/ec2-update.sh`

## 모델 응답을 기다리는 동안 SSE 연결 유지

- **문제:** 모델 응답을 기다리는 동안에는 이벤트가 없고, 프록시가 응답을 모아 두면 진행 상황이 화면에 바로 보이지 않습니다.
- **해결:** nginx의 응답 대기 시간을 150초로 늘리고 `X-Accel-Buffering: no`로 버퍼링을 끕니다. 실행 시간 상한은 서버가 120초로 지켜서 대기 시간보다 먼저 끝납니다. 응답 헤더가 요청 스레드에서 나가도록 스트림을 열 때 한 줄을 먼저 보냅니다.
- **근거:** [커밋 20428931](https://github.com/thswjdguq/blackbox/commit/20428931), `AgentController`

## 시계가 뒤로 맞춰져도 시간 상한 유지

- **문제:** 개발 PC에서 운영체제가 시간을 동기화하며 시각이 뒤로 맞춰지는 일이 있었습니다. 현재 시각의 차이로 재면 상한이 지났는데도 안 지난 것으로 나올 수 있습니다.
- **해결:** AI 실행의 흐른 시간을 `System.nanoTime()`으로 잽니다. 기록에 남는 시작 시각과 상한을 재는 기준을 나눴습니다.
- **근거:** `AgentRunner.requireInTime`

## 업로드 폴더가 로그인 없이 열리는 경로 제거

- **문제:** nginx 설정에 업로드 폴더를 직접 내려 주는 경로가 있어 권한 확인을 거치지 않았습니다.
- **해결:** 해당 경로를 지워, 파일은 권한을 확인하는 다운로드 API로만 받게 했습니다.
- **근거:** [커밋 24f8b57e](https://github.com/thswjdguq/blackbox/commit/24f8b57e)
