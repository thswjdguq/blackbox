# 시연 준비

시연 자료는 `scripts/demo-seed.mjs`가 만든다. 이 문서는 스크립트가 확인하지 못하는 설정과, 돌리기 전에 알아 둘 것을 적는다.

## 1. 순서

| 순서 | 할 일 | 확인 |
| --- | --- | --- |
| 1 | `git switch main` 뒤 `git pull` | |
| 2 | `docker compose up -d --build` | 서버와 화면 이미지를 새로 만든다. 몇 분 걸린다 |
| 3 | `docker ps` | `blackbox_db`, `blackbox_backend`, `blackbox_frontend`, `blackbox_nginx` 넷이 모두 Up. PC를 켠 직후 `blackbox_nginx`만 꺼져 있으면 `docker start blackbox_nginx` |
| 4 | `https://localhost`를 연다 | 스스로 서명한 인증서라 경고가 나온다. "고급 → 계속". 로그인 화면이 보이면 된다 |
| 5 | `node scripts/demo-seed.mjs` | Node 20 이상(`node -v`). 끝에 프로젝트 주소와 계정이 나온다 |
| 6 | 리허설용 계정으로 `docs/demo-storyboard.md`의 순서를 처음부터 끝까지 한 번 눌러 본다 | |
| 7 | 본 시연용 계정으로 창마다 로그인해 둔다 | |

스크립트의 옵션과 만드는 자료는 파일 맨 위 주석에 있다.

## 2. 스크립트가 만드는 것

| | 본 시연용 | 리허설용 |
| --- | --- | --- |
| 프로젝트 | 캡스톤 디자인 — 우리 동네 재활용 안내 앱 | 같은 이름 뒤에 "(리허설)" |
| 팀장 김팀장 | `kim@demo.example.com` | `kim.r@demo.example.com` |
| 팀원 이팀원 | `lee@demo.example.com` | `lee.r@demo.example.com` |
| 팀원 박팀원(활동 없음) | `park@demo.example.com` | `park.r@demo.example.com` |
| 관찰자 최교수 | `choi@demo.example.com` | `choi.r@demo.example.com` |

비밀번호는 모두 `Demo-pass-2026`이다(`--password`로 바꾼다). 이 주소와 비밀번호는 공개 저장소에 적혀 있고 `docker-compose.yml`은 80·443 포트를 그 PC 밖에서도 닿게 연다(방화벽이 막지 않으면). 같은 네트워크의 다른 사람이 닿을 수 있는 곳에서는 비밀번호를 바꿔 돌린다. 시연 중에 올릴 수정본은 홈 폴더의 `blackbox-demo/중간보고서_초안.pdf`에 생긴다.

## 3. 스크립트가 확인하지 못하는 것

### 그 PC의 `.env`

| 값 | 시연에 미치는 것 |
| --- | --- |
| `NOTION_API_KEY`, `NOTION_PARENT_PAGE_ID` | 둘 다 있으면 **파일을 올릴 때마다** 그 Notion 페이지 아래에 "업로드 파일 이력" 쪽이 생긴다. 스크립트가 프로젝트마다 둘, 시연에서 올리는 수정본이 하나다. 싫으면 두 값을 비우고 `docker compose up -d`로 서버를 다시 띄운다 |
| `DISCORD_WEBHOOK_URL` | 업무·회의·경보 알림은 프로젝트 설정에 웹훅을 넣은 프로젝트만 보내므로 새로 만든 시연 프로젝트에서는 나가지 않는다. 이 값은 **회의록을 Notion으로 내보낼 때**만 쓰인다. 시연 프로젝트에서 그 버튼을 누르면 이 채널로 알림이 간다 |
| `CLAUDE_API_KEY`, `OPENAI_API_KEY` | 회의 AI 요약에만 쓰인다. 없어도 나머지는 그대로 동작한다 |

AI 기능은 프로젝트 기록을 외부 모델로 보낸다. **시연은 스크립트가 만든 지어낸 프로젝트로만 한다.** 실제 팀의 기록이 든 프로젝트에서 AI 기능을 누르지 않는다.

### 그 PC의 DB

- 서버가 뜨면서 DB를 새 버전으로 올린다. 그 PC에서 병합 전의 PR 브랜치를 띄운 적이 있으면 번호가 어긋나 서버가 뜨지 않을 수 있다. `docker logs blackbox_backend`에 `Validate failed`나 `Detected … migration`이 보이면 그 경우다. 시연 전에 미리 한 번 띄워 본다
- 스크립트는 새 계정과 새 프로젝트를 더할 뿐, 있던 프로젝트는 건드리지 않는다
- 스크립트가 중간에 실패하면 그 프로젝트는 이름 끝에 "(만드는 중)"이 붙은 채 남는다. 다시 돌리면 그것은 두고 새로 만든다. 남은 것은 그 계정의 프로젝트 목록에 보이므로 시연 때 열지 않는다
- **만든 자료는 화면에서 지울 수 없다.** 계정을 지우는 기능은 없고, 기록이 있는 프로젝트는 삭제되지 않는다(지금 main에서는 500, #111이 병합되면 409 "기록 보존을 위해 이 프로젝트는 삭제할 수 없습니다"). 시연 계정과 프로젝트는 그 PC의 DB에 남는다

### 날짜와 시각

- 기한은 스크립트를 돌린 날을 기준으로 잡는다("API 설계 문서"는 어제, 중간 보고서는 6일 뒤). **시연 당일에 돌린다.** 전날 돌리면 "1일 지남"이 "2일 지남"이 되고 D-6이 D-5가 된다
- 서버 컨테이너의 시계는 UTC다. 오전 9시 전에는 서버의 "오늘"이 하루 늦어서 마감 위험도 계산과 내려받는 파일 이름의 날짜가 화면과 어긋난다. 오전 9시 뒤에 돌리고 시연한다

### 브라우저

- 계정 셋을 동시에 띄우려면 창마다 쿠키가 따로여야 한다. 일반 창, 시크릿 창, 다른 브라우저(또는 다른 프로필)로 나눈다. 시크릿 창끼리는 쿠키를 같이 쓴다
- 프로젝트 홈의 "Discord, Notion, Google Calendar를 연동하면 …" 안내는 브라우저(프로필)와 프로젝트마다 한 번 닫으면 된다. 같은 브라우저의 일반 창끼리는 같이 쓰고, 시크릿 창은 따로이며 시크릿 창을 모두 닫으면 다시 나온다. 본 시연용과 리허설용은 프로젝트가 달라 따로 닫는다. 시작 전에 창마다 새로 고쳐 안내가 없는지 본다
- 로그인은 30분이 지난 뒤 다음 요청 때 갱신되고, 마지막 갱신부터 7일 동안 이어진다. 그래도 시작 직전에 창마다 한 번 새로 고쳐 둔다. 파일 금고 내려받기 수정(#109)이 병합되기 전이면, 30분 넘게 둔 창에서 내려받기를 먼저 누르지 않는다. 갱신을 거치지 않아 새 창에 401이 뜬다
- 발표 화면의 해상도에서 한 번 넘겨 본다. 스크립트 확인은 가로 1440에서 했다

## 4. 알아 둘 동작

- **경보는 둘이 뜬다.** 박팀원(의도한 것)과 최교수다. 기여도 계산이 관찰자를 가리지 않아 교수 계정도 "미참여"로 잡힌다. 준비 자료로는 없앨 수 없다
- **김팀장에게 경보가 뜨면** 김팀장의 파일이 빠진 것이다. 업무 완료, 회의 참석, 파일 업로드, 액션아이템 가운데 한 가지 이하만 한 사람이 "미참여"다. 스크립트는 김팀장 이름으로 "과제안내문.pdf"를 올려 둔다
- **수정본은 이름이 같아야** 새 버전으로 들어간다. 스크립트가 만든 파일을 이름을 바꾸지 않고 올린다
- **본 시연용 프로젝트는 시연 전에 누르지 않는다.** 한 번 누르면 자료가 바뀐다. 연습은 리허설용 계정으로 한다. 리허설용을 써 버렸으면 `node scripts/demo-seed.mjs --count 3`으로 하나 더 만든다(`kim.r2@…`)
- 스크립트를 다시 돌려도 이미 있는 프로젝트는 건너뛴다. 다만 날짜가 바뀌었으면 기한이 어긋나 있으므로 `--again`으로 새로 만들어 그 프로젝트로 시연한다. 이때 그 계정에 같은 이름의 프로젝트가 둘 보인다

## 5. 확인한 것과 확인하지 않은 것

- main을 Docker와 nginx로 띄운 빈 서버(https)에서 스크립트를 돌렸다. 처음 실행, 다시 실행, 비밀번호가 다를 때, 서버가 꺼져 있을 때를 봤다
- 업무 만들기만 503을 주는 대역 서버로 중간 실패를 만들었다. 실패로 끝나고, 다시 돌리면 만들다 만 것을 알린 뒤 새로 만들고, 한 번 더 돌리면 건너뛴다
- 스크립트가 넣은 자료에서 경보가 박팀원과 최교수 둘인 것, 프로젝트 삭제가 500으로 끝나는 것을 봤다
- Windows에서는 손정효님이 돌렸다(Windows 11, Node 24). 시연할 PC에서는 아직 돌리지 않았다. Notion과 Discord로 실제 보내는 것은 보지 않았고 언제 보내는지만 코드에서 확인했다
