## D. 시스템 아키텍처 (Mermaid 다이어그램 생성용 구조 설명)

```
[사용자 브라우저]
    ↕ HTTPS (443)
[Nginx] ← SSL 터미네이션, HTTP→HTTPS 리다이렉트
    ↕
[Next.js 프론트엔드 컨테이너 :3000]
    ↕ REST API (/api/**)
[Spring Boot 백엔드 컨테이너 :8080]
    ├── PostgreSQL 16 컨테이너 :5432
    ├── 로컬 파일 스토리지 (/data/uploads)
    ├── Anthropic Claude API (WebClient) → AI 요약/추천
    ├── Google Calendar API (OAuth 2.0) → 캘린더 조회
    ├── Notion API → 회의록/칸반 동기화
    └── Discord Webhook → 알림 전송
```

### 인증 흐름
- 로그인 → JWT 발급 → **HttpOnly 쿠키** 저장 (XSS 방어)
- 프론트 Axios 인터셉터 → 모든 요청에 쿠키 자동 첨부 (withCredentials)
- 만료 시 Refresh Token으로 자동 갱신

### 주요 백엔드 서비스 목록

## E. 데이터베이스 스키마 (Flyway V1~V18 기반)

### 테이블 목록 및 역할

| 테이블명 | 역할 |
|---|---|
| users | 사용자 계정 (UUID PK, email, name, password_hash, role, notion_api_key) |
| projects | 프로젝트 (name, course_name, semester, invite_code, start/end_date) |
| project_members | 프로젝트-유저 다대다 (role: LEADER/MEMBER/OBSERVER, 동의 플래그 5종) |
| oauth_tokens | OAuth 토큰 저장 (provider: GITHUB_APP/GOOGLE, AES-256 암호화) |
| tasks | 태스크 (status: TODO/IN_PROGRESS/DONE, priority: LOW/MEDIUM/HIGH/URGENT, tag, due_date) |
| task_assignees | 태스크-담당자 다대다 |
| meetings | 회의록 (meeting_date, purpose, notes, decisions, checkin_code, ai_summary, notion_page_id) |
| meeting_attendees | 회의 참석자 (checked_in, checked_at, checked_in_date) |
| activity_logs | 활동 로그 (source, action_type, metadata JSONB, trust_level, quality_score) |
| file_vault | 위변조 불가 파일 금고 (file_hash SHA-256, is_immutable=TRUE, UPDATE/DELETE 트리거 차단) |
| tamper_detection_log | 변조 감지 이력 (original_hash vs new_hash) |
| contribution_scores | 기여도 점수 (task/meeting/doc/git 항목별 + 총합, 가중치 스냅샷) |
| alerts | 경보 (alert_type: FREE_RIDE/DROPOUT/OVERLOAD/CRUNCH_TIME/TAMPER, severity) |
| weight_configs | 가중치 설정 (프로젝트별, 합계 1.00 CHECK 제약) |
| weight_change_log | 가중치 변경 이력 (JSONB) |
| manual_work_reports | 수동 작업 신고 (오프라인 작업 보완) |
| google_calendar_tokens | Google Calendar OAuth 토큰 (user별 1개) |
| discord_settings | Discord 웹훅 설정 (프로젝트별, 알림 종류별 토글) |

### 핵심 설계 특이사항
- `file_vault`에 `BEFORE UPDATE OR DELETE` 트리거 → 레코드 수정/삭제 물리적 차단
- `updated_at` 자동 갱신 트리거 (V8) — users/projects/tasks/meetings 전체 적용
- `activity_logs.metadata` JSONB — 커밋 메시지, diff 크기 등 비정형 데이터 유연 저장
- `contribution_scores`의 가중치 합계 = 1.00 CHECK 제약 (DB 레벨 보장)

## G. 담당자별 구현 기능 + 핵심 코드 포인트 (주간보고서 기반)

### 송병철 (백엔드 — 인증/인프라/태스크)

**구현 기능:**
1. JWT 인증 모듈 (회원가입/로그인 API, JWT 필터, SecurityConfig, Refresh Token)
2. Task CRUD API (생성/수정/삭제, 상태 변경 PATCH /tasks/{id}/status, 담당자 배정)
3. 태스크 이벤트 → activity_logs 자동 기록 연동
4. JWT HttpOnly 쿠키 전환 (XSS 방어, 11주차)
5. Spring Security 403→401 긴급 수정 — HttpStatusEntryPoint(UNAUTHORIZED) 추가 (12주차)
6. Nginx/Docker SSL 구성 (nginx/Dockerfile, OpenSSL 자체서명 인증서)
7. 프론트엔드: 빈 상태 UI 추가 (칸반/회의록/Hash Vault/기여도), 마감일 경고 배지 (13주차)

**핵심 코드 포인트:**
- `SecurityConfig.java` — HttpStatusEntryPoint + permitAll 설정, 쿠키 기반 인증
- `TaskController.java` + `TaskService.java` — CRUD + PATCH /status + PUT /assignees
- `TaskCard.tsx` — 마감일 D+N/오늘/D-3 배지 로직 (날짜 diff 계산)
- `nginx/nginx.conf` — 80→443 리다이렉트 + SSL 서버 블록

---

### 송승준 (백엔드 — Hash Vault/회의록/Notion/Discord/DB)

**구현 기능:**
1. DB 설계 총괄 — Flyway V1~V18 마이그레이션, updated_at 트리거(V8), task 트리거(V9)
2. Hash Vault — SHA-256 해시 생성(HashService), 파일 업로드/다운로드 API, 불변 트리거
3. 회의록 API — Meeting CRUD, 체크인 코드 생성 & 체크인 API, 액션아이템→태스크 연결
4. 변조 감지 — tamper_detection_log + alerts 자동 기록
5. 증거패키지 ZIP — GET /api/projects/:id/evidence-package (회의록+기여도PDF+파일이력)
6. Notion 연동 고도화 — upsert 방식(중복 생성 방지), 유저별 API Key 지원, KST 시간 변환
7. Discord 알림 — DiscordNotionNotifier (비동기, 내보내기 완료 시 Embed 전송)
8. GoogleCalendarService 코드 정리 — durationMinutes 하드코딩 수정, 죽은 코드 6개(104줄) 제거, 참석자 미선택 warning 처리 (13주차)

**핵심 코드 포인트:**
- `V6__init_file_vault.sql` — `prevent_vault_modification()` 트리거 (UPDATE/DELETE 차단)
- `HashService.java` — SHA-256 MessageDigest
- `NotionService.java` — upsert 로직, 유저 키 오버로딩(서버 키 폴백)
- `DiscordNotionNotifier.java` — @Async 비동기, 기존 서비스와 독립 격리
- `GoogleCalendarService.java` — `recommendMeetingTimes()` durationMinutes 파라미터 반영

---

### 손정협 (백엔드 — Score Engine/AI 연동/프로젝트 관리)

**구현 기능:**
1. 프로젝트 관리 API — Project CRUD, 초대코드 생성&참여, 멤버 관리(역할 변경/탈퇴)
2. ProjectAccessChecker — LEADER/MEMBER/OBSERVER 권한 검증
3. Score Engine — 기여도 수식(태스크/회의/파일/git 가중치), 팀 평균 정규화(상한 150), 30분 스케줄러 + 태스크 완료 즉시 트리거
4. 경보 시스템 — FREE_RIDE/DROPOUT/OVERLOAD 감지
5. ClaudeService(WebClient) — AI 회의 요약 + 액션아이템 구조화 추출(JSON)
6. RiskService — 마감 지연 위험도 예측 API
7. ReportService — SHA-256 무결성 PDF 생성(NanumGothic TTF 임베드, 한글 수정)
8. Google Calendar AI 추천 고도화 — freeBusy→Events API 교체, HARD/SOFT BLOCK, 점수제, UTC(Z) 형식 버그 수정

## H. 주요 이슈 & 해결 사례 (시행착오)

| # | 이슈 | 원인 | 해결 방법 |
|---|---|---|---|
| 1 | 칸반 담당자 수정 저장 불가 | UpdateTaskRequest DTO에 assigneeIds 필드 누락 | PUT /tasks/{id}/assignees 별도 엔드포인트 추가 |
| 2 | 칸반 상태 변경 저장 불가 | UpdateTaskRequest DTO에 status 필드 누락 | PATCH /tasks/{id}/status 별도 엔드포인트 분리 |
| 3 | 칸반 드래그앤드롭 동작 불가 | @dnd-kit listeners가 Grip 핸들에만 부착 | listeners를 카드 최상위 div로 이동 + 체크박스 stopPropagation |
| 4 | 전체 API 403 반환 | Spring Security 기본 진입점이 Http403으로 동작 | HttpStatusEntryPoint(UNAUTHORIZED) 추가 → 401 정상 반환 |
| 5 | PDF 한글 깨짐 | OpenPDF 기본 폰트 한글 미지원 | NanumGothic TTF를 BaseFont로 임베드 |
| 6 | Notion 중복 페이지 생성 | 수정 시 기존 페이지 외 새 페이지 추가 생성 | upsert 방식으로 변경 (기존 페이지 업데이트) |
| 7 | SOFT BLOCK 미동작 | Events API URL에서 +09:00의 '+' → 공백 인코딩 | UTC(Z) 형식으로 변환하여 해결 |
| 8 | JWT localStorage → XSS 취약 | localStorage는 JS에서 접근 가능 | HttpOnly 쿠키 기반으로 전환 |
| 9 | Chrome HTTPS(HSTS) 이슈 | HTTP 접속 시 HSTS 정책으로 차단 | nginx Dockerfile + 자체서명 인증서 + 443 SSL 블록 추가 |
| 10 | AI 요약 응답 지연 | Claude API 호출 5~10초 소요 | 로딩 스피너 + 비동기 처리 적용 |

## I. AI 활용 기능 상세

### 1. 회의록 AI 자동 요약
- **사용 API**: Anthropic Claude API
- **입력**: 회의록 텍스트(notes, decisions)
- **출력**: 회의 요약 텍스트
- **화면**: 회의 상세 페이지 → "AI 요약" 버튼 클릭 → ClaudeService → 응답 렌더링

### 2. 액션아이템 자동 추출 → 태스크 생성
- **사용 API**: Anthropic Claude API
- **입력**: 회의록 텍스트
- **출력**: JSON 구조화 (제목/담당자/마감일 파싱)
- **화면**: 회의 상세 페이지 → "액션아이템 추출" → 칸반 태스크 자동 생성

### 3. AI 회의 일정 추천
- **사용 API**: Google Calendar OAuth (캘린더 조회) + Anthropic Claude API (추천 이유)
- **알고리즘**:
  - Events API로 팀원 일정 수집
  - HARD BLOCK: 시간 명시 일정과 겹치는 슬롯 완전 제외
  - SOFT BLOCK: 종일 일정 있는 팀원 있으면 감점 (-30점/명, 최저 0점)
  - 상위 3개 슬롯 선택 → AI에게 추천 이유 문장만 생성 요청
- **화면**: /projects/[id]/schedule — 추천 카드 (점수 배지: 90+초록, 60~89주황, 60-빨강)

### 4. 마감 지연 위험도 예측
- **방식**: 규칙 기반 (RiskService — 태스크 완료율, 마감일 임박도 계산)
- **화면**: 기여도 분석 페이지 → RadialBarChart 게이지
