# Team Blackbox 전시 보드 원고

## BOARD 01 프로젝트 소개

**프로젝트명**  Team Blackbox

**한 줄 소개**  제출물과 업무를 연결하고 협업 과정을 기록하는 대학생 팀 프로젝트 관리 서비스

### 01 PROJECT OVERVIEW 프로젝트 개요

Team Blackbox는 한 학기 동안 공동 결과물을 만드는 대학생 팀을 위한 웹 서비스입니다. 제출물의 요구사항을 실제 업무에 연결하고, 회의 내용과 파일·활동 기록을 함께 관리해 팀이 해야 할 일과 진행 상황을 확인하도록 돕습니다.

**PROBLEM**

- 과제 요구사항과 할 일이 따로 관리되어 업무의 목적과 완료 기준이 불분명합니다.
- 회의에서 정한 일이 업무로 이어지지 않으면 담당자와 기한이 누락되기 쉽습니다.
- 파일과 활동 기록이 흩어져 결과물의 변경 이력과 팀원의 작업 과정을 확인하기 어렵습니다.

**SOLUTION**

- 제출물과 필수·선택 요구사항을 등록하고 각 조건에 필요한 업무를 연결합니다.
- 회의 내용을 정리하고, 확인한 할 일을 담당자와 기한이 있는 업무로 등록합니다.
- 파일 버전·해시·업로드 이력과 활동 기록을 프로젝트 안에서 관리합니다.

### 02 KEY EXPERIENCE 핵심 기능

**제출물 중심 업무 관리**
제출 기한과 요구사항을 정하고, 연결된 업무의 담당자·기한·완료 기준을 관리합니다.

**회의에서 업무로 연결**
회의록과 참석 기록을 남기고, AI가 요약하거나 추출한 할 일을 확인해 업무로 등록합니다.

**파일과 협업 기록 확인**
파일 버전과 변경 이력을 확인하고, 활동 기반 기여도와 기록 패키지로 작업 과정을 돌아봅니다.

### 03 DESIGN PRINCIPLES 화면 설계 원칙

- **다음 행동 안내**: 제출물 등록, 요구사항 작성, 업무 연결 순서로 사용자가 할 일을 안내합니다.
- **일관된 정보 연결**: 제출물 화면과 업무 보드에서 같은 제출물·요구사항 정보를 사용합니다.
- **명확한 저장 피드백**: 저장 성공과 실패를 구분하고, 실패 시 작성 중인 내용을 유지합니다.
- **상태 의미 구분**: 업무 완료 수와 최종 제출 완료를 구분해 진행 상황을 전달합니다.

### 04 PROJECT PROCESS 개발 과정

**문제 정리 → 요구사항 정의 → 데이터와 화면 설계 → 기능 구현 → 통합 검증 → 시연 준비**

대학생 팀의 제출물과 협업 기록을 관리하는 흐름을 정하고, 제출물·요구사항·업무의 관계를 설계했습니다. 현재 관련 화면과 API를 구현했으며, 단위 테스트와 빌드 검증 기록을 바탕으로 실제 DB·브라우저 통합 검증과 시연을 준비하고 있습니다.

### 05 PRODUCT PREVIEW 주요 화면 설명

**제출물과 요구사항**: 제출 기한, 담당자, 필수·선택 조건과 연결된 업무를 한 화면에서 확인합니다.

**업무 보드**: 할 일·진행 중·완료 상태를 관리하고 제출물별로 필요한 업무를 살펴봅니다.

**회의 상세**: 회의 내용과 참석 기록을 확인하고, 회의에서 나온 할 일을 업무로 연결합니다.

### 06 SYSTEM ARCHITECTURE 시스템 구조

**화면**  Next.js · React · TypeScript

**API와 업무 처리**  Spring Boot · Spring Security · JWT

**데이터와 파일**  PostgreSQL · Flyway · 파일 저장소

**AI와 외부 연동**  Claude API · Google Calendar · Notion · Discord

Nginx가 웹 화면 요청과 API 요청을 각각 프론트엔드와 백엔드로 전달합니다. 백엔드는 프로젝트 권한과 업무 규칙을 검사하고 데이터를 저장하며, AI와 외부 서비스 연동을 처리합니다.

## BOARD 02 기술 구현과 팀 역할

**프로젝트명**  Team Blackbox

**한 줄 설명**  제출물과 업무를 연결하는 기능의 구현 과정과 검증 현황

### 01 KEY UI AND FEATURE FLOW 주요 사용 흐름

**01 제출물 등록 → 02 요구사항 작성 → 03 업무 연결 → 04 진행 상태 관리**

1. **제출물 등록**: 결과물의 이름과 제출 기한을 정하고 담당자·제출 경로를 입력합니다.
2. **요구사항 작성**: 과제에 필요한 내용과 형식을 필수·선택 조건으로 정리합니다.
3. **업무 연결**: 새 업무를 만들거나 기존 업무를 연결하고 담당자·기한·완료 기준을 정합니다.
4. **진행 상태 관리**: 업무 보드에서 상태를 변경하고 제출물별로 남은 작업을 확인합니다.

업무를 완료해도 요구사항 충족이나 최종 제출이 자동 승인되지는 않습니다. 현재 완료 업무 수는 진행 상황을 확인하는 참고 정보입니다.

### 02 TECH STACK AND TOOLS 기술과 역할

- **Frontend**: Next.js와 TypeScript로 프로젝트별 화면과 데이터 타입을 구성했습니다. Tailwind CSS로 화면 스타일을, dnd-kit으로 칸반 이동을, Recharts로 활동 데이터 시각화를 구현했습니다.
- **Backend**: Java 17과 Spring Boot로 API와 업무 규칙을 구현했습니다. Spring Security와 JWT로 인증을 처리하고, 서비스 계층에서 프로젝트 소속과 쓰기 권한을 확인합니다.
- **Data**: PostgreSQL로 프로젝트·업무·제출물의 관계 데이터를 저장하고 Flyway로 스키마 변경 이력을 관리합니다. 파일은 별도 저장소에 보관하며 해시와 버전 정보를 기록합니다.
- **AI and Integration**: Claude API로 회의 요약과 할 일 추출을 지원합니다. Google Calendar 일정 조회, Notion 내보내기, Discord 알림을 연동합니다.
- **Runtime**: Docker Compose로 실행 구성을 정의하고 Nginx로 웹 화면과 API 요청을 전달합니다.

### 03 IMPLEMENTATION HIGHLIGHTS 핵심 구현

**제출물과 업무의 관계 관리**
업무에 제출물·요구사항·완료 기준을 연결했습니다. 제출물을 변경하면 이전 요구사항 연결을 해제해 서로 맞지 않는 관계가 남지 않도록 처리합니다.

**프로젝트별 권한 검증**
제출물·업무 변경 시 서버에서 프로젝트 소속과 쓰기 권한을 확인합니다. 다른 프로젝트의 항목 연결과 비회원·관찰자의 담당자 지정을 거절합니다.

**파일 이력과 기록 출력**
파일의 SHA-256 해시, 버전, 업로드 시각을 저장합니다. 회의록·파일 이력 CSV·기여도 PDF를 ZIP으로 묶어 작업 기록을 내보냅니다. 해시 비교는 파일 내용의 변경을 확인하는 근거로 사용합니다.

**저장 결과와 오류 처리**
제출물 저장 후 서버 목록을 다시 조회하고, 저장 실패와 목록 재조회 실패를 구분해 안내합니다. 실패한 경우에는 사용자가 내용을 확인하고 다시 시도할 수 있도록 입력을 유지합니다.

### 04 CHALLENGE AND FIX 기술적 과제와 해결

**기존 업무를 보존하면서 제출물 구조 추가**
기존 업무를 미연결 상태로 유지하고, 사용자가 제출물과 요구사항을 연결·변경·해제하도록 구현했습니다.

**다른 프로젝트의 데이터가 연결되는 문제 방지**
프로젝트 범위를 포함한 조회와 서버 검증을 적용했습니다. DB에는 업무·제출물·요구사항 관계를 제한하는 복합 외래키를 정의했습니다.

**연결된 항목 삭제로 인한 관계 손실 방지**
업무가 연결된 제출물과 요구사항의 삭제를 거절하고, 먼저 업무를 옮기거나 연결을 해제하도록 안내합니다.

**검증 현황**
2026년 9월 21일 기록 기준, 제출물·업무 연결·담당자·권한 관련 단위 테스트 35개가 통과했습니다. 프론트 타입 검사와 빌드, 백엔드 컴파일의 통과 기록도 확보했습니다. 실제 DB와 브라우저 통합 검증은 후속 과제이며, 외부 연동은 시연 환경에서 별도 확인이 필요합니다.

### 05 TEAM AND ROLE 현재 고도화 역할

**송승준 · 팀장**
제출물·요구사항, 인증·권한 기반, 파일 저장, DB·실행 환경을 담당합니다. 검토 회차와 최종 제출 기록 영역의 후속 개발을 맡습니다.

**손정효 · 프론트엔드**
